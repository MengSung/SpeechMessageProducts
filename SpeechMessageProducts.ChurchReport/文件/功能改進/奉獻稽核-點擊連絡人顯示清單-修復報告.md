# 奉獻稽核 - 點擊連絡人顯示清單修復報告

## 問題描述
當用戶在「奉獻稽核」頁面查詢到多個同名連絡人時，點擊其中一個連絡人後，系統應該顯示該連絡人的奉獻清單，但實際上清單沒有顯示。

## 根本原因分析

### 1. 數據流程問題
```
用戶點擊連絡人 → 提交表單 → AuditQueryDedication (返回 JSON)
→ onSuccess 處理 → 原本會重定向到 AuditViewWeb
→ **問題**: 重定向會丟失查詢的奉獻清單數據
```

### 2. 原始代碼的問題

**視圖 (DedicationFeeAuditViewWeb.cshtml)**
```javascript
function onSuccess(data) {
    if (data.status == 1) {
        if (data.clicktype == "查詢") {
            // 問題: 這裡會重定向，丟失數據
            window.location.href = "/DedicationAudit/AuditViewWeb";
        }
    }
}
```

**控制器 (DedicationAuditController.cs)**
```csharp
// AuditQueryDedication 只返回 JSON，不會設置 Session 或其他持久化數據
return Json(new { 
    status = "1", 
    clicktype = "查詢", 
    DedicationNumber = DedicationNumber, 
    // ... 但沒有奉獻清單數據
});
```

**QpayManager.cs**
```csharp
public async Task<IActionResult> AuditQueryDedication(QpayModel QpayModel)
{
    // 當找到一個連絡人時
    SetDedicationFeeList(DedicationContacts.Entities[0]);
    
    // 數據存在 m_QpayModel.DedicationFeeList 中
    // 但 JSON 返回時沒有包含這些數據
    return Json(new { status = "1", clicktype = "查詢", ... });
}
```

## 解決方案

### 方案 1: AJAX 局部更新（推薦）?

**優點**: 
- 不重新載入頁面
- 保持用戶體驗流暢
- 數據不會丟失

**實施步驟**:

1. **修改視圖的 onSuccess 函數**
```javascript
function onSuccess(data) {
    getLoadPanelInstance().hide();

    if (data.status == 1) {
        if (data.clicktype == "上傳") {
            // ... 上傳邏輯
        }
        else {
            // ? 修改: 不重定向，直接顯示奉獻清單
            document.getElementById("samenamecontainer").style.display = "none";
            document.getElementById("data-grid").style.display = "";
            document.getElementById("displayamountfield").style.display = "";
            
            // 更新總金額顯示
            if (data.TotalAmount) {
                document.getElementById("displayamountfield").innerHTML = "<h4>" + data.TotalAmount + "</h4>";
            }
            
            // 刷新奉獻清單 DataGrid
            var grid = $("#DedicationFeeGrid").dxDataGrid("instance");
            if (grid) {
                grid.refresh();
            }
            
            ShowToast("成功載入 " + data.FullName + " 的奉獻記錄", "success", 2000);
        }
    }
    // ... 其他邏輯
}
```

2. **確保 DataGrid 使用正確的數據源**

視圖已經正確配置:
```csharp
.DataSource(d => d
    .WebApi()
    .Controller("DedicationAudit")
    .LoadAction("LoadDedicationFeeList")
    .Key("DedicationDate")
)
```

3. **修改控制器的 LoadDedicationFeeList 方法**
```csharp
[HttpGet]
public object LoadDedicationFeeList(string id, DataSourceLoadOptions loadOptions)
{
    try
    {
        var dedicationFeeList = InMemoryContext.QpayManager.m_QpayModel?.DedicationFeeList;
        
        if (dedicationFeeList == null || dedicationFeeList.Count == 0)
        {
            return DataSourceLoader.Load(new List<DedicationFee>(), loadOptions);
        }
        
        return DataSourceLoader.Load(dedicationFeeList, loadOptions);
    }
    catch (Exception e)
    {
        System.Diagnostics.Debug.WriteLine($"LoadDedicationFeeList 錯誤: {e.Message}");
        return DataSourceLoader.Load(new List<DedicationFee>(), loadOptions);
    }
}
```

### 方案 2: Session 持久化（備選）

**優點**: 
- 支持頁面刷新
- 數據在 Session 中保存

**缺點**:
- 需要管理 Session 生命週期
- 可能有並發問題

**實施步驟**:

1. **在 AuditQueryDedication 中存儲數據到 Session**
```csharp
public async Task<IActionResult> AuditQueryDedication(QpayModel QpayModel)
{
    // ... 現有邏輯
    
    if (DedicationContacts.Entities.Count == 1)
    {
        SetDedicationFeeList(DedicationContacts.Entities[0]);
        
        // 存儲到 Session
        HttpContext.Session.SetString(
            "DedicationFeeList_" + DedicationContacts.Entities[0].Id, 
            JsonSerializer.Serialize(m_QpayModel.DedicationFeeList)
        );
        HttpContext.Session.SetString("CurrentContactId", DedicationContacts.Entities[0].Id.ToString());
        
        return Json(new { status = "1", ... });
    }
}
```

2. **在 AuditViewWeb 中從 Session 讀取**
```csharp
[Route("/DedicationAudit/AuditViewWeb")]
public IActionResult DedicationFeeAuditViewWeb()
{
    SetupAuditViewBag(true);
    
    var contactId = HttpContext.Session.GetString("CurrentContactId");
    if (!string.IsNullOrEmpty(contactId))
    {
        var dedicationFeeListJson = HttpContext.Session.GetString("DedicationFeeList_" + contactId);
        if (!string.IsNullOrEmpty(dedicationFeeListJson))
        {
            var dedicationFeeList = JsonSerializer.Deserialize<List<DedicationFee>>(dedicationFeeListJson);
            InMemoryContext.QpayManager.m_QpayModel.DedicationFeeList = dedicationFeeList;
        }
    }
    
    return View(InMemoryContext.QpayManager.m_QpayModel);
}
```

## 潛在問題和注意事項

### 1. 並發問題 ??
**問題**: `InMemoryContext.QpayManager` 是靜態單例，多個用戶同時使用會互相覆蓋數據

**解決方案**:
- 使用 Session 存儲用戶特定數據
- 使用依賴注入的 Scoped 服務代替靜態實例
- 添加鎖機制保護共享數據

### 2. 數據同步問題 ??
**問題**: DataGrid 的 WebAPI 數據源可能不會即時反映 m_QpayModel 的變化

**解決方案**:
- 當前實施: 在 onSuccess 中調用 `grid.refresh()` 強制刷新
- 更好的方式: 使用本地數組數據源而不是 WebAPI

**建議改進**:
```csharp
// 在視圖中直接使用 Model 數據
.DataSource(Model.DedicationFeeList)
```

然後在 JavaScript 中更新:
```javascript
function onSuccess(data) {
    if (data.status == 1 && data.clicktype == "查詢") {
        // 重新載入頁面以獲取最新數據
        window.location.href = "/DedicationAudit/AuditViewWeb?showList=true";
    }
}
```

### 3. 記憶體洩漏風險 ??
**問題**: 靜態實例會一直佔用記憶體

**解決方案**: 參考項目中的記憶體優化文件，將 QpayManager 改為 Scoped 服務
