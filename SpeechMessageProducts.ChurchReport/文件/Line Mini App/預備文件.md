## 第一章：LINE Mini App 是什麼？

LINE Mini App 是一種**跑在 LINE App 內部瀏覽器（LIFF Browser）裡的 Web 應用程式**。

使用者不需要另外下載 App，直接在 LINE 裡就能使用你的服務；開發者也不需要學 Swift 或 Kotlin，用一般的 HTML / CSS / JavaScript 就能做出來。

```
一般 App 的做法：
  開發者 → 寫 iOS App → 上架 App Store → 使用者下載 → 使用

LINE Mini App 的做法：
  開發者 → 寫 Web App → 申請 LINE Mini App Channel → 使用者在 LINE 內直接用 ✅
```

### 1.1 Mini App vs 原生 App vs 一般網頁

| 比較 | LINE Mini App | 原生 App | 一般網頁 |
|------|:---:|:---:|:---:|
| 需要下載安裝 | ❌ | ✅ | ❌ |
| 需要另外設計登入 | ❌（直接用 LINE） | ✅ | ✅ |
| 開發技術 | Web（HTML/JS/CSS）| Swift/Kotlin | Web |
| 取得用戶資料 | 直接取得 LINE 資料 | 需自建 | 需自建 |
| 推播通知 | Service Message | Push Notification | 需申請 |
| 上架流程 | LINE 審核 | App Store 審核 | 無 |

### 1.2 Unverified vs Verified Mini App

LINE Mini App 分為兩個等級：

```
┌─────────────────────────────────────────────────────────────┐
│  Unverified MINI App（未認證）                               │
│  → 建立 Channel 後立即可用                                   │
│  → 功能受限：無 Service Message、無 Quick-fill               │
│  → 只有 Tester 名單上的人可存取（Published 後全開）           │
└────────────────────────────┬────────────────────────────────┘
                             │ 提交審核 → 通過
                             ▼
┌─────────────────────────────────────────────────────────────┐
│  Verified MINI App（已認證）✅                               │
│  → 全功能解鎖                                               │
│  → Service Message 發送通知                                 │
│  → Common Profile Quick-fill 快速填表                       │
│  → 主畫面捷徑（Add to Home Screen）                         │
│  → LINE 搜尋中出現                                          │
│  → 顯示 Verified 徽章                                       │
└─────────────────────────────────────────────────────────────┘
```

## 第三章：開始前的準備工作

### 3.1 你需要準備的帳號

**① LINE 個人帳號**（用來登入開發者後台）
- 下載 LINE App，用手機號碼申請
- 這組帳號之後也會用來測試 Mini App

**② LINE Developers Console 帳號**
- 前往 https://developers.line.biz/
- 點「Log in」→「Log in with LINE account」
- 用上面的 LINE 帳號登入

**③ 台灣地區：需先申請開發許可** ⚠️
> 台灣地區無法自行建立 LINE Mini App Channel，  
> 必須先獲得 **LINE Taiwan** 的審核許可才行。  
> 申請管道：https://tw.linebiz.com/service/other-solutions/line-mini-app/

### 3.2 開發環境需求

| 項目 | 最低需求 | 建議 |
|------|---------|------|
| Node.js | v16+ | v20 LTS |
| HTTPS | 必須（LINE 不接受 HTTP）| 正式環境用 SSL 憑證 |
| 本地 HTTPS 工具 | ngrok（免費版可用）| ngrok / localtunnel |
| 前端框架 | 無限制 | React / Vue / Next.js |

**安裝本地測試工具：**

```bash
# 安裝 ngrok（本地開發用，產生 HTTPS 隧道）
npm install -g ngrok

# 或使用官網下載：https://ngrok.com/download
```

### 3.3 你的 Web App 必須滿足什麼條件？

```
✅ 必要條件：
  □ Endpoint URL 必須是 HTTPS（不接受 HTTP）
  □ Endpoint URL 必須可以公開存取（LINE 平台要能讀到）
  □ 需有隱私政策頁面（Privacy Policy URL）
  □ Channel 名稱不能含有 "LINE" 字樣

✅ 強烈建議：
  □ 提供 /loading.gif 作為載入圖示
  □ 處理 iOS safe area（避免瀏海遮擋內容）
  □ 針對手機畫面優化 UI（Mini App 主要在手機上使用）
  □ 妥善處理「用戶在外部瀏覽器開啟」的情境
```

## 第四章：建立 LINE Mini App Channel

### 4.1 認識 Provider 和 Channel 的關係

```
LINE Developers Console
└── Provider（你的公司 / 品牌）         ← 先建立這個
    ├── LINE Mini App Channel A         ← 再建立這個
    ├── LINE Mini App Channel B
    └── LINE Login Channel C

注意：
  • 同一個 Provider 下，所有 Channel 共用同一套 User ID
  • Channel 建立後，無法搬移到其他 Provider！
  • 如果以後需要整合多個服務（例如電商 + 會員系統），
    應該放在同一個 Provider 下，讓 User ID 可以對應
```

### 4.2 建立 Provider（如果還沒有的話）

1. 登入 https://developers.line.biz/console/
2. 點擊「**Create a new provider**」
3. 填入 Provider 名稱（建議用公司名或品牌名）
4. 點擊「**Create**」

### 4.3 建立 LINE Mini App Channel（完整步驟）

**Step 1**：在 Console 選擇你的 Provider  
**Step 2**：點擊「**Channels**」→「**Create a new channel**」  
**Step 3**：選擇「**LINE MINI App**」

**Step 4**：填寫 Channel 資訊（對照下表）：

| 欄位名稱 | 必填？ | 填什麼 | 用戶會在哪裡看到 |
|---------|:-----:|--------|----------------|
| Channel type | ✅ | 選「LINE MINI App」| — |
| Provider | ✅ | 自動帶入 | 授權同意畫面 |
| **Region to provide the service** | ✅ | 台灣選「**Taiwan**」<br>日本選「Japan」<br>泰國選「Thailand」 | — |
| Channel icon | 建議填 | 你的 App 圖示（見下方規格）| 授權畫面、聊天分享卡片、<br>Multi-tab、Service Message |
| **Channel name** | ✅ | 你的服務名稱<br>⚠️ **不能含「LINE」字樣** | 授權畫面、聊天分享卡片 |
| Channel description | ✅ | 說明服務內容<br>開發公司≠服務公司時需特別說明 | 授權畫面 |
| Email address | ✅ | 接收重要通知的信箱 | — |
| **Privacy policy URL** | ✅* | 隱私政策的 HTTPS 網址<br>*Certified Provider 才能在建立時填，<br>否則建立後再編輯 | 授權畫面 |
| Terms of use URL | 建議填 | 服務條款的 HTTPS 網址 | 授權畫面 |
| Service company's country/region | ✅ | 必須與 Region 一致<br>（台灣服務選 Taiwan）| 授權畫面 |

> ⚠️ **Channel Icon 規格**：
> - 格式：PNG 或 JPG
> - 尺寸：最小 100x100px（建議 500x500px）
> - 不能有透明背景

**Step 5**：閱讀並同意所有協議：
- LINE Developers Agreement ✅
- LINE MINI App Platform Agreement ✅
- LINE MINI App Policy ✅

**Step 6**：勾選確認聲明方塊  
**Step 7**：點擊「**Create**」  
**Step 8**：閱讀「Regarding Consent to Usage of the Information」，點擊「**Accept**」

✅ 建立成功！系統自動產生三個內部 Channel（Developing / Review / Published）

### 4.4 建立後取得重要資訊

建立完成後，馬上記錄以下資訊：

```
進入 Channel → 「Basic settings」分頁
  ├── Channel ID    ← 呼叫後端 API 時需要
  └── Channel secret ← 用來產生 Channel Access Token

進入 Channel → 「Web app settings」分頁（或 LIFF 分頁）
  ├── Developing 的 LIFF ID   ← 格式：1234567890-AbCdEfGh
  ├── Review 的 LIFF ID
  └── Published 的 LIFF ID
```

## 第五章：三個內部 Channel 環境

### 5.1 三個環境的差異總覽

```
┌─────────────────────────────────────────────────────────────────────┐
│               LINE Mini App Channel 內部結構                         │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  📦 Developing（開發測試環境）                                │   │
│  │                                                             │   │
│  │  • Channel 狀態：永遠是 "Developing"                        │   │
│  │  • 存取限制：只有被加為 Tester 的用戶才能存取                │   │
│  │  • 支援 Basic Authentication（HTTP 基本驗證）                │   │
│  │  • 可測試 Service Message（但在此環境不能對外發送）           │   │
│  │  • 可使用 liff.$commonProfile.getDummy() 測試 Quick-fill     │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  🔍 Review（審核環境）                                        │   │
│  │                                                             │   │
│  │  • Channel 狀態：永遠是 "Developing"                        │   │
│  │  • LINE 審核員會在這個環境進行測試                           │   │
│  │  • 提交審核前，必須先部署到這個環境                          │   │
│  │  • 同樣支援 Basic Authentication                            │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  🌐 Published（正式上線環境）                                 │   │
│  │                                                             │   │
│  │  • Channel 狀態：永遠是 "Publishing"                        │   │
│  │  • 通過審核後才能部署到這裡                                  │   │
│  │  • 所有 LINE 用戶都可以存取                                 │   │
│  │  • 不支援 Basic Authentication                              │   │
│  │  • 可設定 Custom Path（自訂網址路徑）                        │   │
│  │  • Service Message 可正常對外發送                            │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

### 5.2 設定各環境的 Endpoint URL

**操作步驟：**
1. 進入 LINE Developers Console
2. 選擇你的 Mini App Channel
3. 點擊「**Web app settings**」分頁
4. 分別為三個環境設定 Endpoint URL

```
範例設定：
  Developing:  https://dev.yourapp.com/
  Review:      https://review.yourapp.com/
  Published:   https://yourapp.com/

本地開發時（使用 ngrok）：
  Developing:  https://abc123def456.ngrok.io/
  ← 每次重啟 ngrok，這個網址會變，需重新設定
```

**啟動 ngrok（本地開發用）：**
```bash
# 假設你的 Web App 跑在 port 3000
ngrok http 3000

# 輸出類似：
# Forwarding  https://abc123def456.ngrok.io -> http://localhost:3000
# 把這個 HTTPS 網址貼到 Console 的 Endpoint URL
```

### 5.3 加入測試人員（Tester）

在 Developing 和 Review 環境，只有 Tester 才能存取：

**操作步驟：**
1. 進入 Mini App Channel
2. 點擊「**Roles**」分頁
3. 點擊「**Add Tester**」
4. 方式一：輸入測試者的 LINE User ID
5. 方式二：讓對方掃 QR Code

**如何找到自己的 LINE User ID？**
```javascript
// 在 Mini App 中執行：
const profile = await liff.getProfile();
console.log(profile.userId); // 這就是 User ID，格式：Uxxxxxxxxxx...
```

### 5.4 使用 Basic Authentication 保護開發環境

在 Developing / Review 環境，你可以設定帳號密碼保護：

```
在 Endpoint URL 中加入帳密：
```

### 7.2 Token 種類與使用規則

> ⚠️ **LINE Mini App Channel 有特殊 Token 限制，和一般 LIFF 不同！**

| Token 類型 | 說明 | 能否用於 Mini App Channel |
|-----------|------|:------------------------:|
| Long-lived channel access token | 不會過期，但風險高 | ❌ **完全不能用** |
| Channel Access Token v2.1 | 用戶指定到期時間 | ❌ **完全不能用** |
| Short-lived channel access token | 30 天有效 | ✅ 可以用 |
| **Stateless channel access token** | 每次都新生成，無限次 | ✅ **強烈推薦** |

**為什麼要用 Stateless Token？**

```
Stateless Token 的優點：
  ✅ 發行次數無限制（不像 Short-lived 有限制）
  ✅ 不需要儲存、不需要管理生命週期
  ✅ 每次使用前直接生成新的，安全性高
  ✅ LINE 官方推薦的方式
```

### 7.3 後端取得 Stateless Channel Access Token

```javascript
// utils/lineToken.js（Node.js 後端）

const axios = require('axios');

/**
 * 取得 Stateless Channel Access Token
 * 每次需要時直接呼叫，不需要快取
 */
async function getChannelAccessToken() {
  const response = await axios.post(
    'https://api.line.me/oauth2/v3/token',
    new URLSearchParams({
      grant_type: 'client_credentials',
      client_id: process.env.LINE_CHANNEL_ID,       // Channel ID
      client_secret: process.env.LINE_CHANNEL_SECRET, // Channel Secret
    }),
    {
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' }
    }
  );

  return response.data.access_token;
}

module.exports = { getChannelAccessToken };
```

## 第八章：Service Message API

> ⚠️ **限制說明**：
> - **Verified Mini App** 才能在 Published 環境正式發送
> - Developing 環境中可以測試，但訊息**不會真的發出**
> - 每個 Notification Token 有效期 **1 年**，最多發 **5 則**

### 8.1 Service Message 是什麼？

Service Message 是 LINE Mini App 的**免費推播通知**機制。不需要用戶加 Official Account 為好友，只要用戶使用過你的 Mini App，你就可以發送通知給他。

使用場景：
- 電商：「您的訂單 #12345 已出貨！」
- 餐廳：「您的預訂已確認，明天 19:00 見！」
- 醫療：「您的掛號提醒：明日上午 10:00 看診」

```javascript
// routes/notifications.js

const express = require('express');
const axios = require('axios');
const { getChannelAccessToken } = require('../utils/lineToken');
const router = express.Router();

// ─── 訂閱通知 ────────────────────────────────────────────────────
router.post('/subscribe', async (req, res) => {
  const { liffAccessToken } = req.body;

  if (!liffAccessToken) {
    return res.status(400).json({ error: '缺少 liffAccessToken' });
  }

  try {
    // 取得 Stateless Channel Access Token
    const channelToken = await getChannelAccessToken();

    // 向 LINE 申請 Service Notification Token
    const { data } = await axios.post(
      'https://api.line.me/message/v3/notifier/token',
      { liffAccessToken },
      {
        headers: {
          'Content-Type': 'application/json',
          'Authorization': `Bearer ${channelToken}`
        }
      }
    );

    const { notificationToken, expiresIn, remainingCount } = data;

    // 儲存 notificationToken 到資料庫
    // ⚠️ 必須要能透過 userId 找到對應的 token
    // 這裡假設你已有 session 機制取得 userId
    const userId = req.session.userId; // 替換成你的實際取得方式
    
    await db.upsert('notification_tokens', {
      userId,
      notificationToken,
      remainingCount,
      expiresAt: new Date(Date.now() + expiresIn * 1000)
    });

    res.json({ success: true, remainingCount });

  } catch (err) {
    const status = err.response?.status;
    const errData = err.response?.data;
    
    console.error('訂閱通知失敗：', status, errData);
    
    if (status === 400) {
      res.status(400).json({ error: 'LIFF Token 無效或已被使用過' });
    } else if (status === 403) {
      res.status(403).json({ error: '此 Channel 未授權使用 Service Message' });
    } else {
      res.status(500).json({ error: '伺服器錯誤，請稍後再試' });
    }
  }
});
```

```javascript
// services/serviceMessage.js

async function sendServiceMessage(userId, templateName, params) {
  // 從資料庫取得該用戶的 notificationToken
  const tokenRecord = await db.findOne('notification_tokens', { userId });
  
  if (!tokenRecord) {
    throw new Error(`找不到用戶 ${userId} 的 notificationToken`);
  }

  if (tokenRecord.remainingCount <= 0) {
    throw new Error('notificationToken 已用盡，需要用戶重新訂閱');
  }

  const channelToken = await getChannelAccessToken();

  const { data } = await axios.post(
    'https://api.line.me/message/v3/notifier/send?target=service',
    {
      templateName,  // 例如：'order_shipped_zh-TW'
      params,
      notificationToken: tokenRecord.notificationToken
    },
    {
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${channelToken}`
      }
    }
  );

  // ⚠️ 非常重要：每次發送後 token 都會更新，必須儲存新的！
  const { notificationToken: newToken, remainingCount } = data;
  
  await db.update('notification_tokens', 
    { userId },
    { 
      notificationToken: newToken, 
      remainingCount 
    }
  );

  console.log(`✅ 通知發送成功給 ${userId}，剩餘次數：${remainingCount}`);
  return { success: true, remainingCount };
}

// 使用範例：
```

### 10.2 前端：取得商品、同意條款、發起付款

```javascript
// iap.js（前端）

const PRODUCT_IDS = [
  'premium_monthly',   // 月費方案
  'premium_yearly',    // 年費方案
  'coin_pack_100',     // 100點虛擬貨幣
];

// ─── 取得商品列表 ──────────────────────────────────────────────
async function loadProducts() {
  try {
    const products = await liff.iap.getPlatformProducts({ 
      productIds: PRODUCT_IDS 
    });

    /* products 的資料結構：
    {
      "premium_monthly": {
        currency: "TWD",
        price: 99,
        productName: "進階月費方案"
      },
      "premium_yearly": {
        currency: "TWD",
        price: 999,
        productName: "進階年費方案"
      }
    }
    */

    renderProductList(products);
  } catch (err) {
    console.error('取得商品失敗：', err.message);
  }
}

// ─── 購買流程 ──────────────────────────────────────────────────
async function startPurchase(productId) {
  try {
    // Step A：確認用戶同意「LINE In-App Purchase 使用條款」
    // 如果已同意，這個呼叫會直接 resolve，不會顯示畫面
    await liff.iap.requestConsentAgreement();

  } catch (err) {
    if (err.message.includes('did not agree')) {
      alert('需要同意使用條款才能購買');
    }
    return;
  }

  let orderId;
  try {
    // Step B：向後端預留訂單，取得 orderId
    const response = await fetch('/api/iap/reserve', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        productId,
        userAccessToken: liff.getAccessToken(),  // 傳給後端用
        userOS: liff.getOS(),                    // 'ios' 或 'android'
      })
    });

    const data = await response.json();
    orderId = data.orderId;

  } catch (err) {
    alert('建立訂單失敗，請稍後再試');
    return;
  }

  try {
    // Step C：啟動 App Store / Google Play 付款畫面
    await liff.iap.createPayment({ productId, orderId });
    
    // ⚠️ 到這裡表示付款流程完成，但不要在這裡直接發放商品！
    // 要等 Webhook 確認才是安全的
    alert('✅ 付款完成！稍後確認後將發放商品。');

  } catch (err) {
    if (err.message.includes('cancel')) {
      alert('已取消購買');
    } else {
      alert('付款失敗：' + err.message);
    }
  }
}
```

### 10.3 後端：預留訂單（Reserve Purchase）

```javascript
// routes/iap.js（後端）

// ─── POST /api/iap/reserve ─────────────────────────────────────
router.post('/reserve', async (req, res) => {
  const { productId, userAccessToken, userOS } = req.body;
  
  // ⚠️ 用戶 IP 必須從伺服器端取得，不信任前端傳來的值
  const clientIp = req.ip || req.headers['x-forwarded-for'];
  
  try {
    // 注意：reserve 使用的是「用戶的 Access Token」，不是 Channel Token！
    const { data } = await axios.post(
      'https://api.line.me/iap/v1/product/reserve',
      {
        clientIp,
        clientOs: userOS,        // 'ios' 或 'android'
        productId,
        shopProductName: getProductName(productId)  // 最多20字，不能含emoji
      },
      {
        headers: {
          'Content-Type': 'application/json',
          'Authorization': `Bearer ${userAccessToken}` // 用用戶 token！
        }
      }
    );

    const { orderId } = data;

    // 將 orderId 儲存到資料庫（等 Webhook 時用來核對）
    await db.create('pending_orders', {
      orderId,
      productId,
      userId: req.session.userId,
      status: 'pending',
      createdAt: new Date()
    });

    res.json({ orderId });

  } catch (err) {
    const errCode = err.response?.data?.errorCode;
    const errMsg = err.response?.data?.message;
    
    console.error('Reserve 失敗：', errCode, errMsg);
    
    const errorMessages = {
      'WEBHOOK_URL_IS_NOT_SET': '尚未設定 Webhook URL，請在 Console 設定',
      'PRODUCT_ID_NOT_FOUND':   `商品 ${productId} 不存在`,
      'BLOCKED_USER':           '此用戶無法完成購買',
      'TERMS_AGREEMENT_ERROR':  '用戶尚未同意最新使用條款',
    };

    res.status(400).json({ 
      error: errorMessages[errCode] || '預留訂單失敗' 
    });
  }
});
```

### 10.4 後端：接收 Webhook（購買完成 / 退款事件）

```javascript
// routes/webhook.js（後端）

// ─── POST /webhook/iap ─────────────────────────────────────────
router.post('/iap', express.raw({ type: 'application/json' }), async (req, res) => {
  
  // Step 1：驗證 Webhook 簽名（防止偽造）
  const signature = req.headers['x-line-signature'];
  const body = req.body.toString();
  
  if (!verifyWebhookSignature(body, signature)) {
    console.warn('⚠️ Webhook 簽名驗證失敗！');
    return res.status(401).send('Unauthorized');
  }

  const event = JSON.parse(body);
  
  // ─── 購買完成事件 ─────────────────────────────────────────────
  if (event.type === 'purchaseComplete') {
    const { orderId, userId, productId, purchaseTimestamp, channelId } = event;

    console.log(`購買完成：orderId=${orderId}, userId=${userId}, productId=${productId}`);

    // Step 2：從資料庫取得待確認訂單
    const pendingOrder = await db.findOne('pending_orders', { orderId });
    
    if (!pendingOrder) {
      console.error(`未知的 orderId：${orderId}`);
      return res.status(200).send('OK'); // 回 200 避免 LINE 重發
    }
    
    if (pendingOrder.status === 'completed') {
      console.warn(`訂單 ${orderId} 已處理過，跳過`);
      return res.status(200).send('OK'); // 防重複處理
    }

    // Step 3：發放商品給用戶
    await grantProduct(userId, productId, orderId);
    
    // Step 4：更新訂單狀態
    await db.update('pending_orders', 
      { orderId }, 
      { status: 'completed', completedAt: new Date(purchaseTimestamp * 1000) }
    );

    console.log(`✅ 商品已發放：${userId} 獲得 ${productId}`);
  }

  // ─── 退款事件 ─────────────────────────────────────────────────
  if (event.type === 'refundComplete') {
    const { orderId, userId, productId, purchaseTimestamp } = event;
    
    console.log(`退款完成：orderId=${orderId}`);
    
    // 撤銷已發放的商品
    await revokeProduct(userId, productId, orderId);
    
    await db.update('pending_orders',
      { orderId },
      { status: 'refunded', refundedAt: new Date() }
    );
  }

  res.status(200).send('OK');
});

// Webhook 簽名驗證函式
function verifyWebhookSignature(body, signature) {
  const crypto = require('crypto');
  const hash = crypto
    .createHmac('SHA256', process.env.LINE_CHANNEL_SECRET)
    .update(body)
    .digest('base64');
  return hash === signature;
}
```

- 新增主要功能
- 更改服務性質
- 更改 Channel icon / name / description
- 使用新的 LIFF API 或 Permission

## 第十三章：常見錯誤與排查

### 13.1 LIFF 初始化錯誤

| 錯誤代碼 / 訊息 | 可能原因 | 解決方式 |
|----------------|---------|---------|
| `INVALID_ARGUMENT` | LIFF ID 填錯 | 確認 Console 中的 LIFF ID，完整複製貼上 |
| `FORBIDDEN` | Endpoint URL 與 Console 設定不符 | 確認開啟 Mini App 的網址，和 Console 設定的 Endpoint URL 一致 |
| `UNAUTHORIZED` | 未登入就呼叫需要登入的 API | 確認 `liff.isLoggedIn()` 後再呼叫 |
| 白畫面，無任何錯誤 | 靜態資源路徑錯誤 / HTTPS 設定問題 | 開啟 DevTools 查看 Console 錯誤 |

### 13.2 Service Message 錯誤

| HTTP 狀態碼 | 可能原因 | 解決方式 |
|-----------|---------|---------|
| `400 Bad Request` | ① LIFF Token 已被使用過<br>② Request body 格式錯誤 | ① 每個 LIFF Token 只能用一次換 Notification Token<br>② 確認 JSON 格式正確 |
| `401 Unauthorized` | Channel Token 或 LIFF Token 無效 / 過期 | 重新取得 Stateless Channel Access Token |
| `403 Forbidden` | ① 此 Channel 未授權發送 Service Message<br>② Template 名稱不存在 | ① 確認是 Verified Mini App 且在 Published 環境<br>② 確認 Console 中的 Template 名稱拼寫正確 |

### 13.3 IAP 錯誤

| errorCode | 原因 | 解決方式 |
|-----------|------|---------|
| `WEBHOOK_URL_IS_NOT_SET` | 沒有設定 Webhook URL | Console → IAP 設定 → 填寫 Webhook URL |
| `PRODUCT_ID_NOT_FOUND` | 商品 ID 不存在 | 確認 Console 中已建立該商品 ID |
| `TERMS_AGREEMENT_ERROR` | 用戶未同意最新條款 | 確認在購買前呼叫了 `liff.iap.requestConsentAgreement()` |
| `BLOCKED_USER` | 用戶被 LINE 判定為可疑 | 無法處理，記錄並回覆友好錯誤訊息 |
| `VALIDATION_ERROR` | 請求欄位格式錯誤 | 確認 `clientOs` 是 'ios' 或 'android'，`shopProductName` 不超過20字 |

### 13.4 常見開發問題 Q&A

**Q：本地開發時，Endpoint URL 要填什麼？**

```bash
# 用 ngrok 產生 HTTPS 隧道
ngrok http 3000

# ngrok 會顯示：
# Forwarding  https://abc123.ngrok.io -> http://localhost:3000
# 
# 把 https://abc123.ngrok.io 填到 Console 的 Endpoint URL（Developing）
# ⚠️ 每次重啟 ngrok，網址都會改變，需要再更新一次
```

**Q：為什麼取到的 profile.userId 和之前的不一樣？**

```
LINE 的 User ID 是 Provider 層級的，不是跨 Provider 的。
同一個用戶在不同 Provider 下會有不同的 User ID。

確認你的 Channel 是否還在同一個 Provider 下。
```

**Q：用戶在外部瀏覽器（Safari / Chrome）開啟時，怎麼處理？**

```javascript
if (!liff.isInClient()) {
  // 顯示提示，引導用戶用 LINE 開啟
  document.body.innerHTML = `
    <div style="text-align:center; padding:40px;">
      <h2>請用 LINE 開啟</h2>
      <p>掃描下方 QR Code，或用 LINE 點選連結</p>
      <img src="/qrcode.png" alt="QR Code" />
      <br>
      <a href="https://miniapp.line.me/你的LIFF_ID">
        點此在 LINE 中開啟
      </a>
    </div>
  `;
}
```

**Q：`liff.getAccessToken()` 回傳 null？**

```javascript
// ❌ 錯誤：在 liff.init() 完成前就呼叫
const token = liff.getAccessToken(); // null

// ✅ 正確：在 liff.init() 且確認登入後才呼叫
await liff.init({ liffId: LIFF_ID });
if (liff.isLoggedIn()) {
  const token = liff.getAccessToken(); // 有值
}
```

## 第十四章：完整 API 速查表

### 14.1 LIFF Client-side API

| 方法 | 說明 | 回傳 |
|------|------|------|
| `liff.init({ liffId, withLoginOnExternalBrowser })` | 初始化 LIFF（必須第一個呼叫）| `Promise<void>` |
| `liff.login({ redirectUri })` | 導向 LINE 登入 | `void` |
| `liff.logout()` | 登出 | `void` |
| `liff.isLoggedIn()` | 是否已登入 | `boolean` |
| `liff.isInClient()` | 是否在 LINE App 內 | `boolean` |
| `liff.getOS()` | 取得 OS | `'ios' \| 'android' \| 'web'` |
| `liff.getLanguage()` | 取得語言設定 | `string`（如 `'zh-TW'`）|
| `liff.getVersion()` | 取得 LIFF SDK 版本 | `string` |
| `liff.getAccessToken()` | 取得 LIFF Access Token（傳後端用）| `string \| null` |
| `liff.getProfile()` | 取得用戶 Profile | `Promise<Profile>` |
| `liff.closeWindow()` | 關閉 Mini App | `void` |
| `liff.openWindow({ url, external })` | 開啟連結 | `void` |
| `liff.shareTargetPicker(messages)` | 分享訊息 | `Promise<void>` |
| `liff.permanentLink.createUrl()` | 取得永久連結 | `string` |

### 14.2 Service Message API（後端呼叫）

| 端點 | 方法 | 說明 | Authorization |
|------|:----:|------|:------------:|
| `/message/v3/notifier/token` | POST | 發行 Notification Token | Channel Token |
| `/message/v3/notifier/send?target=service` | POST | 發送 Service Message | Channel Token |

### 14.3 In-App Purchase API

| 端點 / 方法 | 位置 | 說明 | Authorization |
|------------|:----:|------|:------------:|
| `liff.iap.getPlatformProducts({ productIds })` | 前端 | 取得商品列表 | — |
| `liff.iap.requestConsentAgreement()` | 前端 | 請求用戶同意 IAP 條款 | — |
| `liff.iap.createPayment({ productId, orderId })` | 前端 | 啟動 App Store / Google Play 付款 | — |
| `/iap/v1/product/reserve` | 後端 POST | 預留訂單（取得 orderId）| **用戶 Access Token** |
| `/iap/v1/webhook/events` | 後端 GET | 查詢 Webhook 事件歷史 | Channel Token |

> ⚠️ `/iap/v1/product/reserve` 使用的是**用戶的 Access Token**（`liff.getAccessToken()` 取得後由前端傳給後端），其他後端 API 使用 Channel Access Token。

### 14.4 Common Profile Quick-fill API

| 方法 | 說明 |
|------|------|
| `liff.$commonProfile.get(scopes, options)` | 顯示確認 Modal，讓用戶授權並取得 Common Profile |
| `liff.$commonProfile.getDummy(scopes, options, caseId)` | 取得測試用假資料（caseId: 1-10，僅開發環境）|
| `liff.$commonProfile.fill(profile)` | 將 profile 資料自動填入有 `data-liff-autocomplete` 屬性的表單欄位 |

### 14.5 Channel Access Token API

| 端點 | 說明 |
|------|------|
| `POST https://api.line.me/oauth2/v3/token` | 取得 Stateless Channel Access Token（後端用）|
