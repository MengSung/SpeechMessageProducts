請生成範例架構與程式碼時 **務必遵守以下要求**：

[架構需求]

4. 任何實作 IDisposable 的類別必須使用 `using` 或 `IAsyncDisposable`，並在範例中示範正確釋放資源。

[避免記憶體洩漏 Coding 規範]
5. 所有背景 Task 必須可取消，使用 CancellationToken，例如 QueueBackgroundWorkItem / HostedService。
6. 大資料對象(I/O, Stream, byte[]) 需確保釋放並避免無限制緩存。
7. 回傳集合時避免 `ToList()` 造成額外拷貝，提出最佳處理方式。
8. 避免事件未解除訂閱，若存在事件委派，請示範 Detach。

[記憶體行為監控與壓力測試]

我的核心目標是：**確保 ASP.NET Core 應用程式在長期運行和高負載情況下，記憶體使用量保持穩定，絕對不能出現記憶體洩漏或持續性、不可回收的記憶體增長。**

請以「生產級零記憶體洩漏」標準，全面檢查並強化目前這個 ASP.NET Core 10 專案，確保在長時間高併發下記憶體絕對不會持續增長。

請一次完成以下所有項目（不要分多次）：

1. 掃描並修正所有可能的記憶體洩漏來源：
   - 未註冊的 EventHandler / 靜態事件訂閱
   - 沒有 Dispose 的 IDisposable（HttpClient、Timer、Stream、DbContext、IHostedService 等）
   - 沒有取消的 async void、Task.Run、BackgroundService 內的無限迴圈
   - 沒有使用 IAsyncDisposable 的資源
   - 靜態變數、單例、Cache 持有 Controller/Service 實例或大物件

2. 強制使用正確的生命週期與資源管理模式：
   - 所有 IHostedService、BackgroundService 必須正確實作 StopAsync + Dispose
   - 所有 Timer、Polling 必須在 Dispose 時停止
   - 所有事件訂閱必須在 Dispose / Unsubscribe 時取消
   - HttpClient 只能用 IHttpClientFactory 或單例
   - Entity Framework 必須用 AddDbContextPool 或短生命週期 + 嚴格 NoTracking

3. 加入防記憶體持續增長的必備機制：
   - 所有 MemoryCache / IDistributedCache 必須設定絕對過期或滑動過期 + 大小限制
   - 所有自訂 Queue / Channel / BlockingCollection 必須有上限
   - 所有靜態 List/Dictionary 必須改用 Concurrent 並定期清理或改 Scoped/Singleton 注入
   - 禁止在 Controller / PageModel 內 new 大物件或長生命週期物件

4. 加入運行時檢查（僅 Development 環境）：
   - 在 Program.cs 加入 GC 監控，每 10 分鐘記錄一次 GC.CollectionCount + Process.PrivateMemorySize64
   - 在 Startup 加入 DiagnosticSource 監聽 Microsoft.AspNetCore.Hosting 與 EntityFrameworkCore 事件，偵測長時間請求與 EF 洩漏

5. 請直接給出：
   - 所有需要修改的檔案 + 完整修正後的程式碼（diff 格式或完整檔案）
   - 必須加入的 NuGet 套件（如 Microsoft.Extensions.Diagnostics.HealthChecks）
   - 最終的 Program.cs 與所有背景服務範例
   - 建議的 appsettings.Production.json 記憶體相關設定

目標：部署到 IIS 或 Linux 後，連續跑 7 天 1000 併發，記憶體增長 < 50MB 且最終穩定（可接受 GC 後回落）。
