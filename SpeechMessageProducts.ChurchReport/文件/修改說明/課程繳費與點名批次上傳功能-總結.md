### 2. 修改 FeeList.cs (業務邏輯層)

**檔案**: `ChurchReport\Models\FeeList.cs`

**變更點**:

#### 2.1 新增 ChangeHistory 屬性
```csharp
/// <summary>
/// 修改歷程 ViewModel (暫存修改，不立即提交到資料庫)
/// </summary>
public FeeChangeHistoryViewModel ChangeHistory { get; set; }
```

#### 2.2 修改 PopulateObjectAndUpdateEntity() 方法
- **原本**: 立即呼叫 `UpdateFeeDataList()` 更新資料庫
- **修改後**: 只更新記憶體物件，記錄修改到 `ChangeHistory`

```csharp
public void PopulateObjectAndUpdateEntity(string Values, Fee aFee)
{
    // 更新記憶體中的 Fee 物件
    JsonConvert.PopulateObject(Values, aFee, settings);

    // ? 記錄修改到 ChangeHistory，而不直接更新資料庫
    ChangeHistory.RecordChange(aFee.StorLessonsId, Key, Value);

    // 處理特殊欄位的聯動邏輯（僅更新記憶體）
    if (Key == "Amount" && !string.IsNullOrEmpty(Value) && Value != "0")
    {
        ChangeHistory.RecordChange(aFee.StorLessonsId, "PayDate", DateTime.Now.ToUniversalTime().ToString("u"));
        ChangeHistory.RecordChange(aFee.StorLessonsId, "PayWay", "現金");
    }
}
```

#### 2.3 新增 CommitPendingChanges() 方法
```csharp
/// <summary>
/// 批次提交所有待處理的修改到資料庫
/// </summary>
public int CommitPendingChanges()
{
    int successCount = 0;

    foreach (var changeRecord in ChangeHistory.PendingChanges.Values)
    {
        try
        {
            // 對每個欄位執行資料庫更新
            foreach (var field in changeRecord.ModifiedFields)
            {
                bool createFlag = false;
                m_FeeDownUpLoader.UpdateFeeDataList(
                    field.Key, 
                    field.Value, 
                    changeRecord.StorLessonsId, 
                    ref createFlag);
            }
            successCount++;
        }
        catch (Exception ex)
        {
            // 記錄錯誤，繼續處理其他記錄
        }
    }

    // 清除所有待處理的修改
    ChangeHistory.ClearAll();

    return successCount;
}
```

### 3. 修改 FeeManagementController.cs (API 層)

**檔案**: `ChurchReport\Controllers\FeeManagementController.cs`

**變更點**:

#### 3.1 UpdateFeeData API - 記錄修改到 ChangeHistory
```csharp
[HttpPut]
[Route("/FeeManagement/Api/UpdateFeeData")]
public IActionResult UpdateFeeData(string key, string values)
{
    var fee = InMemoryContext.FeeList.FeeDataList?.FirstOrDefault(f => f.StorLessonsId == key);

    // ? 只更新記憶體，記錄修改歷程
    InMemoryContext.FeeList.PopulateObjectAndUpdateEntity(values, fee);

    System.Diagnostics.Debug.WriteLine(
        $"[UpdateFeeData] 修改已記錄 - 待處理修改數: {InMemoryContext.FeeList.ChangeHistory.GetPendingCount()}");

    return Ok();
}
```

#### 3.2 SaveBatch API - 批次提交所有修改
```csharp
[HttpPost]
[Route("/FeeManagement/Api/SaveBatch")]
public IActionResult SaveBatch(string aResult)
{
    try
    {
        // ? 執行批次提交所有待處理的修改
        int successCount = InMemoryContext.FeeList.CommitPendingChanges();

        return Json(new
        {
            status = "success",
            message = $"繳費資料已成功儲存 ({successCount} 筆記錄已更新)",
            count = successCount
        });
    }
    catch (Exception ex)
    {
        return Json(new
        {
            status = "error",
            message = ex.Message
        });
    }
}
```

#### 4.4 新增 JavaScript 追蹤修改數量
```javascript
var pendingChangesMap = {};

function updatePendingChangesIndicator() {
    var count = Object.keys(pendingChangesMap).length;
    $("#pendingChangesCount").text(count);
    
    if (count > 0) {
        $("#pendingChangesIndicator").show();
    } else {
        $("#pendingChangesIndicator").hide();
    }
}

function recordDataChange(storLessonsId, fieldName) {
    if (!pendingChangesMap[storLessonsId]) {
        pendingChangesMap[storLessonsId] = new Set();
    }
    pendingChangesMap[storLessonsId].add(fieldName);
    updatePendingChangesIndicator();
}

function clearPendingChanges() {
    pendingChangesMap = {};
    updatePendingChangesIndicator();
}
```

## ?? 效能影響分析

### 優點 ?

1. **減少資料庫連線次數**
   - 修改前: 每次編輯 1 次連線
   - 修改後: 批次上傳 1 次連線
   - **改善幅度**: 若編輯 10 筆記錄，從 10 次連線減少到 1 次連線（減少 90%）

2. **提升使用者體驗**
   - 編輯流暢度不受網路延遲影響
   - 可以連續編輯多筆資料，最後一次上傳
   - 明確的待上傳指標，讓使用者知道狀態

3. **降低伺服器負載**
   - 減少不必要的資料庫更新請求
   - 批次處理提升效率

### 缺點 ??

1. **資料同步延遲**
   - 修改不會立即反映到資料庫
   - **影響**: 可接受，因為是刻意設計

2. **記憶體佔用**
   - 需要額外記憶體儲存 `ChangeHistory`
   - **影響**: 極小，每筆記錄僅佔用少量記憶體
