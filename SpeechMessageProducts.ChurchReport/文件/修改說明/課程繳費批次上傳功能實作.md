## ?? 修改摘要

將 `FeeView.cshtml` (課程繳費頁面) 實作與 `PresentView.cshtml` (課程點名頁面) 相同的批次上傳功能。

## ?? 修改目標

1. **延遲資料庫更新**: 修改不立即提交到資料庫
2. **暫存修改歷程**: 所有修改先暫存在 `FeeChangeHistoryViewModel`

```javascript
.OnClick(@<text>
    function(arg) {
        var dataGrid = $("#FeeGridContainer").dxDataGrid("instance");
        var ButtonContainer = $("#save-button").dxButton("instance");

        // ? 先儲存 DataGrid 的所有編輯變更到本地
        $("#FeeGridContainer").dxDataGrid("instance").saveEditData();

        // ? 檢查是否有待處理的變更
        var pendingChangesCount = dataGrid.hasEditData();
        
        if (!pendingChangesCount) {
            // 沒有待處理的變更，顯示提示
            DevExpress.ui.notify("目前沒有需要上傳的資料變更", "info", 2000);
            return;
        }

        // 顯示旋轉載入面板
        $("#loadPanel").dxLoadPanel("instance").show();

        // 禁用上傳按鈕
        ButtonContainer.option("disabled", true);

        // AJAX 請求批次上傳數據
        $.ajax({
            url: '@Url.Action("SaveBatch", "FeeManagement")',
            data: { aResult: "" },
            type: 'POST',
            success: function (response) {
                $("#loadPanel").dxLoadPanel("instance").hide();
                ButtonContainer.option("disabled", false);

                if (response.status === "success") {
                    // 顯示成功提示，包含更新筆數
                    var message = response.count > 0 
                        ? "上傳成功! 已更新 " + response.count + " 筆記錄" 
                        : "上傳成功!";
                    
                    DevExpress.ui.notify(message, "success", 3000);
                    
                    // ? 清除待上傳修改記錄
                    clearPendingChanges();
                    
                    // ? 重新載入資料以確保與資料庫同步
                    dataGrid.refresh();
                } else {
                    DevExpress.ui.notify("上傳失敗: " + response.message, "error", 5000);
                }
            },
            error: function (xhr, status, error) {
                $("#loadPanel").dxLoadPanel("instance").hide();
                ButtonContainer.option("disabled", false);

                var errorMessage = "上傳時發生錯誤";
                if (xhr.responseJSON && xhr.responseJSON.message) {
                    errorMessage += ": " + xhr.responseJSON.message;
                }
                DevExpress.ui.notify(errorMessage, "error", 5000);
                
                console.error("上傳錯誤:", error);
            }
        });
    }
</text>)
```

**主要變更**:
- ? 改為呼叫 `SaveBatch` API (批次上傳)
- ? 加入待處理變更檢查
- ? 使用 `DevExpress.ui.notify` 顯示友善提示
- ? 顯示上傳成功後的更新筆數
- ? 上傳成功後清除待上傳記錄
- ? 上傳成功後重新載入資料
- ? 加入完整的錯誤處理

### 4. 新增 JavaScript 追蹤修改數量

在 `<script>` 區塊中加入:

```javascript
// ? 追蹤待上傳的修改數量
var pendingChangesMap = {}; // Key: StorLessonsId, Value: 修改的欄位集合

// ? 更新待上傳修改數量的顯示
function updatePendingChangesIndicator() {
    var count = Object.keys(pendingChangesMap).length;
    var indicator = $("#pendingChangesIndicator");
    var countSpan = $("#pendingChangesCount");

    countSpan.text(count);

    if (count > 0) {
        indicator.show();
        console.log('[FeeView - PendingChanges] 目前有 ' + count + ' 筆待上傳的修改');
    } else {
        indicator.hide();
    }
}

// ? 記錄資料修改
function recordDataChange(storLessonsId, fieldName) {
    if (!pendingChangesMap[storLessonsId]) {
        pendingChangesMap[storLessonsId] = new Set();
    }
    pendingChangesMap[storLessonsId].add(fieldName);
    updatePendingChangesIndicator();
}

// ? 清除所有待處理的修改記錄
function clearPendingChanges() {
    pendingChangesMap = {};
    updatePendingChangesIndicator();
}

// 調試：顯示當前數據來源參數
console.log('[FeeView] Model.FeeDataList Count:', @(Model.FeeDataList?.Count ?? 0));
```

**功能說明**:
- `pendingChangesMap`: 追蹤每筆記錄的修改欄位
- `updatePendingChangesIndicator()`: 更新指標顯示
- `recordDataChange()`: 記錄單筆修改
- `clearPendingChanges()`: 清除所有待上傳記錄

## ?? 測試建議

### 1. 功能測試

| 測試項目 | 操作步驟 | 預期結果 |
|---------|---------|---------|
| 修改單筆繳費記錄 | 修改一筆記錄的「實收金額」 | 指標顯示「1 筆待上傳」 |
| 修改多筆記錄 | 修改 3 筆不同記錄 | 指標顯示「3 筆待上傳」 |
| 修改同一筆記錄多次 | 修改同一筆的多個欄位 | 指標仍顯示「1 筆待上傳」 |
| 批次上傳成功 | 點擊「上傳」按鈕 | 顯示「上傳成功! 已更新 X 筆記錄」 |
| 無修改時上傳 | 不修改任何資料，直接點擊「上傳」 | 顯示「目前沒有需要上傳的資料變更」 |
| 上傳後重新載入 | 上傳成功後 | DataGrid 重新載入，顯示最新資料 |

### 2. 特殊欄位測試

| 欄位 | 測試項目 | 預期行為 |
|------|---------|---------|
| 實收金額 (Amount) | 填入金額後 | 自動設定「繳費日期」和「付款方式=現金」 |
| 繳費日期 (PayDate) | 選擇日期 | 正常記錄修改 |
| 退費金額 (RefundAmount) | 填入退費金額 | 自動設定「退費日期」 |
| 付款方式 (PayWay) | 切換付款方式 | 正常記錄修改 |

### 3. 資料庫驗證

1. 修改 2 筆繳費記錄（例如: 修改實收金額）
2. **不點擊「上傳」按鈕**
3. 查詢資料庫 → 資料應未變更 ?
4. 點擊「上傳」按鈕
5. 再次查詢資料庫 → 2 筆記錄已更新 ?

## ?? 效能影響分析

### 優點 ?

1. **減少資料庫連線次數**: 從「每次編輯 1 次連線」改為「批次上傳 1 次連線」
2. **提升使用者體驗**: 使用者可以連續編輯多筆資料，最後一次上傳
3. **降低網路延遲影響**: 不會因為網路慢而影響編輯流暢度
4. **統一行為**: 與 `PresentView.cshtml` (課程點名頁面) 行為一致

### 缺點 ??

1. **資料同步延遲**: 修改不會立即反映到資料庫（可接受，因為是刻意設計）
2. **記憶體佔用**: 需要額外記憶體儲存 `ChangeHistory`（影響極小）
