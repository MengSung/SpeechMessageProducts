# 裝備狀態聯絡人錯誤歸屬問題診斷與修復指南

## ?? 問題描述

**症狀**: 裝備狀態頁面中，某個小組的聯絡人錯誤地顯示在其他小組中

**具體表現**:
```
小組 A
  ├─ 張三 ? (正確)
  ├─ 李四 ? (正確)
  └─ 王五 ? (錯誤！應該在小組 B)

小組 B
  ├─ 趙六 ? (正確)
  └─ (缺少王五)
```

**影響範圍**: 
- 裝備狀態頁面 (EquipmentView)
- 可能影響週報和統計

**嚴重程度**: ?? 高 - 導致資料混亂和錯誤統計

---

## ?? 問題根源分析

### 根源 1: 出席記錄的小組關聯錯誤 (90% 可能性)

**問題**: 聯絡人的出席記錄（`new_present_record`）關聯到錯誤的小組名單或週報

**位置**: `GetAllMemberDataFromPresentRecord` 方法

```csharp
private void GetAllMemberDataFromPresentRecord(String GroupName, Guid WeeklyReportId, ref ListSmallGroupWeeklyReport aListSmallGroupWeeklyReport)
{
    // 搜尋這個週報裡的所有個人聚會與靈修記錄集合
    EntityCollection PresentRecordCollection = GetPresentRecordByLoginType(GroupName, WeeklyReportId, ref aListSmallGroupWeeklyReport);
    
    // ? 問題：如果出席記錄的小組關聯錯誤，聯絡人會出現在錯誤的小組
    foreach (Entity PresentRecordEntity in PresentRecordCollection.Entities)
    {
        // ... 處理出席記錄
        // 問題：沒有驗證出席記錄的小組是否與當前小組一致
    }
}
```

**資料流程**:
```
週報 (new_group_present_weekly_report)
  ├─ 關聯小組: 小組 A
  └─ 包含出席記錄:
      ├─ 張三的記錄 → 小組名單: 小組 A ?
      ├─ 李四的記錄 → 小組名單: 小組 A ?
      └─ 王五的記錄 → 小組名單: 小組 B ? (錯誤關聯！)
```

### 根源 2: 名單成員資料錯誤 (8% 可能性)

**問題**: 聯絡人被錯誤地加入到多個小組名單中

**位置**: `GetAllMemberDataFromList` 方法

```csharp
private void GetAllMemberDataFromList(String GroupName, Guid ListEntityId, ref ListSmallGroupWeeklyReport aListSmallGroupWeeklyReport)
{
    Entity ListEntity = this.m_ToolUtilityClass.RetrieveEntity("list", ListEntityId);
    
    // ? 問題：如果聯絡人在多個名單中，可能導致重複或錯誤顯示
    EntityCollection MemberCollection = /* 查詢名單成員 */;
    
    foreach (Entity MemberEntity in MemberCollection.Entities)
    {
        // ... 添加成員
    }
}
```

### 根源 3: 週報關聯錯誤 (2% 可能性)

**問題**: 週報本身關聯到錯誤的小組名單

## ?? 診斷步驟

### 步驟 1: 識別問題聯絡人

**請提供以下資訊**:
1. 哪個聯絡人出現在錯誤的小組中？
2. 這個聯絡人應該屬於哪個小組？
3. 這個聯絡人錯誤地顯示在哪個小組中？

**範例**:
- 聯絡人: 王五
- 應該在: 小組 B
- 錯誤顯示在: 小組 A

### 步驟 2: 在 CRM 中檢查聯絡人的基本資料

1. **查詢聯絡人**
   ```
   CRM → 聯絡人 → 搜尋 "王五"
   ```

2. **檢查所屬名單**
   - 查看 "名單" 相關記錄
   - 確認王五在哪些名單中
   - 檢查是否有重複或錯誤的名單

3. **記錄資訊**:
   ```
   聯絡人: 王五
   ContactId: {GUID}
   所屬名單:
     - 小組 A (ListId: {GUID-A}) ← 錯誤！
     - 小組 B (ListId: {GUID-B}) ← 正確
   ```

### 步驟 3: 檢查出席記錄的小組關聯

**在 CRM 中執行查詢**:

1. **查詢王五的所有出席記錄**
   ```
   進階尋找 → 個人聚會與靈修記錄
   篩選: 聯絡人 = "王五"
   顯示欄位: 
     - 名稱
     - 主日日期
     - 小組名單 (new_list_new_present_record)
     - 週報 (new_group_present_weekly_report_prese)
   ```

2. **檢查每筆記錄的小組關聯**
   ```
   記錄 1: 2024/01/15
     - 小組名單: 小組 A ? (錯誤！)
     - 週報: 小組 A 的週報
   
   記錄 2: 2024/01/22
     - 小組名單: 小組 B ? (正確)
     - 週報: 小組 B 的週報
   ```

### 步驟 4: 檢查週報的小組關聯

1. **查詢小組 A 的週報**
   ```
   進階尋找 → 小組主日週報
   篩選: 小組名單 = "小組 A"
   顯示欄位:
     - 週報名稱
     - 主日日期
     - 小組名單
   ```

2. **檢查週報包含的出席記錄**
   - 開啟週報
   - 查看 "相關" → "個人聚會與靈修記錄"
   - 確認是否包含王五的記錄

### 步驟 5: 使用 FetchXML 深入診斷

**查詢王五的出席記錄及其小組關聯**:

```xml
<fetch version='1.0'>
  <entity name='new_present_record'>
    <attribute name='new_name' />
    <attribute name='new_sunday_date' />
    <attribute name='new_list_new_present_record' />
    <attribute name='new_group_present_weekly_report_prese' />
    <link-entity name='contact' from='contactid' to='new_contact_new_present_record'>
      <filter>
        <condition attribute='fullname' operator='eq' value='王五' />
      </filter>
    </link-entity>
    <link-entity name='list' from='listid' to='new_list_new_present_record' alias='list'>
      <attribute name='listname' />
    </link-entity>
    <link-entity name='new_group_present_weekly_report' from='new_group_present_weekly_reportid' to='new_group_present_weekly_report_prese' alias='report'>
      <link-entity name='list' from='listid' to='new_list_weekly_report' alias='reportlist'>
        <attribute name='listname' />
      </link-entity>
    </link-entity>
  </entity>
</fetch>
```

**結果分析**:
```
記錄 1:
  - 出席記錄: 王五-2024/01/15
  - 小組名單 (list.listname): 小組 A ← 問題！
  - 週報小組 (reportlist.listname): 小組 A
  
記錄 2:
  - 出席記錄: 王五-2024/01/22
  - 小組名單 (list.listname): 小組 B ← 正確
  - 週報小組 (reportlist.listname): 小組 B
```

## ?? 修復方案

### 方案 A: 修正出席記錄的小組關聯（最常見）

**步驟**:

1. **找到錯誤的出席記錄**
   - 使用步驟 3 的查詢找到王五關聯到小組 A 的記錄

2. **修正小組名單欄位**
   ```
   CRM → 個人聚會與靈修記錄 → 開啟錯誤的記錄
   
   修改前:
   - 小組名單: 小組 A
   
   修改後:
   - 小組名單: 小組 B
   ```

3. **修正週報關聯**
   ```
   修改前:
   - 週報: 小組 A 的週報
   
   修改後:
   - 週報: 小組 B 的週報（或清空）
   ```

4. **儲存變更**

### 方案 B: 從錯誤的名單中移除聯絡人

**步驟**:

1. **導航到錯誤的名單**
   ```
   CRM → 行銷 → 名單 → 小組 A
   ```

2. **移除聯絡人**
   ```
   點擊 "成員" 標籤
   找到 "王五"
   勾選並點擊 "從名單移除"
   確認移除
   ```

3. **確認正確的名單包含該聯絡人**
   ```
   CRM → 行銷 → 名單 → 小組 B
   確認 "王五" 在成員列表中
   ```

### 方案 C: 刪除錯誤的出席記錄（如果是重複建立）

**步驟**:

1. **確認是重複或錯誤建立的記錄**
   - 檢查記錄的建立日期
   - 檢查記錄的內容是否為空或無意義

2. **刪除記錄**
   ```
   CRM → 個人聚會與靈修記錄
   開啟錯誤的記錄
   點擊 "刪除"
   確認刪除
   ```

### 檢查聯絡人所屬名單
```
CRM → 行銷 → 進階尋找 → 名單
→ 新增相關 → 名單成員 → 新增相關 → 聯絡人
→ 篩選: 全名 = "{聯絡人姓名}"
→ 執行查詢
```

### 檢查出席記錄小組關聯
```
CRM → 進階尋找 → 個人聚會與靈修記錄
→ 新增相關 → 聯絡人
→ 篩選: 全名 = "{聯絡人姓名}"
→ 顯示: 名稱、主日日期、小組名單、週報
→ 執行查詢
```

### 修正出席記錄
```
開啟錯誤的出席記錄
→ 修改 "小組名單" → 選擇正確的小組
→ 修改 "週報" → 選擇正確的週報或清空
→ 儲存
```

### 從名單移除聯絡人
```
CRM → 行銷 → 名單 → {錯誤的小組}
→ 成員標籤
→ 勾選聯絡人
→ 從名單移除
→ 確認
```

## ?? 常見場景和解決方案

### 場景 1: 聯絡人轉組後資料未更新

**症狀**: 王五從小組 A 轉到小組 B，但舊的出席記錄仍然關聯到小組 A

**解決方案**:
1. 更新舊出席記錄的小組關聯（方案 A）
2. 或從小組 A 的名單中移除（方案 B）

### 場景 2: 出席記錄被錯誤建立

**症狀**: 同一個聯絡人有多筆出席記錄，分別關聯到不同小組

**解決方案**:
1. 刪除錯誤的出席記錄（方案 C）
2. 保留正確的出席記錄

### 場景 3: 聯絡人在多個名單中

**症狀**: 聯絡人同時在小組 A 和小組 B 的名單中

**解決方案**:
1. 從錯誤的名單中移除（方案 B）
2. 確認只在正確的名單中

### 場景 4: 週報關聯錯誤

**症狀**: 小組 A 的週報包含小組 B 成員的出席記錄

**解決方案**:
1. 修正出席記錄的週報關聯（方案 A）
2. 或重新建立正確的週報
