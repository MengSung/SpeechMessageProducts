## 路由配置原則

### 1. 路由命名規範
- 使用 **RESTful** 風格命名
- 控制器名稱反映功能領域
- Action 名稱清楚描述操作

### 2. 參數傳遞
- 使用路由參數：`{param}`
- 支援可選參數：`{param?}`
- 保持向後相容性

### 3. 控制器分組
```
登入系統    → HomeController
小組管理    → SmallGroupController
新人管理    → NewPersonController
個人資訊    → PersonalController
行事曆      → SchedulerController, AppointmentController
奉獻管理    → DedicationController
奉獻稽核    → DedicationAuditController
QR Code     → QrCodeController
名單管理    → ListManagementController
```

## 向後相容性處理

### 方案 1: URL 重定向
在舊的路由中加入重定向邏輯：

```csharp
// 在 HomeController 中保留舊方法，重定向到新位置
[Route("/Home/MultiGroupView/{LoginParameter}")]
public IActionResult MultiGroupView_Deprecated(string LoginParameter)
{
    return RedirectToAction("MultiGroupView", "SmallGroup", new { LoginParameter });
}
```

### 方案 2: 路由別名
在 `Startup.cs` 中保留舊路由作為別名：

```csharp
// 舊路由別名（向後相容）
routes.MapRoute(
    name: "multigroup_legacy",
    template: "Home/MultiGroupView/{LoginParameter?}",
    defaults: new { controller = "SmallGroup", action = "MultiGroupView" });
```

### 方案 3: 兩者並存
暫時保留 `HomeController` 中的舊方法，同時在新控制器中實作新方法，逐步遷移。

## 注意事項

### 1. LINE LIFF 路由
LINE LIFF 功能的路由必須保持穩定，因為已經在 LINE Developer Console 註冊：
- 不能隨意更改 URL 結構
- 如需更改，必須同步更新 LINE Developer Console 設定

### 2. QR Code 路由
QR Code 中包含的 URL 可能已經印製或分享：
- 建議保留舊路由或建立重定向
- 新功能使用新路由結構

### 3. API 端點
確保所有 AJAX 呼叫的端點都已更新：
- DevExtreme DataGrid
- 自訂 AJAX 請求
- JavaScript 路由生成
