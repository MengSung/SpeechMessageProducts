## ?? 極簡化策略

### 核心理念
**ToolUtilityClass.Minimal.cs 是純粹的 Facade**
- ? 不包含任何業務邏輯
- ? 不包含任何具體實現
- ? 僅提供統一的委派介面
- ? 向後相容所有呼叫

### 設計原則
1. **單一職責（SRP）** - 只負責「委派」
2. **開放封閉（OCP）** - 新增服務無需修改 Facade
3. **依賴反轉（DIP）** - 依賴抽象介面而非具體類別
4. **介面隔離（ISP）** - 每個服務有獨立介面
5. **里氏替換（LSP）** - 所有服務可替換實現

## ?? 關鍵簡化點

### 1. 移除所有直接實現
```csharp
// ? 舊版本：直接實現邏輯（1726 行）
public string GetEntityStringAttribute(ref Entity entity, string attrName)
{
    if (entity == null || !entity.Contains(attrName))
        return string.Empty;
    return entity[attrName]?.ToString() ?? string.Empty;
}

// ? 極簡版：純粹委派（1 行）
public string GetEntityStringAttribute(ref Entity entity, string attrName) 
    => EntityAttributeHandler.GetStringAttribute(entity, attrName);
```
