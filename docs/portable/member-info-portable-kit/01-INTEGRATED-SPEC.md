# 會友資訊整合規格

## 使用方式與規格優先序

- **MI-USE-001 — 先盤點、後適配。** 目標 AI 必須先確認目標專案的 framework、DevExtreme 前後端版本、CRM logical names、權限來源、照片儲存、LINE 契約與測試入口，再提出差異報告；未完成盤點不得修改程式。此流程承接套件的「先分析差異再適配」原則，而不是要求把 Sunny 原檔覆蓋到另一個教會版本。[權威需求](authoritative-context/requirements.md)
- **MI-USE-002 — 本文件是整合後的最終行為契約。** 若十一份原始規格彼此因演進而不同，以本文件為準；[權威 requirements](authoritative-context/requirements.md) 補充樹狀功能的安全與效能修正；[原始規格](original-specs/)用於追溯決策背景。參考實作只示範 Sunny 的一種整合方式，不得凌駕目標版本既有安全模型。[權威需求](authoritative-context/requirements.md)
- **MI-USE-003 — 以目標環境事實決定適配點。** CRM 欄位名稱、授權資料來源、照片 storage 或 LINE credentials contract 與 Sunny 不同時，保留本文件的行為與安全不變，改寫整合接點；若事實無法建立，停止該階段並列出缺少證據、可選方案與影響，等待使用者核准。[權威需求](authoritative-context/requirements.md)
- **MI-USE-004 — 每階段都要留下證據。** 至少保留盤點結果、測試命令與輸出、授權負向測試、瀏覽器／手機操作結果、嚴格 UTF-8 檢查及最終 diff；只有畫面截圖而沒有資料與權限證據，不算完成。[Session 註解與 UTF-8 規格](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)

## MI-AUTH：角色、範圍與批次授權

- **MI-AUTH-001 — 只接受兩種已解析範圍。** 後端把目標系統既有身分／claims 映射成 `Church`（全教會）或 `ShepherdList`（牧養名單）；無登入資料、未知角色或解析失敗一律不授權。Sunny 的 `new_church_jobtitle`、`ListManager.LoginType` 與職稱文字只是來源範例，不得在尚未核對目標教會角色模型時硬編碼照搬。[樹狀原始規格：存取範圍](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威安全修正](authoritative-context/requirements.md)
- **MI-AUTH-002 — Church 仍須驗證清單。** `Church` 可讀所有符合有效小組條件的清單及「無小組」，但每個外部傳入的 `listId` 必須落在伺服器即時建立的 authoritative visible-list set；不得因為是 Church 就接受任意非空 GUID。[權威安全修正](authoritative-context/requirements.md)
- **MI-AUTH-003 — Shepherd 採交集。** `ShepherdList` 可見清單是「有效小組清單」與登入者牧養清單 ID 集合的交集；不得只信任前端 listId，也不得顯示「無小組」。[樹狀原始規格：牧養名單](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威安全修正](authoritative-context/requirements.md)
- **MI-AUTH-004 — 有效小組條件。** Sunny 的 authoritative set 只含 `list.statecode = 0`、`purpose = "小組名單"`、`new_app_named = true` 的 `list`。目標欄位或值不同時必須先取得 schema／資料擁有者確認，不得 invent field 或放寬條件。[權威安全修正](authoritative-context/requirements.md)
- **MI-AUTH-005 — 查詢後批次授權。** Group、Search、Ungrouped、照片批次等端點先取得候選 contact IDs，再以 chunked `CanViewContactsBatch` 或目標系統等價的批次授權一次過濾，最後才組 DTO；禁止在每一列呼叫 CRM 授權服務，也禁止先回傳再由前端隱藏。[Session 註解規格](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)｜[權威安全修正](authoritative-context/requirements.md)
- **MI-AUTH-006 — fail closed。** 越權 list、非 Church 存取 Ungrouped、未知 access、畸形 GUID 或無法解析「結案」OptionSet 時，端點必須拒絕或回可診斷錯誤；不得以空條件、全部資料或略過過濾的方式繼續。[權威安全修正](authoritative-context/requirements.md)
- **MI-AUTH-007 — 個人範圍不可共用快取。** Church 的無個資骨架與 grouped-ID snapshot 可共用短期快取；Shepherd 骨架、搜尋結果及任何使用者專屬資料不得進入跨使用者共用快取。[樹狀原始規格：快取邊界](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威安全修正](authoritative-context/requirements.md)
- **MI-AUTH-008 — 寫入沿用既有聯絡人授權。** 明細照片上傳與其他既有更新功能必須以目標版本 authoritative contact-write policy 驗證，不得把「能看」自行推論為「能改」；若目標版本沒有明確寫入授權契約，只停止照片上傳／contact update 等寫入 capability，不得連帶阻擋已通過 schema 與 read authorization gate 的樹、成員、搜尋或明細讀取。[權威需求：先比對權限](authoritative-context/requirements.md)
- **MI-AUTH-009 — LINE 重新同步限 Church。** 候選 ID 與分批同步兩個入口均須在伺服器驗證 Church；前端是否顯示按鈕不是授權措施。[樹狀原始規格：工具列](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威安全修正](authoritative-context/requirements.md)
- **MI-AUTH-010 — 成員 read 授權來源是核心 hard stop。** 若無法指出 Church／Shepherd 的 authoritative claims、登入資料、清單歸屬與 contact read 授權服務，目標 AI 只能輸出差異與待確認問題，並阻擋核心 tree／member／search／detail read API；禁止編碼、放寬權限或建立臨時 allow-all。Contact write policy 只依 MI-AUTH-008 阻擋寫入 capability，不得擴張為核心 read blocker。[權威需求](authoritative-context/requirements.md)

## MI-DATA：CRM 欄位、PascalCase DTO 與日期正規化

- **MI-DATA-001 — Entity 契約。** Sunny 的核心樹與成員 read 使用 `contact`、`list`、`listmember`，relationship enrichment 另使用 `connection`；目標 AI 必須用 metadata、既有查詢或 schema 文件逐一證明欲啟用 capability 的 entity 與 logical name 存在，不能由畫面中文名稱猜欄位。[樹狀原始規格：CRM 對應](original-specs/2026-07-15-member-info-district-group-tree-design.md)
- **MI-DATA-002 — Contact 欄位。** 核心成員列至少需要 `contactid`、`fullname`、`gendercode`、`birthdate`、`mobilephone`、`new_spiriitual_identity`、`address2_line1`、`customertypecode`、`statecode`；主要照片 prerequisite 另需要已確認的 photo read/storage mapping，LINE 圖片 fallback／重新同步另需要已確認的 LINE 欄位。目標版本若使用不同 custom fields，必須建立明確 mapping 並經使用者核准；核心欄位缺口阻擋核心 read，照片或 LINE 欄位缺口則只阻擋其對應 capability。[樹狀原始規格：成員欄位](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威需求](authoritative-context/requirements.md)
- **MI-DATA-003 — List／listmember 欄位。** 小組骨架使用 `listid`、`listname`、`statecode`、`purpose`、`new_app_named`、`new_area_name`、`new_contact_race_leager_list`、`new_contact_family_leader_list`、`new_contact_list_arealeader`，並由既有 `FetchSmallGroupDescriptors` 單一 list query 一併取得 `new_group_time`、`new_group_place`；不得為時間／地點增加逐小組 CRM request。成員關聯使用 `listmember.listid` 與 `listmember.entityid`。注意 `race_leager` 是 Sunny 現有 logical name 的拼法，未核對前不得「修正」字串。[樹狀原始規格：CRM 對應](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[最新摘要規格：CRM list 查詢](original-specs/2026-07-17-member-info-column-order-group-metadata-design.md)
- **MI-DATA-004 — Connection 欄位。** 關係目標由 `connection.record1id`、`record2id`、`record1roleid`、`record2roleid` 取得，依對象方向選對角色，批次查詢後以穩定順序去重。Schema／read privilege 尚未確認時，只停止 relationship enrichment 與 MI-DETAIL 的關係目標 stage 並要求決策，不得停止核心樹或移除成員列；已確認目標未啟用或不允許讀取 `connection` 時，可依核准降級保留成員列、關係目標留白，並留下診斷與驗收例外，不得逐人重試。若目標驗收要求關係目標必備，必須補齊 schema／read privilege 後才能完成該 capability。[樹狀原始規格：關係／目標](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[Session 註解規格](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)
- **MI-DATA-005 — OptionSet 取顯示文字。** 性別、信仰狀態與會員身分透過目標 CRM metadata 解析 label，不硬編碼數值；「結案」值無法解析時必須 fail closed，不得把可能結案者納入。[明細性別生日規格](original-specs/2026-07-16-member-detail-gender-birthdate-design.md)｜[權威安全修正](authoritative-context/requirements.md)
- **MI-DATA-006 — Tree DTO 一律 PascalCase。** `Districts`、`Ungrouped`、`Scope`、`RaceLeaderKey`、`AreaName`、`RaceLeaderName`、`MemberCount`、`GroupCount`、`Groups`、`ListId`、`GroupName`、`LeaderName`、`GroupTime`、`GroupPlace` 及成員列欄位均以 PascalCase 輸出，前端也只讀 PascalCase；目標 serializer 必須用測試證明此契約。[權威資料契約](authoritative-context/requirements.md)｜[最新摘要規格：Descriptor 與 ViewModel](original-specs/2026-07-17-member-info-column-order-group-metadata-design.md)
- **MI-DATA-007 — 明確保留小寫例外。** DevExtreme remote-load envelope 保留 `data`／`totalCount`；既有頭像與 LINE 匿名 JSON 契約保留 `success`、`images`、`sources`、`ids` 等小寫欄位。不可用全域大小寫轉換破壞這些相容端點。[權威資料契約](authoritative-context/requirements.md)
- **MI-DATA-008 — Birthday 正規化一次完成。** 後端將空值或 CRM `Year <= 1` 哨兵日期正規化為 nullable `null`，列表與搜尋共用同一列 builder；有效日期不做時區轉換，畫面格式固定為 `yyyy/MM/dd`。[明細性別生日規格](original-specs/2026-07-16-member-detail-gender-birthdate-design.md)｜[Session 註解規格](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)
- **MI-DATA-009 — 搜尋列與瀏覽列同契約。** 搜尋回應直接承載授權後的完整成員列，欄位名稱、OptionSet label、生日正規化、關係目標與頭像補載方式都和小組／無小組表格一致。[版面搜尋規格](original-specs/2026-07-16-member-info-layout-search-design.md)
- **MI-DATA-010 — 核心 CRM logical names 是 hard stop。** `contact`／`list`／`listmember` 或核心樹與成員列所需 custom fields 無法在目標環境被證明時，阻擋核心 tree／member／search／detail read API。`connection`、photo 與 LINE schema 缺口分別只阻擋 relationship enrichment、主要照片／上傳、LINE 圖片 fallback／重新同步 capability；禁止 invent 欄位、以中文 label 當 logical name、用常數假裝 lookup，或為通過畫面測試塞入假資料。[權威需求](authoritative-context/requirements.md)
- **MI-DATA-011 — 會員身份排序 DTO 不暴露 raw value。** 成員列保留顯示用 `MembershipStatus`，另以 `MembershipStatusOrder: int?` 表示 metadata rank，並以 `HasMembershipStatusValue: bool` 區分 metadata 未知舊值與真正空白。`MembershipStatusOrder` 不是 `customertypecode` raw integer；不得新增可見 raw value 欄位，也不得用 `MembershipStatus` 中文文字排序。[會員身份 metadata 順序規格](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)

## MI-TREE：區長→小組→會友樹與排序

- **MI-TREE-001 — 三層資訊架構。** 畫面呈現區長節點 → 小組節點 → 成員 DataGrid，省略 CRM 組織中的區牧層；區節點以區長為分群鍵，同牧區不同區長仍是不同節點。[樹狀原始規格：名詞與結構](original-specs/2026-07-15-member-info-district-group-tree-design.md)
- **MI-TREE-002 — 骨架不含個資與照片。** 初次只載入區／小組名稱、領袖與去重人數；成員列在展開小組後才請求，頭像再於列渲染後批次補載。[樹狀原始規格：延遲載入](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威效能修正](authoritative-context/requirements.md)
- **MI-TREE-003 — 成員表最終欄位。** 小組、無小組與搜尋結果共用完全相同的九欄順序：`ContactId`（頭像）、`FullName`（姓名）、`Phone`（行動電話）、`BirthDate`（生日）、`Address`（地址）、`SpiritualIdentity`（信仰狀態）、`MembershipStatus`（會員身份）、`RelationGoals`（關係目標）、`Gender`（性別）。`Phone` caption 固定為「行動電話」且置中；`Gender` 固定最後。「關係目標」是單一顯示欄，不依關係筆數動態拆欄。這是整合後契約，取代早期原始規格的舊順序及「關係／目標兩欄」描述。[最新欄位順序規格](original-specs/2026-07-17-member-info-column-order-group-metadata-design.md)
- **MI-TREE-004 — 人數一致。** 小組人數為該組在籍、非結案 contact 去重數；區人數為所屬小組 contact 跨組去重數；展開後的授權結果與標題人數如因個別授權不同，必須可診斷，不得偽造相同數字。[樹狀原始規格：人數](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威需求](authoritative-context/requirements.md)
- **MI-TREE-005 — 預設展開。** 有小組的區預設展開以露出小組標題；成員 DataGrid 預設收合。整個可見範圍只有一個小組時自動展開該組，且不受 Ungrouped 是否存在影響。[樹狀原始規格：預設展開](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威修正](authoritative-context/requirements.md)
- **MI-TREE-006 — 整列可操作。** 區列與小組列整列可點／鍵盤操作，保留大型展開箭頭並同步 `aria-expanded`；CRM 文字以文字節點／`textContent` 輸出，不插入未編碼 HTML。[樹狀原始規格：互動](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威需求](authoritative-context/requirements.md)
- **MI-TREE-007 — 無小組節點。** Church 一律有 `Ungrouped` 物件（可為 0 人），與區節點同層、預設收合，展開直接顯示伺服器端分頁成員；Shepherd 的 `Ungrouped` 必須為 `null` 且不得出現在畫面。[樹狀原始規格：無小組](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威資料契約](authoritative-context/requirements.md)
- **MI-TREE-008 — 無小組先在 CRM 分頁。** 在 CRM 端依序套用在籍、排除結案、搜尋、排除 grouped IDs、穩定排序與 PageInfo，只對當頁執行授權、關係查詢與 DTO 組裝；禁止先取回全部再用記憶體或 `DataSourceLoader` 分頁。[權威效能修正](authoritative-context/requirements.md)
- **MI-TREE-009 — 小組分頁。** 每頁最多 50 個小組，跨頁可重複區標題；Ungrouped 只在最後一頁或沒有任何小組時出現。[樹狀原始規格：分頁](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威需求](authoritative-context/requirements.md)
- **MI-TREE-010 — 最終排序。** `Districts` 先列所有已填區長，再列顯示為「區長未填」者；同類內維持牧區名稱、區長名稱、區長鍵值的穩定排序。Ungrouped 是獨立欄位並由前端最後附加，所以總順序是「已填區長 → 區長未填 → 無小組」。[未填區長排序規格](original-specs/2026-07-16-sort-unassigned-district-last-design.md)
- **MI-TREE-011 — 最終標題版面。** 牧區名稱為選填；空字串或既有「(未填牧區)」哨兵值不渲染。區長姓名後先顯示「N 組」，再顯示「本區 N 人」；`GroupCount` 是該區未受前端小組分頁裁切的完整實際 `Groups` 數量，獨立 `Ungrouped` 不計入。小組名稱、小組長與「N 人」永遠顯示；trim 後非空的 `GroupTime`／`GroupPlace` 各自獨立顯示，兩者皆空時整列及兩個標籤都不存在。數量與 metadata 可自然換行，不使用固定高度裁切。[版面搜尋規格：組織版面](original-specs/2026-07-16-member-info-layout-search-design.md)｜[最新區／小組摘要規格](original-specs/2026-07-17-member-info-column-order-group-metadata-design.md)
- **MI-TREE-012 — 工具列最終狀態。** 保留搜尋；僅 Church 顯示重新同步 LINE；不恢復舊「顯示照片／顯示全部」切換，因照片已按展開節點延遲載入。[樹狀原始規格：工具列](original-specs/2026-07-15-member-info-district-group-tree-design.md)
- **MI-TREE-013 — 摘要 builder 契約。** `SmallGroupDescriptor`、`GroupNodeViewModel` 使用 `GroupTime`／`GroupPlace`，`DistrictNodeViewModel` 使用 `GroupCount`；builder 先 trim metadata，再以完整群組集合設定 `GroupCount`，前端分頁複製 district 時必須保留該值、只裁切 `Groups`。不得以 `district.Groups.length` 代替完整計數，也不得新增 N+1 query。[最新摘要規格：後端與前端資料流](original-specs/2026-07-17-member-info-column-order-group-metadata-design.md)

## MI-COLUMN：固定身分欄、欄寬調整與表頭排序

- **MI-COLUMN-001 — 三種 DataGrid 共用契約。** 一般小組、Ungrouped 與搜尋結果都經同一個 `miMemberColumns(remotePaging)` 欄位 factory；一般小組與搜尋為 local rows，Ungrouped 使用既有 remote datasource／remote paging。三種 grid 必須依序使用 `ContactId`、`FullName`、`Phone`、`BirthDate`、`Address`、`SpiritualIdentity`、`MembershipStatus`、`RelationGoals`、`Gender`，固定欄、調寬與排序規則不得分叉。[固定身分欄規格](original-specs/2026-07-17-member-info-fixed-identity-columns-design.md)｜[最新欄位順序規格](original-specs/2026-07-17-member-info-column-order-group-metadata-design.md)
- **MI-COLUMN-002 — 姓名固定且縮窄。** `FullName` 必須維持 `fixed: true`、`fixedPosition: 'left'`，預設 `width: 62`，且應用程式不得設定 `minWidth`；使用者可由 DevExtreme 原生欄寬引擎調整本次 DataGrid instance 的姓名寬度。此規則明確取代較早 resizable/sortable 原始規格中的 96px 與 `minWidth: 80`，但不取代其 widget resize、single sort 與手勢契約。[最新欄位順序規格：頭像與姓名](original-specs/2026-07-17-member-info-column-order-group-metadata-design.md)
- **MI-COLUMN-003 — 頭像固定且鎖定。** `ContactId` 必須維持 `width: 72`、`fixed: true`、`fixedPosition: 'left'`，並明確設定 `allowResizing: false`、`allowSorting: false`；頭像欄不能顯示可調寬或可排序的假操作。[欄寬與排序規格：頭像欄](original-specs/2026-07-17-member-info-resizable-sortable-columns-design.md)
- **MI-COLUMN-004 — 其餘欄使用 DevExtreme 原生 widget resize。** 除 `ContactId` 外，`FullName`、`Phone`、`BirthDate`、`Address`、`SpiritualIdentity`、`MembershipStatus`、`RelationGoals`、`Gender` 可從表頭分隔線調寬。每個 grid mount 都設定 `allowColumnResizing: true`、`columnResizingMode: 'widget'`、`columnAutoWidth: false`；不得使用 `nextColumn` 或自訂 header drag handler。`widget` 只改目前欄與 grid 內容寬度，不壓縮下一欄。[欄寬與排序規格：欄寬調整](original-specs/2026-07-17-member-info-resizable-sortable-columns-design.md)｜[最新欄位順序規格](original-specs/2026-07-17-member-info-column-order-group-metadata-design.md)
- **MI-COLUMN-005 — 表頭使用原生單欄排序。** 三種 grid 均設定 `sorting: { mode: 'single' }`；輕點資料欄表頭在升冪／降冪間切換，點另一欄時只保留新欄排序。`FullName`、`Phone`、`BirthDate`、`Address`、`SpiritualIdentity`、`MembershipStatus`、`Gender` 都可排序；`RelationGoals` 依 MI-COLUMN-006；點姓名表頭只排序，點資料列姓名才開啟明細。[欄寬與排序規格：表頭排序](original-specs/2026-07-17-member-info-resizable-sortable-columns-design.md)
- **MI-COLUMN-006 — 關係目標依 datasource 限制排序。** `RelationGoals` 在一般小組與搜尋的 local rows 可排序；Ungrouped remote grid 必須維持 `allowSorting: !remotePaging`，不得把不存在的 CRM 計算欄送進 remote sorting。[欄寬與排序規格：關係目標](original-specs/2026-07-17-member-info-resizable-sortable-columns-design.md)
- **MI-COLUMN-007 — resize、sort 與姓名點擊不可誤觸。** 滑鼠或手指拖曳表頭分隔線只調寬且不得觸發排序；輕點表頭才排序；資料列姓名點擊才開明細。fixed-columns touch bridge 的 selector 只處理 rows view，不得綁定或攔截 headers；既有 6px 判向、垂直手勢與防誤點行為保持不變。[固定身分欄規格：手勢](original-specs/2026-07-17-member-info-fixed-identity-columns-design.md)｜[欄寬與排序規格：手機互動](original-specs/2026-07-17-member-info-resizable-sortable-columns-design.md)
- **MI-COLUMN-008 — 欄寬與排序狀態皆不保存。** 手動欄寬及目前排序欄／方向只屬當下 DataGrid instance；本 scope 不啟用 DevExtreme `stateStoring`，也不得以 `localStorage`、`sessionStorage`、server preference／mapping 或其他機制跨 grid、跨頁、跨裝置同步。grid rebuild、remount 或 page reload 後，欄寬回到宣告的核准預設值（`ContactId` 72px、`FullName` 62px 且無應用程式 `minWidth`，其餘依欄位 factory），排序則清除先前欄／方向並回到 datasource 的核准初始順序；本次不建立任何欄寬或排序 state storage。[欄寬與排序規格：保存邊界](original-specs/2026-07-17-member-info-resizable-sortable-columns-design.md)｜[最新欄位順序規格](original-specs/2026-07-17-member-info-column-order-group-metadata-design.md)
- **MI-COLUMN-009 — 保留單一捲動與欄位順序。** `allowColumnReordering` 維持關閉，`columnHidingEnabled: false` 且不得有 adaptive dots；Grid host 不建立第二條水平捲軸。頭像與姓名始終固定在左側，右側欄位仍由唯一 DevExtreme scrollable 瀏覽。[固定身分欄規格](original-specs/2026-07-17-member-info-fixed-identity-columns-design.md)｜[欄寬與排序規格：禁止捷徑](original-specs/2026-07-17-member-info-resizable-sortable-columns-design.md)
- **MI-COLUMN-010 — pointer／touch 必須實機驗證。** DevExtreme client 22.1.6 是 Sunny 的實際前端資產版本；目標版本不同時須先驗證 fixed columns、header resize／sort 與 remote datasource 相容性。桌機與 320／390／430／640px 真機須分別驗證滑鼠／單指拖曳、升冪／降冪、垂直手勢、單一捲軸及三種 grid；不能用靜態契約測試取代實機證據。[欄寬與排序規格：人工驗收](original-specs/2026-07-17-member-info-resizable-sortable-columns-design.md)

## MI-ORDER：會員身份的 Dynamics 客製化順序

- **MI-ORDER-001 — 唯一權威是 metadata 集合位置。** `contact.customertypecode` 的排序必須由 `RetrieveAttributeRequest` 取得 `PicklistAttributeMetadata.OptionSet.Options`，依集合原始先後建立從 0 開始的 rank。`OptionMetadata.Value` 只用來識別資料，不能以整數大小推定順序；中文 label 與 Sunny 專屬清單也不是排序來源。[會員身份 metadata 順序規格](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)
- **MI-ORDER-002 — 不硬編碼其他教會設定。** 目標 AI 必須向目標 Dataverse 讀取已發佈 metadata；不同教會、solution 版本或語系可有不同 options 與順序。禁止複製 Sunny 的 value、label 或畫面順序作為 fallback。[會員身份 metadata 順序規格：跨環境適配](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)
- **MI-ORDER-003 — metadata provider 使用共用有限期快取。** provider 只快取 schema metadata，不含會友或使用者資料；成功可採有限期限快取，失敗只採短期空結果，避免每列／每頁重打 metadata API。失敗時不得改用 raw integer 冒充順序。[會員身份 metadata 順序規格：provider](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)
- **MI-ORDER-004 — 固定分類為 Configured、Unknown、Empty。** 已在 metadata 中設定的值依 rank 排列；有 raw value 但 metadata 找不到者保留為 Unknown；真正 null 為 Empty。正向與反向都必須維持 Configured → Unknown → Empty，只有 Configured ranks 反轉。[會員身份 metadata 順序規格：共用排序](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)
- **MI-ORDER-005 — 同類型結果穩定。** 同一 rank、Unknown 或 Empty 內依 `FullName` Ordinal，再依 `ContactId` OrdinalIgnoreCase 遞增，避免搜尋去重、重新整理與跨頁時順序漂移。[會員身份 metadata 順序規格：穩定排序](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)
- **MI-ORDER-006 — 一般小組與搜尋在授權後排序。** Controller 完成在籍條件、批次 contact 授權、關係目標與 DTO mapping 後才套用共用 rank sorter；搜尋先依 allowed IDs 過濾及 ContactId 去重，再套相同排序。未授權列不得參與排序或回應。[會員身份 metadata 順序規格：local grids](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)
- **MI-ORDER-007 — Ungrouped 在 CRM 分段後遠端分頁。** 先保留既有在籍、搜尋、排除 grouped IDs 條件，透過 SDK 產生的 FetchXML aggregate 計算各非空 value 筆數，另計 null；依 metadata 建 segments，再把全域 `skip/take` 切成必要 slices。每段只查當頁範圍，段內依 fullname／contactid；禁止先取一頁再排序或載入全教會到記憶體。[會員身份 metadata 順序規格：遠端分頁](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)
- **MI-ORDER-008 — 可見欄位仍是會員身份中文 label。** DataGrid 的 visible `dataField` 保持 `MembershipStatus`；local grid 以方向感知 sort-value 函式讀 `MembershipStatusOrder`／`HasMembershipStatusValue`，remote grid 只送 `MembershipStatusOrder` selector。預設為 metadata 升冪，反覆點擊表頭切換方向；九個可見欄位不得增加 rank 或 raw value。[會員身份 metadata 順序規格：DataGrid](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)
- **MI-ORDER-009 — 必須驗證真實客製化順序與跨頁。** 測試至少包含「raw value 較大但 metadata rank=0」的案例、Unknown／Empty 正反向置底、metadata failure、重複 value／負 count／跨 segment slice，以及一般小組、搜尋、Ungrouped 25／50／100 分頁的真實 Network 與畫面證據。[會員身份 metadata 順序規格：驗收](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)

## MI-AVATAR：主要照片、LINE、剪影、批次載入、上傳與快取

- **MI-AVATAR-001 — 必要 prerequisite（來源早於 2026-07-15）。** 本節的 ContactAvatar、照片 API、LINE 圖與性別剪影基礎能力不是十一份 Specs 新設計；它們是完成各自 avatar source／upload capability 的前置依賴。十一份 Specs 只定義樹狀／搜尋如何重用已確認的能力及其後續 UI 演進，不得把 prerequisite 偽稱為十一份 Specs 的產物；目標版若先以安全剪影核准降級，核心樹可先提供 read，但未提供的 avatar capability 仍不得標為完成。[權威需求：頭像前置能力](authoritative-context/requirements.md)
- **MI-AVATAR-002 — 來源優先序。** 每位 contact 依序使用 CRM 主要照片（Sunny 為 `entityimage`／`entityimageid`）、經 `http`／`https` 驗證的 LINE 照片 URL、依 `gendercode` 選擇的男／女／中性 SVG 剪影；任一來源失敗都不得洩漏未授權照片或改抓任意 URL。[樹狀原始規格：頭像語意](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威 prerequisite](authoritative-context/requirements.md)
- **MI-AVATAR-003 — 列 DTO 不含圖片 bytes。** 小組、無小組與搜尋列先回輕量資料；畫面渲染可見列後，將去重 contact IDs 送到批次端點。禁止在骨架或每一列 JSON 夾帶原始影像，也禁止每列一個授權／CRM 查詢。[樹狀原始規格：延遲頭像](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威需求](authoritative-context/requirements.md)
- **MI-AVATAR-004 — 批次端點先授權再查圖。** 對合法 GUID 去重，先做 MI-AUTH-005 的批次 contact 授權，再以分塊 CRM 查詢取得未命中快取者；回應維持小寫 `success`、`images`、`sources`，來源值能區分 `primary`、`line`、`fallback`。[權威資料契約](authoritative-context/requirements.md)
- **MI-AVATAR-005 — 縮圖與 response cache。** 主要照片依請求尺寸產生縮圖，伺服器 `IMemoryCache` 以 contact、模式與尺寸分鍵；含個人照片的批次 JSON 使用 private／no-store，單張 redirect／檔案也不得變成跨使用者公用快取。[權威 prerequisite 與安全要求](authoritative-context/requirements.md)
- **MI-AVATAR-006 — 上傳驗證與正規化。** 目標版本確認寫入授權及 storage 後，接受既定圖片格式與大小上限（Sunny：JPG／JPEG／PNG／GIF，5 MB），用 ImageSharp 自動套用 EXIF orientation、置中補邊為正方形並轉 JPEG；檔名、副檔名與 Content-Type 檢查不可取代實際解碼驗證，目標安全政策較嚴時從嚴適配。[權威 prerequisite](authoritative-context/requirements.md)
- **MI-AVATAR-007 — 上傳後快取失效。** 成功寫入主要照片後，清除該 contact 的全尺寸、thumb、fit 與其他共用頁面所使用的相關 cache keys，回傳新版本值並立即更新明細與樹內縮圖；不得等待舊圖自然過期。[樹狀原始規格：上傳後同步](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威 prerequisite](authoritative-context/requirements.md)
- **MI-AVATAR-008 — LINE 重新同步。** Church 可先取得「在籍且有 LINE user ID」的候選 IDs，再分批驗證現有圖片 URL、查 LINE Profile 並 set-or-clear 圖片／顯示資料；LINE 403／404、逾時與無照片要分辨，暫時無法判定時不得誤清仍可能有效的資料。[樹狀原始規格：重新同步 LINE](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威 prerequisite](authoritative-context/requirements.md)
- **MI-AVATAR-009 — LINE schema／credentials contract 是 capability hard stop。** 必須先確認 LINE user／profile 欄位、目標組織如何選擇 Channel Access Token、secret provider／設定層級與輪替責任。可以保留設定 key 的「名稱」，不得把 token 值寫入 source、文件、patch、log 或測試；任一契約不明時只停用 LINE 圖片 fallback／重新同步並回報，不得阻擋核心樹或已確認的 primary／安全剪影 fallback，也不得硬編碼或借用其他教會 token。[權威安全要求](authoritative-context/requirements.md)
- **MI-AVATAR-010 — 照片 storage 是 capability hard stop。** 必須確認主要照片實際位於 Dataverse `entityimage`、檔案欄、blob、外部服務或其他位置，以及其尺寸、內容類型與 read privilege；任一 read/storage 事實未知時阻擋 avatar primary-photo stage，不得假設 Sunny storage 或直接建立同名欄位。核心樹可在明確設計下先使用經授權且不取照片的安全剪影 fallback，但整體 avatar capability 仍須標為未完成或核准降級；write privilege／cache invalidation 未確認時只阻擋 upload，不得誤擋已確認安全的讀取能力。[權威需求：先比對照片儲存](authoritative-context/requirements.md)

## MI-DETAIL：明細、關係目標、性別與生日

- **MI-DETAIL-001 — 姓名開啟既有明細。** 樹與搜尋結果的姓名沿用同一明細入口，contactId 仍需伺服器授權；不得為新表格另做一套權限較弱的明細 API。[樹狀原始規格：姓名互動](original-specs/2026-07-15-member-info-district-group-tree-design.md)
- **MI-DETAIL-002 — 同一次 Retrieve 取得性別生日。** 在既有 contact detail 欄位集合加入 `gendercode` 與 `birthdate`，不新增額外基本資料 API 或前端從列表偷帶可能過期的值。[明細性別生日規格](original-specs/2026-07-16-member-detail-gender-birthdate-design.md)
- **MI-DETAIL-003 — 唯讀顯示。** `Gender` 是 metadata 解析後的文字，`BirthDate` 是正規化後的 nullable 日期；明細格式 `yyyy/MM/dd`，性別或生日缺值顯示「（未設定）」，不加入性別／生日編輯與上傳輸入。[明細性別生日規格](original-specs/2026-07-16-member-detail-gender-birthdate-design.md)
- **MI-DETAIL-004 — 欄位位置。** 性別／生日放在地址／會員身分之後、關係目標之前；桌機為同列左右欄，手機沿既有 media query 改單欄。[明細性別生日規格](original-specs/2026-07-16-member-detail-gender-birthdate-design.md)
- **MI-DETAIL-005 — 關係目標是單一摘要欄。** 多筆 `RelationGoals` 在一個跨欄欄位依穩定順序顯示「角色: 對象」，以頓號串接；已查詢且沒有資料時顯示「（無）」，不得依關係數量動態增減版面欄位。依 MI-DATA-004 核准 connection 降級時關係目標留白，並以診斷／驗收例外區分「能力不可用」與「確實沒有關係」。[Session 註解規格：關係目標](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)｜[樹狀原始規格：關係語意](original-specs/2026-07-15-member-info-district-group-tree-design.md)
- **MI-DETAIL-006 — 詳細 Loading 共用狀態元件。** 開啟明細期間顯示 MI-LOAD 的共用狀態卡，成功、失敗、重複開啟或關閉 popup 都必須結束 loading 生命週期。[Loading 原始規格](original-specs/2026-07-15-member-info-loading-animation-design.md)

## MI-SEARCH：搜尋、取消、結果取代、零筆與返回

- **MI-SEARCH-001 — 四態狀態機。** 前端搜尋只有 `idle`、`searching`、`results`、`error`；每次轉態由單一入口管理 overlay、按鈕、樹、pager、results grid 與錯誤區，禁止用互不相干的旗標拼湊狀態。[版面搜尋規格：搜尋狀態](original-specs/2026-07-16-member-info-layout-search-design.md)

- **MI-SEARCH-004 — 搜尋期間保留原 DOM。** 進入 `searching` 前保存樹的頁次、展開狀態、捲動位置與必要 UI state；以全頁遮罩禁止其他操作，但不銷毀或重載原樹。[版面搜尋規格：搜尋狀態](original-specs/2026-07-16-member-info-layout-search-design.md)
- **MI-SEARCH-005 — 停止搜尋是唯一可操作控制。** 搜尋按鈕升到遮罩之上並變成紅色「停止搜尋」；點擊時 abort 目前 AJAX、遞增 request token、移除遮罩並完整恢復搜尋前畫面，取消不顯示錯誤。[版面搜尋規格：全頁遮罩](original-specs/2026-07-16-member-info-layout-search-design.md)
- **MI-SEARCH-006 — 忽略過期回應。** 每次搜尋使用遞增 token；較晚到達的舊請求、已取消請求或已離開 `searching` 的 callback 不得覆蓋目前狀態。[版面搜尋規格：搜尋資料流](original-specs/2026-07-16-member-info-layout-search-design.md)
- **MI-SEARCH-007 — 結果直接取代瀏覽區。** 一筆、多筆及零筆都進入 `results`；results DataGrid 取代樹與樹 pager，使用同一成員欄位、日期格式、水平捲動、姓名明細與批次頭像。[版面搜尋規格：搜尋資料流](original-specs/2026-07-16-member-info-layout-search-design.md)
- **MI-SEARCH-008 — 零筆是成功狀態。** 顯示「沒有搜尋到符合的會友」並保留「返回會友資訊」，不得把零筆當例外、留下空白頁或永久 loading。[版面搜尋規格：錯誤與空狀態](original-specs/2026-07-16-member-info-layout-search-design.md)
- **MI-SEARCH-009 — 返回不重載樹。** 「返回會友資訊」與取消共用恢復流程：先還原 browse UI，再 dispose results DataGrid；原頁次、展開與捲動位置應保留。[版面搜尋規格：搜尋資料流](original-specs/2026-07-16-member-info-layout-search-design.md)｜[Session 註解規格：搜尋生命週期](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)
- **MI-SEARCH-010 — 錯誤需可理解。** 無權限顯示「無權搜尋此範圍」，其他失敗顯示「搜尋失敗，請稍後再試」並提供返回；詳細例外只進安全診斷證據，不把 CRM／token／個資輸出給瀏覽器。[版面搜尋規格：錯誤與空狀態](original-specs/2026-07-16-member-info-layout-search-design.md)

## MI-LOAD：Loading、錯誤、空狀態與 reduced-motion

- **MI-LOAD-001 — 共用友善 loading card。** 首次載入樹、展開小組載入名單與開啟明細三個入口使用同一概念的狀態卡：柔和漸層、三顆依序跳動圓點、主標與說明，不增加圖片或第三方動畫套件。[Loading 原始規格](original-specs/2026-07-15-member-info-loading-animation-design.md)

- **MI-LOAD-004 — reduced-motion。** `prefers-reduced-motion: reduce` 時停止跳動、漸層與非必要 transition，但保留文字、spinner 的靜態辨識與全部功能。[Loading 原始規格](original-specs/2026-07-15-member-info-loading-animation-design.md)｜[版面搜尋規格：遮罩](original-specs/2026-07-16-member-info-layout-search-design.md)
- **MI-LOAD-005 — 搜尋使用全頁 overlay。** 搜尋 overlay 覆蓋會友資訊頁可見範圍，含 spinner、友善文字與半透明背景；只有停止搜尋按鈕位於其上方，取消／成功／失敗都保證移除 overlay。[版面搜尋規格：全頁遮罩](original-specs/2026-07-16-member-info-layout-search-design.md)
- **MI-LOAD-006 — 空骨架。** 沒有可見小組時顯示可理解空狀態；Church 仍可顯示 0 人或有資料的 Ungrouped，Shepherd 不建立假的 Ungrouped。[樹狀原始規格：特殊情況](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[權威需求](authoritative-context/requirements.md)
- **MI-LOAD-007 — 空小組／空頁。** 展開後無授權可見成員、分頁超出範圍或資料在載入期間變更時，DataGrid 顯示空狀態並結束 loading，不以無限重試掩蓋。[權威需求：錯誤與範圍](authoritative-context/requirements.md)
- **MI-LOAD-008 — 錯誤不困住 UI。** 每個 AJAX 的 success、error、abort、timeout 與 dispose 例外路徑都必須清理 timer／overlay／loading container，保留可重試或返回的控制項。[Session 註解規格：前端生命週期](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)
- **MI-LOAD-009 — 權限錯誤不得降級成空資料。** 401／403 與資料為空必須可區分；前端不能把拒絕授權當成「沒有會友」，後端也不能為了顯示空狀態改回 200 全空。[版面搜尋規格：錯誤與空狀態](original-specs/2026-07-16-member-info-layout-search-design.md)｜[權威安全修正](authoritative-context/requirements.md)

## MI-MOBILE：單一捲軸、指頭滑動、字級與觸控

- **MI-MOBILE-001 — 完整欄位不隱藏。** 全教會、小組、Ungrouped 與搜尋 results DataGrid 一律 `columnHidingEnabled: false`，不設定 `hidingPriority`，不得重新出現 adaptive「…」欄。[版面搜尋規格：表格與手機手勢](original-specs/2026-07-16-member-info-layout-search-design.md)｜[手機字體規格：DataGrid](original-specs/2026-07-16-member-info-mobile-responsive-typography-design.md)
- **MI-MOBILE-002 — 唯一水平捲軸。** Grid host／外層不建立第二條水平 scrollbar；由 DevExtreme 內建 scrollable 承擔唯一水平捲動，內容維持可讀的最小寬度與固定欄寬。[版面搜尋規格：表格與手機手勢](original-specs/2026-07-16-member-info-layout-search-design.md)
- **MI-MOBILE-003 — 原生指頭滑動。** 行動版 scroll 設定保留 `useNative: true`、`scrollByContent: true` 及可見水平 scrollbar；不得加會攔截 `touchmove` 的自訂拖曳。瀏覽器依手勢方向在表格水平移動或頁面垂直移動。[版面搜尋規格：表格與手機手勢](original-specs/2026-07-16-member-info-layout-search-design.md)｜[手機字體規格：DataGrid](original-specs/2026-07-16-member-info-mobile-responsive-typography-design.md)
- **MI-MOBILE-004 — 行動規則限 640px 以下。** 桌機字級與版面不變；在 320–640 CSS px 內用 CSS `clamp()` 平滑調整，不用 JavaScript resize 重設欄位，也保留瀏覽器文字縮放。[手機字體規格：響應式策略](original-specs/2026-07-16-member-info-mobile-responsive-typography-design.md)
- **MI-MOBILE-005 — 可讀字級。** 320→640px 的目標範圍：區長 18→20px、小組 16→18px、徽章／按鈕 14→15px、DataGrid 表頭 16→17px、資料列 15→16px；行高依規格至少約 1.4–1.5。[手機字體規格：字級與行高](original-specs/2026-07-16-member-info-mobile-responsive-typography-design.md)
- **MI-MOBILE-006 — 觸控尺寸。** 搜尋、LINE 同步、返回等按鈕 `min-height: 48px`；區長列約 64–72px、小組列約 72–84px；箭頭有 44×44px 對齊區且整列可點，DataGrid 資料列垂直尺寸接近至少 48px。[手機字體規格：觸控與間距](original-specs/2026-07-16-member-info-mobile-responsive-typography-design.md)
- **MI-MOBILE-007 — 高度只設最小值。** 不用固定高度截斷長姓名、三位數徽章、地址或 200% 文字縮放；長地址與關係目標允許換行增高。[手機字體規格：觸控與 DataGrid](original-specs/2026-07-16-member-info-mobile-responsive-typography-design.md)
- **MI-MOBILE-008 — 工具列維持單列。** 搜尋框 `min-width: 0` 承擔縮減，搜尋與「重新同步LINE」按鈕不換行；320px 時縮小 padding／圖示間距，不把按鈕掉到下一列。[手機字體規格：工具列](original-specs/2026-07-16-member-info-mobile-responsive-typography-design.md)
- **MI-MOBILE-009 — iOS／LINE WebView 防聚焦縮放。** 搜尋 input 明確為至少 `16px`，不能因 Bootstrap 3 根字級 10px 而使用不安全的 `1rem`；在 iOS Safari 與 LINE WebView 都要實測。[手機字體規格：工具列窄螢幕保護](original-specs/2026-07-16-member-info-mobile-responsive-typography-design.md)

## MI-OBS：診斷、效能與錯誤證據

- **MI-OBS-001 — 階段化計時。** 樹骨架、搜尋、小組／Ungrouped 載入至少可分辨查詢、批次授權、關係查詢與 DTO 組裝耗時；照片批次至少可分辨授權／cache、取連線、CRM 傳輸、縮圖與總耗時。診斷只記 operation、phase、elapsed、筆數與 bytes 等非個資指標。[Session 註解規格：C# 業務邏輯](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)
- **MI-OBS-002 — 禁止敏感 log。** 不記姓名、電話、生日、照片內容、LINE user ID、token、連線字串或完整 CRM payload；例外回應對使用者只顯示可理解訊息，詳細類型留在受控 server log。[Session UTF-8／範圍規格](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)｜[權威安全需求](authoritative-context/requirements.md)
- **MI-OBS-003 — 批次上限可證明。** `IN`、授權、connection 與照片 IDs 依平台限制分塊，Dataverse 多頁查詢支援 PagingCookie；查詢次數應隨 chunk／page 數成長，不隨畫面列數逐列成長。[權威效能修正](authoritative-context/requirements.md)
- **MI-OBS-004 — Cache 證據。** 記錄 Church 骨架與 grouped snapshot 的 hit／miss／expiry 行為、Shepherd 與搜尋不進共用快取、更新後失效鍵；不得以 cache 命中掩蓋權限或資料新鮮度問題。[權威效能修正](authoritative-context/requirements.md)
- **MI-OBS-005 — 前端生命週期證據。** 瀏覽器 Network／console 或自動測試需證明：初載無頭像 storm、重複展開不產生失控請求、取消後舊 response 被忽略、返回不重載樹、loading 在所有路徑結束。[版面搜尋規格：測試](original-specs/2026-07-16-member-info-layout-search-design.md)｜[Loading 原始規格：驗證](original-specs/2026-07-15-member-info-loading-animation-design.md)
- **MI-OBS-006 — 狀態與 HTTP 語意。** 授權拒絕、schema／OptionSet 解析失敗、Dataverse 失敗、LINE 403／404／timeout、圖片驗證失敗、AJAX abort 與真正零筆要有可區分證據；不能全部轉成 200 空集合或同一「失敗」字串。[版面搜尋規格：錯誤狀態](original-specs/2026-07-16-member-info-layout-search-design.md)｜[權威安全修正](authoritative-context/requirements.md)
- **MI-OBS-007 — 不虛構效能門檻。** 未有目標環境基準時先記錄資料量、chunk 數、請求數與耗時，不自行宣稱固定毫秒門檻；優化前後以同環境、同資料範圍比較並保存原始輸出。[權威需求：證據導向驗收](authoritative-context/requirements.md)
- **MI-OBS-008 — 差異報告是交付物。** 所有與 Sunny 不同但已核准的 schema、claims、storage、LINE、framework 或 UI 適配都要記錄「差異、理由、影響、驗證」；尚未核准者保留為 blocker，不得以成功畫面取代決策證據。[權威需求](authoritative-context/requirements.md)

## MI-ENC：註解、UTF-8 與測試

- **MI-ENC-001 — 註解解釋 why。** Controller／service 註解要說明 query→batch authorization→assemble 的順序、Year=1 正規化、未填區長顯示與排序差異、搜尋去重與 token、防共用快取外洩等非顯而易見原因，不逐行翻譯語法。[Session 註解規格：C#](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)
- **MI-ENC-002 — Razor／JS 註解標責任與生命週期。** 說明工具列、樹、DataGrid、搜尋狀態機、loading、單一捲軸、iOS 16px、先恢復 UI 再 dispose grid，以及 abort／timeout 清理順序。[Session 註解規格：Razor、CSS、JavaScript](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)
- **MI-ENC-003 — 嚴格 UTF-8。** 所有新增／修改文字檔以會對 invalid bytes 拋例外的 UTF-8 decoder 驗證，U+FFFD 數量必須為 0；既有 UTF-8 BOM 可保留，不做無關的全檔換行或 BOM 正規化。[Session 編碼規格](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)
- **MI-ENC-004 — 主控台亂碼不是判定。** PowerShell 字型／code page 顯示異常不能直接當檔案損壞或成功；以原始 bytes 嚴格解碼、U+FFFD 掃描、`rg`、編譯與瀏覽器顯示共同判定。[Session 編碼規格](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)
- **MI-ENC-005 — xUnit 行為與契約測試。** 純邏輯測試涵蓋 access resolver／scope guard、區樹與未填排序、搜尋授權／去重／零筆多筆、關係格式、生日正規化與 avatar fallback；靜態契約測試涵蓋 Controller 欄位、PascalCase、Razor 狀態、mobile CSS、捲軸與 reduced-motion。[未填排序規格：測試](original-specs/2026-07-16-sort-unassigned-district-last-design.md)｜[版面搜尋規格：測試](original-specs/2026-07-16-member-info-layout-search-design.md)｜[Loading 原始規格：驗證](original-specs/2026-07-15-member-info-loading-animation-design.md)
- **MI-ENC-006 — 高風險負向測試。** 至少驗證越權／未知 list、非 Church Ungrouped、越權 contact／照片、畸形 GUID、找不到結案值、LINE 未設定／403／404／timeout、不合法圖片、取消搜尋與舊回應；負向測試不得只斷言「沒有 exception」。[權威安全需求](authoritative-context/requirements.md)
- **MI-ENC-007 — 完整驗證層。** 執行目標版等價的 MemberInfo tests、solution Debug build、Razor JavaScript 語法檢查、`git diff --check`，並在桌機、320、390／430、640px、iOS／LINE WebView 與 reduced-motion 實測。[手機字體規格：測試與驗收](original-specs/2026-07-16-member-info-mobile-responsive-typography-design.md)｜[Session 驗證規格](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)
- **MI-ENC-008 — 不得假稱通過。** 任何未能執行的測試、無法取得的外部服務、瀏覽器、裝置或被 hard stop／降級停用的 capability，都必須在驗收標為未驗證、未完成或已核准降級並記錄影響；不能以 code review、編譯、模擬截圖或核心樹可用來宣稱整套功能完整通過。[Session 驗證規格](original-specs/2026-07-16-member-info-session-comments-utf8-design.md)

## 非目標與禁止捷徑

- **MI-GUARD-001 — 不直接覆蓋宿主檔。** 不把 Sunny 的整份 Controller、Startup、csproj、layout 或設定檔蓋到目標專案；只能依差異逐點整合，保留目標教會既有授權、CRM、DI、錯誤處理與設定來源。[權威需求](authoritative-context/requirements.md)
- **MI-GUARD-002 — 不發明相依。** 禁止 invent CRM fields、hardcode secrets、把其他組織 token 當 fallback、建立 allow-all、把 Shepherd 升為 Church，或用前端隱藏取代後端授權。[權威需求](authoritative-context/requirements.md)
- **MI-GUARD-003 — 不用 N+1 換進度。** 禁止逐列 CRM 授權、逐列 connection、初載逐列照片、逐列 OptionSet metadata，或為每個小組另查時間／地點；`new_group_time`、`new_group_place` 必須加入既有 `FetchSmallGroupDescriptors` list query。如果目標 SDK 不支援 Sunny 寫法，應設計等價批次／分頁方案並先核准。[權威安全與效能修正](authoritative-context/requirements.md)｜[最新摘要規格](original-specs/2026-07-17-member-info-column-order-group-metadata-design.md)
- **MI-GUARD-004 — 不回復已淘汰互動。** 不恢復平面舊 grid、照片篩選切換、搜尋命中後自動展開多個小組、adaptive 三點欄、欄位 reordering、`nextColumn` resize、自訂 header drag、會攔截 headers 的 touchmove 或雙水平捲軸。[版面搜尋規格](original-specs/2026-07-16-member-info-layout-search-design.md)｜[樹狀原始規格](original-specs/2026-07-15-member-info-district-group-tree-design.md)｜[欄寬與排序規格](original-specs/2026-07-17-member-info-resizable-sortable-columns-design.md)
- **MI-GUARD-005 — 不擴張明細需求。** 本套件不新增性別／生日編輯、不新增另一支 detail API、不改無關頁面或桌機字級，也不把關係目標改成動態欄位。[明細性別生日規格：邊界](original-specs/2026-07-16-member-detail-gender-birthdate-design.md)｜[手機字體規格：範圍外](original-specs/2026-07-16-member-info-mobile-responsive-typography-design.md)
- **MI-GUARD-006 — Capability-scoped hard stops。** 核心 `contact`／`list`／`listmember` schema 或成員 read authorization 未確認時，阻擋核心 tree／member／search／detail read API；contact write policy 未確認時只阻擋 upload／update；photo read/storage 未確認時阻擋 avatar primary-photo stage，核心樹僅可依明確設計使用安全剪影 fallback 且 avatar capability 仍標未完成或核准降級；photo write 未確認時只阻擋 upload；LINE schema／token／provider 未確認時只阻擋 LINE 圖片 fallback／重新同步；`connection` schema／read privilege 未確認時只阻擋 relationship enrichment／MI-DETAIL 關係 stage 並要求決策。每項均須輸出缺口、受阻能力與選項；不得用假資料、寬鬆 fallback 或部分功能成功假稱全功能完成。[權威需求](authoritative-context/requirements.md)
- **MI-GUARD-007 — 不攜帶環境與個資。** 不複製 `appsettings*.json`、secret、connection string、publish profile、bin／obj、runtime log、真實姓名／電話／生日／照片／LINE ID、絕對路徑或機器操作指令。[權威需求](authoritative-context/requirements.md)
- **MI-GUARD-008 — 不把識別值當順序。** 禁止用 `customertypecode` raw integer、FetchXML `useraworderby`、中文 label 字典序或 Sunny 硬編碼清單實作 MI-ORDER；metadata 暫時不可用時只能保留 Unknown／Empty 的安全穩定行為並留下診斷。[會員身份 metadata 順序規格](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)
