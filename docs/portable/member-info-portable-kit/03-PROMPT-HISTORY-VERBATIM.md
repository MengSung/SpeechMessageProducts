# 會友資訊提示詞歷程（Session 可見原文，已做安全遮罩）

## 收錄範圍與閱讀方式

本文件只把目前 session context 中可見的使用者訊息稱為「逐字」內容，不代表平台完整匯出的 transcript。每一項的序號（ordinal）沿用原始出現順序；「分類」與章節位置是整理者為了遷移用途加上的中介資料，不屬於使用者原文。

同一 session 中完全相同且已收錄的使用者訊息通常不重複抄錄；但若相同短答分別核准連續的不同設計／規格／計畫閘門，仍依原始出現順序逐則保留，不合併成單一決策。序號沿用原始出現順序，因此去重後可能跳號。

為避免把會友個資或目前電腦的環境值帶到其他教會，本文件只對姓名／小組／牧區範例、本機絕對路徑、固定連接埠與程序 PID 做安全遮罩；其餘可見文字、錯字、標點與換行不做語意改寫。最新 cycle 的真實姓名以 `[PERSON_REDACTED]` 取代，疑似由姓名衍生的小組名稱改為泛化 fixture。遮罩後的泛化 fixture 與 token 見 [隱私遮罩說明](07-PRIVACY-REDACTIONS.md)。因此本文的「逐字」應理解為「除明確安全遮罩外的 session 可見原文」。

原始圖片不在這份文字套件中。凡訊息包含 `[Image #1]`、`[Image #2]` 或 `[Image #3]`，只保留 marker 與使用者隨附文字；本文件不推測、補述或聲稱看見圖片內容。短答如「要」、「A」、「同意」只證明當時有一個決策回覆；若前一個選項題未出現在可見 context，不能單靠短答重建未顯示的選項內容。

功能、錯誤、視覺與互動需求收在主要歷程。Branch、worktree、merge、連接埠重啟、Visual Studio、DLL lock、hook status 與 Commit 偏好收在「環境操作歷程（不可直接複製）」；這些資訊只能解釋當時發生過什麼，不能當成另一個教會版本的操作命令。

## 遷移時如何使用這份歷程

- 把主要歷程當成需求演進與驗收案例來源；最終實作以套件的整合規格與已核准設計為準。
- 若早期訊息與後期修正衝突，保留歷史但採後期明確修正。例如會友表格必須是單一「關係目標」欄，不能回到早期拆成「關係」與「目標」兩欄；會員身份也必須依目標 Dynamics 的系統客製化 metadata 集合順序，不能依 raw `customertypecode` 整數值。
- `[Image #]` 只代表當時有圖片，不能當成視覺規格。請使用文字需求、整合規格與目標 repo 的實際畫面重新驗證。
- 環境操作歷程只提供風險提示。遷移時應先建立目標 repo 自己的分支或 worktree、保存現況並重新取得環境證據，再由使用者決定 Commit 與合併。
