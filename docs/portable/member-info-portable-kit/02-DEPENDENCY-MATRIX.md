# 會友資訊依賴矩陣

本矩陣用於實作前盤點及實作後驗證。`Sunny 來源` 只說明參考快照在哪裡，**不是**要求複製相同版本、logical name 或設定；目標 AI 應逐列填入差異報告，並以最後一欄所列證據證明適配完成。行為定義見 [會友資訊整合規格](01-INTEGRATED-SPEC.md)；最新來源是[第 11 份 Spec](original-specs/2026-07-18-member-info-commitment-type-sorting-design.md)與[第 11 份 Plan](original-plans/2026-07-18-member-info-commitment-type-sorting.md)，其[增量 patch06](reference-implementation/host-integration/06-member-info-commitment-type-metadata-order.patch)只可作 **EVIDENCE-ONLY**。

## 實作前 hard-stop gate

- **STOP-CRM：** 無法用 metadata／既有查詢／schema 文件確認核心 `contact`／`list`／`listmember`、必要 custom fields、lookup 方向及 OptionSet 語意時，阻擋核心 tree／member／search／detail read API。禁止 invent fields、以中文 label 當 logical name 或建立假資料繞過；`connection`、photo、LINE schema 依下列 capability gate 處理，不得擴張為核心 read blocker。
- **STOP-OPTION-ORDER：** 無法確認目標 SDK 可讀取 `contact.customertypecode` 的 `PicklistAttributeMetadata.OptionSet.Options` 客製化集合順序時，只阻擋 MI-ORDER 的「依系統客製化順位排序」完成宣告；核心 read 可保留穩定 Unknown／Empty 顯示，但禁止以 raw integer、label 字典序、`useraworderby` 或 Sunny 清單冒充正確順序。
- **STOP-AUTH：** 無法確認 Church／Shepherd 的 authoritative claims、清單歸屬與 contact read policy 時，阻擋核心 tree／member／search／detail read API；contact write policy 未確認時只阻擋 upload／update。禁止放寬權限，包括 allow-all、角色升級、只靠前端隱藏或逐列 CRM 授權。
- **STOP-PHOTO：** 無法確認主要照片 read/storage 契約時，阻擋 avatar primary-photo stage；核心樹可依明確設計使用不取照片的安全剪影 fallback，但 avatar capability 仍須標為未完成或核准降級。Photo write privilege／cache invalidation 未確認時只阻擋 upload；禁止自行建立 `entityimage` 同名欄位或把照片寫到未核准位置。
- **STOP-LINE：** 無法確認 LINE user／profile schema、組織→Channel Access Token 的 secret-provider contract 或輪替責任時，只阻擋 LINE 圖片 fallback／重新同步；不得阻擋核心樹或已確認的 primary／安全剪影 fallback。禁止硬編碼、記錄、封裝或借用其他教會 credentials。
- **STOP-CONNECTION：** `connection` schema／read privilege 狀態未知時，只停止 relationship enrichment／MI-DETAIL 關係目標 stage 並要求決策，不停止核心樹或成員列。已確認不支援或無 read privilege 時，可依核准降級保留成員列、關係目標留白並記診斷／驗收例外；若目標要求關係目標必備，須補齊 schema／privilege 才完成該 capability。
- **STOP-DX-VERSION：** 無法確認瀏覽器實際載入的 DevExtreme client 版本，或目標版本與 Sunny 22.1.6 不同且尚未證明 DataGrid fixed columns、原生 header resize／sort、remote datasource 與 pointer／touch 行為相容時，阻擋 MI-COLUMN 與其真機驗收；不得只看 server NuGet、直接照貼 Sunny options、改用 `nextColumn`／自訂 header drag／第二捲軸或以桌機滑鼠結果代替手機證據。
- 任一 STOP 觸發時，只輸出「已確認事實、缺少證據、受阻 MI IDs、可選適配方案、風險」，等待使用者決定；不可先寫寬鬆版本再補安全。任何未提供的 capability 都必須在驗收標為未完成或已核准降級，不得以核心功能可用假稱全功能完成。

## 建議適配順序

1. 先完成 DEP-RUNTIME、DEP-DX-SERVER、DEP-DX-CLIENT、DEP-JSON、DEP-DATAVERSE 的只讀 inventory；若 client 版本不是已知的 Sunny 22.1.6，先處理 STOP-DX-VERSION，不得直接假設 fixed columns／header resize／sort 相容。
2. 再完成核心 STOP-CRM 與 STOP-AUTH 的 read 證據，建立核心 CRM mapping 與角色／範圍表；未通過不得開 tree／member／search／detail read API。Contact write、connection、photo、LINE gate 另按 capability 驗證，不延誤已通過 gate 的核心 read。
3. 先實作 scope guard、批次授權、DTO／日期與樹骨架，再實作成員／搜尋／Ungrouped；每層跑相應負向測試。
4. 先決定 STOP-CONNECTION：可讀則整合 relationship enrichment；已確認不支援／無權時依核准降級留白並記驗收例外；若關係目標必備則補齊 schema／privilege 後再完成該 capability。
5. 通過 photo read/storage gate 後才整合 avatar primary-photo stage，通過 contact／photo write gate 後才整合上傳；通過 LINE schema／token／provider gate 後才整合 LINE 圖片 fallback／重新同步。這些未完成能力不得阻擋核心樹或已確認安全的 avatar source，但須標為未完成或核准降級。
6. 在最終 UI 前先通過 DEP-OPTION-METADATA 與 DEP-OPTION-PAGING，證明目標 metadata collection order、Unknown／Empty 與跨頁分段，不得以 Sunny raw values 或 label 清單代替。
7. 最後整合 Razor、DataGrid、搜尋狀態、Loading、行動版與 reduced-motion；逐項通過 DEP-DX-FIXED、DEP-DX-HEADER、DEP-DX-REMOTE-SORT、DEP-DX-STATE、DEP-HSCROLL 的桌機／真機證據，再用 DEP-XUNIT、DEP-OBS、DEP-UTF8 完成交付。
