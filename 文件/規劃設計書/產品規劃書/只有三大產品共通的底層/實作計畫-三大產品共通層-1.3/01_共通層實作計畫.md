# 三大產品共通層實作計畫 1.3（P0、F0–F12、FS、M1）

> 本檔由 Codex 依 `00_總覽與執行規則.md` 與 `02_兩條線操作說明.md` 逐包執行，不必另外載入技能。每個 Task 就是一個工作包（WP）：一個 WP 一個提交系列、一頁驗收報告。步驟用勾選框（`- [ ]`）追蹤。

**Goal:** 打好三大產品共用的薄地基，並在 M1 打通「最薄通路」：同一個好牧人 Channel 裡的 A、B 兩間測試教會，會友各自收到帶自己教會名稱與 Logo 的訊息，互不串；並把平台層的資料結構與畫面佈署到 goodshepherd20、construction、association 三個組織。

**Architecture:** 共用層只放不分產品的能力（Webhook 管線、排程、推播出口、LIFF 身分、圖片代管、權限與修改紀錄、審核卡片、觀測），以介面讓產品註冊自己的處理器。好牧人專屬的 Webhook 派送與 QR 程式移到新的 `SpeechMessageProducts.GoodShepherd.Hosting`。好牧人 2.0 有自己的主機 `SpeechMessageProducts.GoodShepherd2.Web`、自己的 D365 測試組織與 Product 值 `GoodShepherd2`。Channel 名額池的規則放在雙目標的 `LineMessagingProcessor.Core/ChannelPool`，由平台 Plugin 組件在 D365 交易內執行；程式三個產品共用，但每個產品只有自己的 Channel 池。D365 的結構與畫面分平台層與產品層（FS）：平台層佈署到三個組織，產品層只在自己的組織。三個產品都是多租戶，共用引擎的介面一律用 `TenantId`（租戶 account ID），2.0 把教會當成租戶。

**Tech Stack:** .NET 10（主機與共用引擎）、net462;net10.0（Plugin 會呼叫的規則）、ASP.NET Core、Dynamics 365 9.1 地端（Plugin）、平台 SQL Server（本機測試用 LocalDB `(localdb)\MSSQLLocalDB`）、Hangfire（F4）、LINE Messaging API／LIFF、永豐豐收款 API 規格書 V2.6、xUnit。

**Spec:** `E:\電子書籍\音訊科技產品市場、競爭對手==分析研究\音訊產品市場功能需求分析\音訊科技產品(規劃、流程圖)\三大產品共用架構與開發路線規劃(Claude版)\共通層開發計畫_v1.3\三大產品共通層開發計畫書_v1.3.docx`（共通層計畫書 v1.3，2026-11-25）與同資料夾的圖解教學 HTML。技術背景見規劃 v2.5（第 5、6、7、8、9、11 章）。本檔由 1.2 的 01 修訂，差異見 `00_總覽與執行規則.md` §0。

## Review Focus

- Channel token 在 D365 被更新（輪替）時，快取裡的舊 token 正在推播 → 收到 401 應失效快取、重新解析一次再送，第二次仍失敗才告警；不得無限重試。（F3：`Push_TokenRotatedMidFlight_ResolvesOnceThenFails`）
- goodshepherd20 裡複製帶來的 1.5 Channel（`new_product` 空白，含正式 token 密文）→ 不得載入、不得解密、健康檢查不得拿它呼叫 LINE。（F3：`Directory_ChannelWithoutProduct_NotLoadedAndNotCalled`）
- 同一套 Plugin 在一個不在對照表裡的組織執行 → 拒絕，不配發。（F3：`SlotRequest_UnknownOrganization_Refused`）
- 同一個 LINE 使用者在同一個 Channel 同時是兩間教會的會友 → 以伺服器記錄的「目前選擇」（平台 SQL：產品＋Channel＋LINE 身分 → 哪一筆 Contact）決定用哪間教會；不得拒絕整個請求、也不得任選一間。（F6：`Resolve_UserInTwoChurchesSameChannel_UsesCurrentChurch`）
- 主機停機數小時後重啟，已錯過的週期工作 → 只補跑一次，不得一次補跑多次而推爆訊息額度。（F4：`MissedRuns_AfterDowntime_RunOnce`）
- 租戶時區不是台北（`account.new_timezone` 有值）→ 週期工作依該租戶時區觸發。（F4：`Recurring_NonTaipeiTenant_UsesTenantTimeZone`）
- 永豐的請款通知比授權結果先到、或同一通知重送 → 交易最終狀態一致、只入帳一次。（F10：`Callback_CaptureBeforeAuthNotice_IdempotentFinalState`）
- 同一套名額池程式在 construction 執行，組織裡卻有一筆 `new_product＝GoodShepherd2` 的 Channel → 不得配發，回「產品不符」並告警。（F3：`Allocate_ChannelOfOtherProduct_Rejected`）
- 分層清單誤把教會專屬實體放進平台層 → construction／association 的 plan 直接失敗，不得產生可 apply 的計畫。（FS：`Plan_ConstructionOrg_ContainsNoChurchEntities`）
- 組織裡有一筆不在本次計畫內的未發布表單變更 → apply 拒絕發布並列出它，不得用 PublishAllXml 一起發布。（FS：`Publish_UnplannedPendingChange_Refused`）
- 推播第一次逾時、其實 LINE 已收到 → 以同一個 `X-Line-Retry-Key` 重試，LINE 回 409，會友只收到一則。（F5：`Push_TimeoutRetry_SameRetryKey_SentOnce`）
- 上線前，推播的租戶不是測試租戶（例如 goodshepherd20 複製帶來的教會）→ 整批拒絕，一則都不送。（F5：`Send_NonTestTenant_RejectedWhileTestTenantsOnly`）
- 租戶在排程後被停用 → 執行時重驗發現就不執行，也不推播。（F4：`Job_TenantDisabledAfterSchedule_NotExecuted`）
- 邀請連結被轉傳後第二個人再開 → 拒絕；只在開發環境、只對測試租戶有效。（F12：`Enroll_TokenReused_Refused`、`Enroll_NotMappedOutsideDevelopment`）
