這一頁把 D365 9.1 的能力與限制逐條對到本計畫（以 Microsoft Learn 的 9.1 地端文件查證）。最重要的一條：Plugin 可以留，但只能是 .NET Framework，不能是 .NET 10。

點任一步驟，右邊的圖會標出對應方框；圖上的圓形數字就是步驟編號。

  2. 2語言套件與標籤翻譯：只影響 D365 自己的畫面（後台）。會友在 LINE 看到的字不從這裡來。

  4. 4多幣別：教會的幣別就用 Account 內建的幣別欄位，金額一律連同幣別存。
  5. 5替代索引鍵＋Upsert：教會改的字、對外待辦都不會重複建立。

為什麼這樣做這十件事都是「資料結構與程式寫法」的決定，晚做就要回頭改資料與程式；翻譯本身則隨時可以補，不影響架構。

字典分層：一個字從哪裡來drawio 分頁 06

這是整套國際化的核心（例子用英文說明以後啟用其他語言時怎麼運作；目前只有繁中與英文空殼）。每個要顯示的字都有一個 key（例如 Org.Level.Group），系統由上往下五層去找，找到就停。

點任一步驟，右邊的圖會標出對應方框；圖上的圓形數字就是步驟編號。

  1. 1例子：晨光教會一位設定成英文的會友，畫面上要顯示「小組」這個詞。
  2. 2第 1 層：晨光教會有沒有替英文設定自己的說法？有 → 顯示 Cell Group。
  3. 3第 2 層：晨光教會有沒有不分語系的說法？有 → 顯示「細胞小組」。
  4. 4第 3 層：系統字典的英文版有沒有？有 → Small Group。
  5. 5第 4 層：如果會友是 en-GB，就退到 en 再找；zh-HK 退到 zh-TW。
  6. 6第 5 層：最後一定回到 zh-TW 的「小組」。
  7. 7五層都沒有：畫面會出現 key 本身並記錄告警。這種情況 CI 會先擋下，正式環境不應該發生。
  8. 8同一個 key，晨光的英文會友、晨光的中文會友、其他教會的會友，會看到三種不同的字。
  9. 9效能：第 3～5 層在程式啟動時載入一次；第 1～2 層每間教會一份唯讀快照，有上限、異動後 60 秒內換新。
  10. 10會友看到的字只來自這條鏈。D365 欄位標籤的翻譯，只給後台使用者看。
為什麼這樣做教會自訂術語與多語系是同一套機制：都是「同一個 key，依教會與語言給不同的字」。做一次，兩種需求都解決。

字典什麼時候進記憶體drawio 分頁 06A

你問：國際化的字（字典）是不是要在程式載入時先放進記憶體，才不會拖慢速度？答案是要，而且分三種字，各有最適合的載入時機。

為什麼這樣做英文試點只能檢查翻譯過的那一條流程，還要花翻譯與維護的工夫；偽語系自動產生、涵蓋全部畫面、沒有維護成本。英文只建空殼：系統認得 en、英文關鍵字表放入現有的 Pray、Report、QR、RPG、ID、Notify，但不翻譯、不開放給教會。以後真的要上英文時，只是補字典。

研究報告的實測結論：國際化本身的成本小到量不出來。Plugin 版要多注意一件事：沙箱有 2 分鐘上限，重的工作不放在 Plugin 裡。

.NET 10（net10.0）
微軟目前的長期支援版本，支援到 2028 年 11 月。網站、LINE 主機與共用程式用它。

上一代的 .NET，只能在 Windows 上跑。D365 9.1 的 Plugin 只能用 4.6.2～4.8，本計畫用 4.8。

裝在自己機房的 Dynamics 365 Customer Engagement 9.1。主流支援到 2029 年 1 月、延伸支援到 2031 年 1 月。
Plugin（外掛）
D365 在資料存檔時自動執行的自訂程式（IPlugin）。本計畫保留，全部收進 Plugins.dll。
自訂工作流程活動（CodeActivity）
D365 流程裡可以呼叫的自訂步驟。本計畫保留，全部收進 Workflows.dll。
沙箱（Sandbox）
D365 執行 Plugin 的隔離環境：DLL 要自含全部邏輯、不能用 GDI 等底層 API、執行上限 2 分鐘。

同一份原始碼一次編出兩個版本（4.8 與 .NET 10）。GoodShepherd.Core、ToolUtility.Core、Localization 都是。
ILRepack
把多個 DLL 合成一個的工具（ILMerge 的後繼）。用來把共用程式庫併進 Plugin DLL。
強式名稱（.snk）
給 DLL 簽章的金鑰，D365 註冊 Plugin 需要。舊金鑰已外流，要產生新的。
對外待辦（new_outboundtask）
Plugin 需要產生宮格圖、QR 圖片或查永豐撥款時寫的一筆紀錄，由 .NET 10 認領並執行。一般推播不用它。

Retry Key
LINE 推播 API 的冪等標頭：同一個 key 在 24 小時內重送，LINE 不會重複送達。本計畫用活動或記錄的 ID。
broadcast
LINE 發給該帳號全部好友的 API。本計畫的程式不提供，避免誤發給別間教會的會友。
樂觀並行
更新時比對版本號；如果別人先改了，這次更新就失敗。用來保證一筆待辦只會被處理一次。
Plugin 追蹤記錄
D365 內建、記錄 Plugin 執行訊息的地方。影子模式把「本來會寫入什麼」寫在這裡比對。
Solution（.sln）
Visual Studio 裡把多個專案包在一起的檔案。目標是三個變一個。
主機（Host）
真正對外「開門」接請求的程式（網站或服務）。本計畫的主機只做組裝。
共用層
多個主機都會用到的程式庫。改一次，所有主機一起生效。

把程式做成「可以換語言、換時區、換幣別」的結構。本計畫現在就做。
在地化（l10n）
真的把字翻成某個語言、配合某個市場。本計畫不翻譯，等有市場再做。
英文空殼
系統已經認得 en 這個語言（語言清單、欄位、宮格命名都有），英文關鍵字表放入現有的英文關鍵字，但字典不翻譯、不開放給教會。以後上英文只要補字典。
教會清單
每間教會自己維護的項目清單（例如奉獻類別），每筆有固定 ID。和「教會覆寫」不同：覆寫只換名字，清單可以增減項目。
語系（culture）／BCP 47
表示語言與地區的代碼，例如 zh-TW（台灣中文）、en（英文）、en-GB（英國英文）。
字典（.resx）
存放「key → 文字」的檔案，每個語系一份。建置時轉成程式碼，所有語系都在同一個 DLL 裡。
key
字的代號，例如 Org.Level.Group。命名規則是「領域.畫面.用途」。
後備（fallback）
找不到某個語系的字時，退到上一層再找，最後一定回到 zh-TW。
教會覆寫
教會自己改的字，存在 D365 的 new_localizedtext；只影響那一間教會。
偽語系
測試用的假語言：把每個字加長、加記號，用來抓出漏掉的字和被截斷的版面。
棘輪（ratchet）
記下現在的數量當基準，之後只能變少、不能變多。用來控制舊程式的中文字串。
UTC
世界標準時間。所有「發生的時間點」都用它存，顯示時再換成教會時區。
IANA 時區
時區的國際標準名稱，例如 Asia/Taipei，內含夏令時間規則。.NET 10 直接使用；4.8 用對照表換成 Windows 名稱。
DateOnly／TimeZoneIndependent
D365 日期欄位的兩種行為：只存日期／原樣存不換算。生日用前者，聚會當地時間用後者。
ISO 4217
幣別代碼標準，例如 TWD、HKD、USD。金額一律和它一起存。
sender.name
LINE 訊息旁顯示的發送者名稱，最多 20 字。每間教會、每個語系都有自己的範本。
宮格（Rich Menu）與 alias
聊天室下方的圖文選單。alias 是它的別名，最長 32 字；本計畫在 alias 加上語系。
去重／冪等
同一件事被送兩次，只做一次。
租戶（Tenant）
一間教會。每間教會的差異寫在設定裡，不寫在程式裡。
影子模式
新程式先「只看不做」，和舊程式的結果比對；完全一樣才正式切換。
DMZ
防火牆裡對外開放的區域。LineWebhook 放這裡。
Exception.log
主方案既有的錯誤日誌檔。規範是先寫進日誌，再通知管理者。
