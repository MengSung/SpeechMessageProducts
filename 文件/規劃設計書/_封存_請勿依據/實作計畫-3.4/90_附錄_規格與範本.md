### A.5　Channel Token 加密封包

```
v1:{base64(iv 16 bytes)}:{base64(ciphertext)}:{base64(mac 32 bytes)}
```

- **金鑰：** 64 bytes 隨機值，以 base64 保存。前 32 bytes 是 AES-256 金鑰，後 32 bytes 是 HMAC-SHA256 金鑰。
- **加密：** AES-256-CBC、PKCS7，每次產生新的隨機 IV（`RandomNumberGenerator`）。
- **MAC 計算：** `HMAC-SHA256(macKey, ASCII("v1") || iv || ciphertext)`。
- **解密順序：** 先驗 MAC（固定時間比較），通過才解密。
- **固定時間比較：** net10 用 `CryptographicOperations.FixedTimeEquals`；net462 自行實作「逐位元組 XOR 累加、長度不同也跑完」。兩個目標共用同一組測試向量。
- **金鑰輪替：** 封包版本號保留給未來的 `v2`。輪替時以工具重新加密全部 Channel。

## 附錄 B　Plugin 步驟註冊清單的欄位（`d365\registration\plugins.registration.json`）

3.3 版起，步驟註冊規格寫成佈署專案讀取的清單（D22），不再另寫「步驟註冊表.md」。每個步驟一筆，欄位如下：

| 欄位 | 說明 |
|---|---|
| `type` | 類別完整名稱，例如 `SpeechMessage.Dynamics.Plugins.Fees.FeeAllotPlugin` |
| `message`／`entity` | 例如 `Create`／`new_fee` |
| `stage`／`mode` | `PreValidation`、`PreOperation`、`PostOperation`／`Synchronous`、`Asynchronous` |
| `filteringAttributes` | 陣列；Update 一定要設 |
| `images` | 名稱（`PreImage`、`PostImage`）、類型與欄位 |
| `rank` | 執行順序，與舊步驟相同 |
| `unsecureConfig` | JSON；至少有 `{"mode":"Shadow"}` 或 `{"mode":"Live"}`；機密或個資以 `${secret:名稱}` 佔位 |
| `secureConfig` | 只寫佔位，例如 `{"tokenKey":"${secret:Deployment:TokenKey}"}`；**清單、plan、紀錄中都不出現值** |
| `enabledByOrganization` | 各組織的期望啟用狀態；沒寫就是停用 |
| `legacy` | 對應舊步驟：舊組件、類別、步驟 ID（來自 `export` 或附錄 D 匯出） |
| `shadowReport` | 影子比對報告檔名與差異數（P5 完成時填） |

清單與 DLL 一致性測試（L2）以本附錄為準：每個 `type` 都存在於建置出的 DLL；DLL 中每個 `IPlugin`／`CodeActivity` 公開類別都至少有一筆；`filteringAttributes` 與 `images` 的欄位都存在於附錄 A 或結構快照。

### E.3　偽語系規則（`qps-ploc`）

- 補字數一律為 `max(1, ceil(原文字數 × 0.4))`；建議以整數運算 `max(1, (2 × 字數 + 4) / 5)`（整數除法），避免浮點誤差。
- **字數：** 去掉所有 `{參數}` 後，剩餘的 Unicode 字元（.NET `Rune`）全部計入，包含全形標點、空白及補充平面的字元；不以 UTF-16 code unit 計數。
- `{參數}` 的辨識與 resx 參數名稱集合檢查共用同一份實作，參數原樣保留，不改字、不加長。
- **包圍：** 整段文字只包一次 `［`…`］`；`ǂ` 接在原文最後面、放在 `］` 前面，不插入參數或各文字片段之間。
- **範例已更正：** 設計 v3.4 已把四字範例改為 2 個 `ǂ`（「課程報名」→「［課程報名ǂǂ］」），與本節公式一致；設計文件「約 40%」是概述，驗收一律依本節精確公式（2026-11-03 核定）。
- 格式語系為 `en-US`。
- 只有 `AllowPseudoLocale=true` 時才能選用，正式環境禁止（P2-01 的啟動檢查）。

### G.3　安全規則（每一條都要有測試）

- **白名單：** `Deployment:AllowedOrganizations` 預設只有 `goodshepherdback`。正式組織在 P7-01 才開放，需 `--production`、輸入組織名稱確認、只能執行已審核的 plan。
- **帳密：** 只從執行者電腦的 User Secrets 或 Windows 認證管理員讀取；命令列不接受密碼；不寫進 plan、紀錄、例外訊息。
- **機密與個資佔位：** 清單中的機密與個資一律寫成 `${secret:名稱}`；plan 與紀錄只顯示佔位名稱。
- **不讀業務資料：** 除了 `smoke` 自己建立的測試資料，所有指令只讀中繼資料（組件、步驟、實體定義、追蹤記錄中對應測試資料的那幾筆）。
- **plan 防過期：** plan 含組織現況指紋與 SHA-256；`apply`、`switch` 前重新計算，不同就拒絕。
- **組件版本：** 同名、同 PublicKeyToken、同主次版本才更新內容，否則停止（設計 10.8 節）。
- **新步驟預設停用：** 除非清單對該組織明確寫 `enabled`。
- **連線生命週期：** 每個指令建立一個連線，結束時 Dispose；不放進靜態快取；逾時或取消後不重用。
- **同時執行：** 同一個組織同時只允許一個會寫入的指令。

### G.4　五層驗證（設計 10.13 節）

| 層 | 在哪裡 | 本專案負責的部分 |
|---|---|---|
| L0 | 本機、CI | 各專案的單元測試 |
| L1 | 本機、CI | plan 比對邏輯（假結構＋結構快照）、冪等、衝突停止、白名單 |
| L2 | 本機、CI | 清單與 DLL 一致性（附錄 B 最後一段）、簽章、版本、合併 |
| L3 | goodshepherdback | `apply`、`smoke`、`shadow`、`switch`、`rollback`（Codex 執行，D24） |
| L4 | 正式組織 | Codex 準備 plan 與回復方式 → 使用者第一次回「可以」→ Codex `apply`／`switch` → `verify` → 觀察 |
