## 2. 固定規則（不得自行變更）

1. **完成定義（五項，不加碼）**：①一頁規格／本計畫列出的驗收條件全部通過；②自動測試（含跨教會隔離測試）全綠、全方案建置通過；③測試環境實機驗收報告一頁，附截圖；④檔案說明、UTF-8 無 BOM、CRLF、資源釋放符合 `AGENTS.md`；⑤使用者審核通過。
2. **狀態只能照階梯宣稱**：程式完成 → 自動測試通過 → 測試環境驗證 → Pilot 通過 → 正式可用。最後一階需要使用者另行授權。
3. **證據等級**：每個「已有／已驗證」的說法要能指到測試名稱、log 的 SHA-256 或截圖；否則寫「待驗證」。
4. **立即停止放行**（任一發生就停下、修好才繼續）：跨教會／Channel／產品／使用者外洩；合法不同 ID 被合併或重複 ID 被靜默吃掉；停止、取消、逾時後資源沒回基線；秘密或完整個資進 log；出現 broadcast 呼叫或推播混入他教會 userId；宮格無上限建立或實際數與帳上不一致仍配發；測試誤連正式組織、正式 Channel 或正式金流；真正失敗沒有告警或無法追查。
5. **時間盒**：每個 WP 以計畫標示的工作天為上限。到期可延長到 1.5 倍，只用來完成驗收條件；仍做不完就把未完成的驗收條件寫進「之後再說」或計畫修正提案，WP 以「已驗收（縮減）」結案並在回報中列明縮減了什麼。
6. **平行上限**：同時最多兩個 WP；兩個必須互不相依、不改同一個檔案（D31）。
7. **提交**：一個提交只屬於一個 WP，訊息以 WP 編號開頭；會讓方案建置失敗的內容不得提交；WP 驗收後才推送（D30）。
8. **回報**：每個 WP 一頁（`wp-reports/3P-<WP>-<名稱>.md`）：每條驗收條件的結果、截圖、已知限制；原始 log 不進 repo，只寫 SHA-256（D32）。
9. **新點子**：寫進 `wp-reports/3P-之後再說.md`，不在當輪做；計畫只由使用者改版（D35）。
10. **環境**：只用 2.0 測試組織（暫名 `goodshepherd20dev`）、測試 Channel（T01–T03）、永豐沙箱；全程不得連任何正式組織；2.0 測試組織只放合成資料；實機測試標 `Category=Live3P`，不進一般測試。
11. **自主範圍**：Codex 依 `AGENTS.md` 與 D24 自行操作測試環境（含 D365-9.1、閘道設定），事後留一頁紀錄。只有下列情況找使用者：P0 標「使用者」的項目、規劃 v2.1 第 18 章的決策（D1–D12，D10 已定案）、任何正式環境作業、停止放行條件發生且無法在時間盒內修好。
