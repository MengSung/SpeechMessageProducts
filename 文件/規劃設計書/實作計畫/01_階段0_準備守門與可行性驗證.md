## P0-05　編碼檢查與編碼轉換工具

**新增** `tools\RepoQuality\Test-TextEncoding.ps1`，需相容 PowerShell 5.1 與 7。

| 參數 | 說明 |
|---|---|
| `-Scope Changed -Base <ref>` | 只檢查與 `<ref>` 相比新增或修改的檔案（`git diff --name-only --diff-filter=AMR`） |
| `-Scope All -ReportPath <md>` | 全部掃描，只輸出報告、不讓建置失敗，用來盤點舊檔 |
| 檢查的副檔名 | `.cs .cshtml .csproj .props .targets .json .md .ps1 .resx .xml .yml` |
| 失敗條件 | 有 BOM；不是合法 UTF-8；有 LF-only 或混用換行；檔尾不是 CRLF；含 U+FFFD 替代字元（亂碼跡象） |

**新增** `tools\RepoQuality\Convert-TextEncoding.ps1`，給之後搬移舊檔用。
- **預設 `-DryRun`。** 偵測 BOM 與 CP950，轉成 UTF-8 無 BOM＋CRLF。
- **輸出 manifest JSON：** 每個檔案記錄路徑、原始編碼、轉換前後的 SHA256，以及「中文字串常值清單轉換前後是否一致」。
  - 中文字串常值以 Roslyn 或正則抽出，轉換前以 CP950 解碼，轉換後以 UTF-8 解碼；兩邊必須完全相同，否則該檔不寫入並列為失敗。

**先寫的測試：** `tools\RepoQuality\Tests\Test-TextEncoding.Tests.ps1`，使用 Pester。若環境沒有 Pester，以純 PowerShell 斷言腳本代替。

**樣本檔：** 放在 `tools\RepoQuality\Tests\Fixtures\`，用腳本在測試時產生，不要提交有問題的檔案：
- UTF-8 無 BOM＋CRLF：通過；
- UTF-8 BOM：失敗；
- LF-only：失敗；
- CP950 中文：失敗；
- 檔尾無換行：失敗；
- 含 U+FFFD：失敗。

轉換腳本另外測三件事：
- 「CP950 → UTF-8 後中文字串相同」；
- 「-DryRun 不寫檔」；
- 「無法無損轉換時不寫檔」。

**驗證：** 測試全過；以 `-Scope All` 產生 `tools\RepoQuality\reports\encoding-baseline.md`。預期會列出 `Trace\` 的 CP950 檔、`Line.Messaging` 的 BOM 檔等既有問題，作為後續階段的待辦。

## P0-06　重複程式掃描（R1）

**新增** `tools\RepoQuality\Find-DuplicateCode.ps1`

**掃描規則：**
- **掃描範圍：** .sln 內所有專案的 `.cs`，排除 `obj\`、`bin\`、`*.g.cs`、`*.Designer.cs`。
- **正規化：** 去掉 BOM、統一換行、去掉行尾空白、去掉 `//` 與 `///` 註解行、壓縮連續空白。
- **找出兩種重複，並列出位置：**
  1. 正規化後 SHA256 相同、但位於不同專案的檔案；
  2. 不同專案中，同一個命名空間＋型別名稱的 `class`、`record`、`struct`。

**基準檔：**
- 第一次執行時產生 `tools\RepoQuality\duplicate-baseline.json`，記錄現有重複。
- 之後只有「比基準多出新的重複」才失敗。基準中的項目解決後要從基準移除；工具在「基準中有、但已不存在」時給出提醒。

**先寫的測試：** 以兩個暫存資料夾、各放一份相同內容的 `.cs` 檔，斷言會被找出；只差註解與空白的兩份也要被找出；基準內的重複不失敗、基準外的重複失敗。

## P0-07　I18nCheck 第一版：中文字串棘輪＋resx 產生器

**新增** `tools\I18nCheck\I18nCheck.csproj`
- net10.0 console，`SpeechMessageStrictCode=true`；
- 不進 .sln；
- 使用 `Microsoft.CodeAnalysis.CSharp`。

**本階段要做的指令**

| 指令 | 行為 |
|---|---|
| `scan --baseline <json>` | 掃描 .sln 內非測試專案的 `.cs`，以 Roslyn 找出含 CJK 字元（U+3400–U+9FFF、U+F900–U+FAFF）的字串常值，排除兩類：(a) `ILogger` 訊息樣板與 `Trace`／`Debug` 呼叫的引數；(b) 標記為 `[I18nIgnore("理由")]` 的成員。`.cshtml` 以「HTML 文字節點與 `title`、`placeholder`、`alt`、`value` 屬性中的 CJK 片段」計算。輸出每個專案、每個檔案的數量 |
| `scan --write-baseline <json>` | 產生基準檔 `tools\I18nCheck\baselines\cjk-literals.json` |
| `generate --resx <檔> --namespace <ns> --class <名> --out <g.cs>` | 讀取 `X.resx`，以及同名的 `X.en.resx` 等語系檔與偽語系，產生 C# 程式碼（格式見附錄 E.2）。輸出排序固定、換行 CRLF、UTF-8 無 BOM，重複執行結果逐位元組相同 |
| `generate --check` | 重新產生並和既有 `.g.cs` 比較，不同就失敗。給 CI 用，防止忘記重產 |
| `verify` | 跑上述 scan（和基準比，任一專案數量增加即失敗；新專案基準為 0）與 `generate --check`，以及 resx 檢查（本階段只做：key 格式、key 唯一、參數名稱集合一致；其餘在階段 1 補） |

**偽語系產生規則**（P0-08 會用到；正式規格見附錄 E.3）
- 偽語系代碼為 `qps-ploc`。
- 轉換方式：`［` ＋原字串＋`］`，再補 `ǂ`，讓字數增加約 40%（至少 1 個）。
- `{name}` 這類參數原樣保留，不加長、不改字。

**先寫的測試**（`tools\I18nCheck.Tests`，net10.0，不進 .sln，CI 執行）
- `Scan_LiteralWithCjk_IsCounted`、`Scan_LoggerTemplate_IsExcluded`、`Scan_CommentOnly_IsNotCounted`、`Scan_I18nIgnoreAttribute_IsExcluded`
- `Ratchet_CountIncreases_Fails`、`Ratchet_CountDecreases_PassesAndReportsImprovement`
- `Generate_SameInput_ByteIdenticalOutput`、`Generate_OutputIsUtf8NoBomCrlf`
- `Pseudo_WrapsAndExpands_KeepsPlaceholders`：輸入 `"{name}，報名成功"`，期望 `"［{name}，報名成功ǂǂǂ］"`，ǂ 的數量依規則計算。
- `Resx_DuplicateKey_Fails`、`Resx_ParameterMismatchBetweenCultures_Fails`、`Resx_InvalidKeyFormat_Fails`

**驗證：** 測試全過；`scan --write-baseline` 產生的基準檔已提交，並在回報中列出前 10 名專案的數量。

| `ILinePushClient.PushAsync(LineChannelCredential credential, LinePushRequest request, CancellationToken ct)` | POST `https://api.line.me/v2/bot/message/push`；標頭 `Authorization: Bearer {token}`、`X-Line-Retry-Key: {RetryKey:D}`；逾時 10 秒；回傳 `LinePushResult`（成功、狀態碼、LINE 的 `x-line-request-id`、錯誤分類） |
| 錯誤分類 | 2xx＝成功；409（同 Retry Key 已接受）＝視為成功並標記 `AlreadyAccepted`；429、5xx、逾時＝`Retryable`；400、401、403、404＝`Permanent` |
| `LineChannelCredential` | 只包 Token 字串。`ToString()` 回傳 `"LineChannelCredential(***)"`，絕不輸出 Token |
| `HttpClient` 生命週期 | net10：由呼叫端傳入 `HttpClient`（主機用 `IHttpClientFactory`）。net48：`LinePushClient` 內部持有一個 `static readonly HttpClient`，原因是 Plugin 沙箱會重用程序，不能每次 new，也沒有 DI。它不含任何使用者或教會狀態，Token 只放在每個請求的標頭，不放 `DefaultRequestHeaders`。逾時與取消一律用每個請求自己的 `CancellationTokenSource`，用完 Dispose。這些都要寫進繁中註解 |
| TLS | net48 依 OS 預設（目標 4.8 已是 `SystemDefault`）；不得寫死 `ServicePointManager.SecurityProtocol` |

     - **不寫 Token、不寫訊息內容以外的個資。**
