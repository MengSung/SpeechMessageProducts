## 3.3 版改了什麼

- **D365 佈署改用 Solution 內的佈署專案**（D22）：新增 `SpeechMessage.Dynamics.Deployment`，不再手動操作 Plugin Registration Tool；v3.2 的 `tools\D365Provisioning`、`tools\ShadowCompare`、`tools\D365StepSwitch` 併入它（附錄 G）。
- **先在 Solution 內測**：五層驗證，L0～L2 不需要 D365（00 第 5.4 節、附錄 G.4）。
- **開發測試組織 goodshepherdback**（D23、D24）：正式組織的複本，使用者回報清理完成前不連線；Codex 只執行不寫入的指令。
- **開發環境防護**（D27）：新增 P0-SEC、P0-ENV。
- **階段 0 調整**：原 P0-12 拆成 P0-12「佈署專案最小版」與 P0-13「使用者以佈署專案驗收」；階段審查改在 P0-12 之後。
- **其他**：步驟註冊規格改成清單 `d365\registration\plugins.registration.json`（附錄 B）；正式組織以同一個佈署專案逐組織佈署，不使用受管理解決方案（D25）；表單、檢視、流程以 `ui-export`／`ui-import` 處理（D26）；專案數 35 → 37。

## 給 Codex 的一句話

一次只做一個 WP。動手前先讀 `AGENTS.md` 與 `00_總覽與執行規則.md`。
**每個 WP 都採測試導向設計（TDD）**：
- 新程式：先寫會失敗的測試、確認失敗，再寫程式讓它通過，最後重構；
- 搬移舊程式：先用「特性測試（黃金檔）」把舊行為鎖住，再搬移。

做完要跑完該 WP 的「驗證」並附上證據（含測試先失敗、後通過的紀錄），才算完成。
遇到「停止條件」就停下來回報，不要自行猜測或繞過。
