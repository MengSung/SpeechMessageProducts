| 正式組織第一次寫入 | 本目標不會發生（D8-2） |
| 改變已定案的決定、計畫與設計矛盾 | 照本檔做，矛盾寫進 `P8-PROP-008`（3.6 時一次處理） |
| 不可逆又無法事前備份 | 不做那一步，改用可回復的做法；沒有可回復的做法就跳過並登錄提案 |
| 業務判斷（類別合併、兩份舊程式行為不同） | 依 D8-7 不合併；行為不同時維持 ChurchReport 現行行為，列進提案 |
| 需要 `NoWarn` 新警告、降低既有檢查 | 不放寬；改寫程式繞開；繞不開就把該項目延後並登錄提案 |
| 同一個自動操作失敗兩次 | 不再試第三次；記錄原因碼，依該單元的「可延後」與 D8-3 處理，繼續做 |
| 時間盒或 15 個提交到期 | D8-26 |
| 計畫規則本身不可行 | 寫進提案，先做不受影響的部分 |
| 05 檔 P8-01「十一／什一」請使用者決定 | D8-7 |
| 05 檔 P8-02「中文文字存放：停止」 | 不適用（D8-11） |
| 05 檔 P8-03「沒有可靠的管理員機制：停止」 | D8-12 |
| 外部審查服務沒有回應 | §6.1 |

### 7.3 真的要停的只有這四種

1. 發現某個指令或設定會連到 goodshepherdback 以外的 D365 組織：立刻中止該指令；檢查是否已經寫入；回報。**整個目標停止**。
2. goodshepherdback 無法回到 `off`（回復兩次都失敗）：停止所有實機單元並回報；離線單元可以繼續做完。
3. 發現秘密（Token、密碼、金鑰、LINE userId）進了提交：不推送、停止、回報如何移除。
4. 使用者說「停」或按下 Esc。
