# P2-12 推播鏈實機驗收步驟

> 只連 `goodshepherdback`；只使用已核定的測試 Channel；秘密只從 User Secrets 或標準輸入取得，不進命令列、檔案、log、回報或進度頁。

## 事前

1. 確認 `Deployment:Organizations:goodshepherdback:TokenKey`、`TestChannelToken`、`TestLineUserId` 已存在；Channel Secret 只從受控標準輸入提供。
2. 執行 `export --org goodshepherdback`，保存本機操作紀錄與 SHA-256；確認既有步驟、Channel 與測試資料的原況。
3. 依 D34 唯讀核對正式 token 與非測試會友 LINE ID 均為 0；失敗先清理，不能開始推播。

## 執行

1. `protect-token --org goodshepherdback --channel-id <測試 Channel ID>`：標準輸入依序提供 token 與 Channel Secret；不把值寫入 shell history。
2. 建立並標記測試教會 A、B、各自測試 Contact；只把 A 的 Contact 綁定 `TestLineUserId`，偏好語言設為 `qps-ploc`。
3. `assign-channel --org goodshepherdback --channel-id <測試 Channel ID> --account <A 的正式 GUID>`。
4. 清單設定 `mode=member`、`culture=qps-ploc`、A 的正式 `sourceChurchId`、`allowPseudoLocale=true`，secure 只放 `${secret:TokenKey}`；執行 `plan → apply → verify`，verify 只核對 metadata，不能把未比對秘密誤稱完整成功。
5. 啟用追蹤「全部」，建立 A Contact 的 task，60 秒內核對固定追蹤欄位：`Outcome=Accepted`、`Status=200`、有效 `RequestId`、`TemplateKey=Diagnostics`、`Culture=qps-ploc`；不保存訊息本文、token 或 userId。
6. 將 task 關聯 B Contact 重跑，核對 `ChurchMismatch` 且沒有新的 LINE HTTP 受理；用同一 task ID 重跑，核對相同 Retry Key 不增加第二次受理。
7. 建立一筆 `RichMenuGenerate` 待辦，啟動兩個 Worker，核對只有一個版本更新成功且只產生一次候選。

## 收尾

1. 先停用 member 步驟並恢復 trace／停用設定，執行 plan → apply → verify=0，追蹤恢復「例外狀況」。
2. 依正式 ID 刪除本次建立的 tasks、outbound tasks、Contacts、Accounts、Channel 指派與本次 Channel 記錄；不刪除他人資料。
3. 再次 `export` 與唯讀盤點，測試資料、待辦、追蹤、暫存檔與本次 Channel 指派殘留必須為 0。

## 通過條件

正常偽語系受理、錯教會不送、同 Retry Key 不重複、雙 Worker 唯一認領及清理 0 全部成立；手機收訊只作觀察，不取代 `Accepted/200/RequestId`。
