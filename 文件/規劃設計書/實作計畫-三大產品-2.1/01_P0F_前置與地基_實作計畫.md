# 前置與地基（P0、F0–F12）實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本專案慣例由 Codex 依 `00_總覽與執行規則.md` 執行；每個 Task 就是一個工作包（WP），一個 WP 一個提交系列、一頁驗收報告。

**Goal:** 打好三大產品共用的薄地基，並在第 5 週打通「最薄通路」：同一個好牧人 Channel 裡的 A、B 兩間測試教會，會友各自收到帶自己教會名稱與 Logo 的訊息，互不串。

**Architecture:** 共用層只放不分產品的能力（Webhook 管線、排程、推播出口、LIFF 身分、圖片代管、權限與修改紀錄、審核卡片、觀測），以介面讓產品註冊自己的處理器；好牧人專屬的 Webhook 派送與 QR 程式移到新的 `SpeechMessageProducts.GoodShepherd.Hosting`；好牧人 2.0 有自己的主機 `SpeechMessageProducts.GoodShepherd2.Web`、自己的 D365 測試組織與 Product 值 `GoodShepherd2`，Channel 名額池的規則放在雙目標的 `SpeechMessageProducts.GoodShepherd.Core`，由 Plugin 在 D365 交易內執行。

**Tech Stack:** .NET 10（主機與共用引擎）、net462;net10.0（Plugin 會呼叫的規則）、ASP.NET Core、Dynamics 365 9.1 地端（Plugin／自訂動作）、平台 SQL Server、Hangfire（F4）、LINE Messaging API／LIFF、永豐豐收款 API 規格書 V2.6、xUnit。

**Spec:** `E:\電子書籍\音訊科技產品市場、競爭對手==分析研究\音訊產品市場功能需求分析\音訊科技產品(規劃、流程圖)\三大產品共用架構與開發路線規劃(Claude版)\三大產品共用架構與開發路線實施計畫_Claude版_v2.1.docx`（第 7、8、9、11、12.1 章）與同資料夾的圖解教學 HTML v2.1。使用者 2026-11-23 核定。

## Review Focus

- Channel token 在 D365 被更新（輪替）時，快取裡的舊 token 正在推播 → 收到 401 應失效快取、重新解析一次再送，第二次仍失敗才告警；不得無限重試。（F3：`Push_TokenRotatedMidFlight_ResolvesOnceThenFails`）
- 同一個 LINE 使用者在同一個 Channel 同時是兩間教會的會友 → 以 Contact 上的「目前顯示教會」決定，不得拒絕整個請求、也不得任選一間。（F6：`Resolve_UserInTwoChurchesSameChannel_UsesCurrentChurch`）
- 主機停機數小時後重啟，已錯過的週期工作 → 只補跑一次，不得一次補跑多次而推爆訊息額度。（F4：`MissedRuns_AfterDowntime_RunOnce`）
- 教會時區不是台北（`account.new_timezone` 有值）→ 週期工作依該教會時區觸發。（F4：`Recurring_NonTaipeiChurch_UsesChurchTimeZone`）
- 永豐的請款通知比授權結果先到、或同一通知重送 → 交易最終狀態一致、只入帳一次。（F10：`Callback_CaptureBeforeAuthNotice_IdempotentFinalState`）
