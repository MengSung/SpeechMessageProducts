## 二、 安全與停止界線逐項審核（基於 v3.3 計畫）

以下針對使用者特別指定的安全與停止界線，逐一核對實作計畫與進度頁規範：

1. **P2-04 沙箱 LINE 測試 channel / 使用者本人測試帳號與測試憑證前置、禁止記錄秘密**
   - *依據*：`03_階段2-4_共用送訊_Webhook_金流.md`（P2-04 小節及 `00_總覽與執行規則.md` P0-SEC）。
   - *審核結果*：計畫明確規定使用 User Secrets 注入 `TestChannelToken` 與 `TestLineUserId`，禁止在 repo 儲存真實 token 或 channel secret，且所有 token 加密與例外日誌皆強制過濾或排除私密資料。
2. **P3-04 必須由使用者提供平台 SQL 並禁止正式記憶體去重**
   - *依據*：`03_階段2-4_共用送訊_Webhook_金流.md`（P3-04 小節）。
   - *審核結果*：計畫指定使用 `Microsoft.Data.SqlClient` 連接 `ConnectionStrings:Platform` 進行 SQL Server 持久化去重（`Webhook_Event` 表），禁止依賴單機正式記憶體去重（以防分散式部署多台實例漏失重覆事件），且 SQL 連線失敗時傳回 503 並維持 LINE 重試，不盲目吞掉例外。
3. **P3-09 測試站與 LINE Developers 使用者操作**
   - *依據*：`03_階段2-4_共用送訊_Webhook_金流.md`（P3-09 小節）。
   - *審核結果*：要求在 DMZ IIS 測試站佈署，並由使用者於 LINE Developers 後台手動設定 Channel Webhook URL 與進行驗證。
4. **P5-02 不修改舊方案來源，P5-03 / 各模組 goodshepherdback 的 apply / switch / smoke 由使用者執行**
   - *依據*：`04_階段5-8_Plugin重建_切換_收尾.md`（P5-02、P5-03 小節）。
   - *審核結果*：P5-02 的 LegacyGolden PluginHarness 僅唯讀對照舊原始碼與轉碼，不修改舊方案來源；P5-03 與後續各模組在 goodshepherdback 的 D365 方案 `apply`、`switch`、`smoke` 驗證皆明訂由使用者操作審核。
5. **P7 禁止 Codex 連正式組織且正式 apply / switch 由使用者審核操作**
   - *依據*：`04_階段5-8_Plugin重建_切換_收尾.md`（階段 7 總覽與 P7-01）。
   - *審核結果*：明文禁止 Codex 直接連線正式組織進行變更；正式組織的 `apply` 與 `switch` 必須透過 `--production` 參數防護並由使用者審核執行。
6. **P8-01 保留同名不同 ID、拒絕重複 ID，不合併名稱**
   - *依據*：`04_階段5-8_Plugin重建_切換_收尾.md`（P8-01 捐獻奉獻項目遷移）。
   - *審核結果*：計畫指定按教會與 option value 進行分組，相同名稱但不同 ID 者必須各自保留，不得盲目合併；重覆 ID 則拒絕發布，確保會計與捐獻稽核歷史正確。
7. **P8-02 遇到以中文文字作比對的既有資料要停止**
   - *依據*：`04_階段5-8_Plugin重建_切換_收尾.md`（P8-02 角色名稱對應與防呆）。
   - *審核結果*：強制拒絕依賴中文顯示名稱進行權限或邏輯比對，遇到以中文文字作比對的既有資料須停止並改採系統代號（Role Enum / ID）。
8. **P8-03 無可靠管理員授權時停止且不信任請求端教會 ID**
   - *依據*：`04_階段5-8_Plugin重建_切換_收尾.md`（P8-03 ChurchSettings）。
   - *審核結果*：必須驗證使用者管理員權限，且絕對不信任請求端夾帶的 `churchId`（必須由伺服器端驗證與過濾白名單），防止越權竄改。
9. **P8-04 不保存帳密且需人工登入**
   - *依據*：`04_階段5-8_Plugin重建_切換_收尾.md`（P8-04 PseudoLocaleAudit）。
   - *審核結果*：Playwright 稽核工具不保存帳號密碼，需人工登入或透過環境憑證授權。
10. **P8-05 依 v3.3 已完成的 Word 修正，不虛構待辦**
    - *依據*：`04_階段5-8_Plugin重建_切換_收尾.md`（P8-05 收尾整理）。
    - *審核結果*：確認 v3.3 Word 規範（如 AES-CBC + HMAC-SHA256 加密格式）已落實，不虛構未完成事項。
