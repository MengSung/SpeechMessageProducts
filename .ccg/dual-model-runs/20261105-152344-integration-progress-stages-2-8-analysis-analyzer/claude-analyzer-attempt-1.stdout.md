## Warning

**W1｜`Test-ProgressPage.cjs` 對 P1-03 的過時警示斷言雖已被局部修補，但修補方式仍綁定易變的敘事文字，建議改綁結構化欄位（第 61-62 行 vs 第 90-96 行）**
審核開始時讀到的版本（對應 HEAD 提交內容）在「No alert hides…」測試中斷言：
```js
assert.match(activePage.get('alert').innerHTML, /P1-03 已正式驗收/);
assert.match(activePage.get('alert').innerHTML, /20261105-140350/);
```
對照當時 `實作進度.html` 的 `DATA.alert`（第 362～391 行），這兩段文字**都不存在**於 alert 物件（已用 `node -e` 直接檢核 `alertText.includes(...)` 為 `false`），實際執行得到：
```
✖ No alert hides the warning region and still renders the page
AssertionError: /P1-03 已正式驗收/ 不匹配
```
原因是 alert 的敘事內容每次工作包推進都會重寫（目前已改寫成描述 P1-04 Constants 抽取的進度），把「P1-03 已驗收」這種一次性敘述硬編碼進 alert 文字斷言，本質上是把測試綁在會員每天改寫的自由文字上，而不是綁在穩定的結構化資料（`p1Wps` 陣列的 `status`／`note`）。

目前（修改中、尚未提交的）版本已把斷言放寬為 `/P1-02／03有逐項需求[\s\S]*已正式驗收/`（第 62 行），暫時能通過，但**仍然是同一種做法**——只是換了一段更長的字面文字去綁，下一次 alert 敘事改寫（例如 P1-04 驗收後）大概率又會斷。

**建議的精確取代條件：**
1. 把「No alert hides…」測試裡對 `D.alert`（自由敘事）的 P1-03 專屬文字斷言拿掉或降級為極通用、不隨敘事改寫的恆定邊界語句（例如本頁一直存在的「D365 預設只讀」這種安全邊界用語，而不是某個 WP 的驗收宣告）。
2. P1-03「已驗收」這件事，應該只透過結構化、不隨敘事改寫的資料斷言：也就是現有「Stage 1 progress…」測試第 90-96 行已經在做的事——`getWorkPackageRow(elements, 'P1-03')` 的 `status === done` 且 note 含驗收報告路徑，加上**直接讀取 `wp-reports/P1-03-acceptance.md` 內容含「狀態：本工作包驗收完成」**。這段斷言**必須保留，不得移除**（這正是題目要求「同時不能移除 P1-03 獨立驗收報告斷言」的部分，目前第 94-95 行確實還在，須繼續維持）。

**W2｜新增的 53 包安全邊界斷言只覆蓋 8/53 包，其餘 45 包目前只靠彙總數字把關**
`Future work packages preserve…` 測試（第 140-163 行）只對 P2-04、P3-04、P5-02、P5-03、P7-01、P8-01～P8-05 這 8 包做內容層級斷言；其餘 45 包（P2-01～03、05～12，P3-01～03、05～09，P4 全部，P5-01、04～13 除 02/03 外，P6 全部）目前只被「數量對、ID 不重複、狀態 todo」這三件事保護，沒有名稱／範圍／測試清單的內容斷言。這在補齊 `plannedWps` 時容易出現「複製標題、沒填對應計畫測試清單」的風險（審核要求第 2 點明確禁止）。建議至少對每包的 `scope`／`verification` 欄位加上「必須引用該包在 03／04 文件中列出的『先寫的測試』清單至少一項」的通用斷言，而不是只挑 8 包。

**W3｜階段估時字串遺漏國際化附加天數（00 文件 vs 頁面 `phases`）**
`03` 文件階段 2 估時「10～13 天（國際化＋2～3 天）」、階段 5「20～27 天（國際化＋5～7 天）」、階段 8「4～6 天，國際化＋3～4 天」；頁面 `phases` 的 `est` 欄位（第 671、695、719 行）都省略了括號內的國際化附加天數。不影響工作包計數正確性，但若日後有人只看進度頁估工時會低估。
