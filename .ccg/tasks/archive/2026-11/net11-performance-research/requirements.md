# .NET 11 效能研究需求

使用者要知道官方 JIT／函式庫改進在此方案中的實際幅度，不接受把官方微基準百分比當成整站收益。

- 保留現行 .NET 10、P5 與另一會話變更；不部署、不讀秘密、不連 SQL／Dataverse／LINE。
- 對照真實產品程式：Webhook 驗簽／解析／HTTP 路由、Newtonsoft Flex template、多語與純資料整理；依源碼選擇實際可執行的代表案例。
- 使用同一份 Release IL，在 10.0.15／11.0.0 執行；區分 runtime-only 實驗與真正 retarget／套件遷移，不能宣稱完整升級驗收。
- 微基準記錄多程序配對時間、CPU、配置量、GC、輸出一致性；HTTP 記錄吞吐、P50／P95／P99、錯誤、資源排空與合成 I/O 延遲。
- 保存硬體、版本、原始輸出、腳本、來源及 DLL hash；採交替順序、多次重複、不挑最快一次。
- 對正式端到端效益使用明示假設的 Amdahl 情境，不捏造正式流量或外部服務延遲占比。
- 交付繁中完整報告、可重跑工具與結果摘要；分開標示實測、推估與待驗證，記錄雙模型審查狀態。
- 目前已位於 linked worktree；僅在忽略 artifacts 建置輸出與 task snapshot 保存研究工具，不新增 csproj／不更動 sln。
