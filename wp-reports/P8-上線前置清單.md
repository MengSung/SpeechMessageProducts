# P8 上線前置清單

2026-11-20 21:46 Asia/Taipei (UTC+08:00)

本清單供未來 D365 9.1 正式上線使用；階段 8 不連正式組織，也不授權執行下列作業。正式組織須由使用者逐一核准，依 `驗收\P7_組織切換手冊.md` 與 07A §6C 操作。

## ChurchReport 部署前必要條件

- 每個正式組織在部署新版 ChurchReport 前，先完成奉獻類別轉換及必要的 `new_fee.new_offeringcategoryid`、`new_dedication_booking.new_offeringcategoryid` 回填；migration verify 的「有選項值但沒有查閱值」及跨教會 lookup 都須為0。
- 依 P8-01c 核定規則：欄位內同值重複才拒絕；跨欄共享值使用單一 `legacy-<值>`，名稱取 `new_fee` 語系1028標籤；booking-only值採預約欄標籤。五組標籤差異及值見 P8-PROP-003／P8-01c migration 回報，不另建類別、不合併不同值、不語意猜測。
- 每個組織都須自行備份並保存雜湊；依序執行結構 plan/apply/verify、稽核確認、migration plan、逐段核對、核准後 apply、verify，再以同一 plan 第二次 apply 證明沒有 lookup 更新批次。即使 lookup 無更新，須如實記錄工具仍可能呼叫類別 alternate-key Upsert。
- 教會沒有正式奉獻類別或 lookup 時，不得先部署並開放新增奉獻；新版 ChurchReport 對缺正式類別 ID 的新增採 fail-closed，應先完成轉換及回填。

## 其他上線步驟

- 依終點回報核定 ChurchReport 與 LineWebhook 部署版本，以及 `Localization:ChurchOverrides:Enabled`、`Messaging:NotifyRelay:Enabled` 等開關。
- 執行 `church-defaults`，只填空白欄位並確認既有值未被覆寫。
- 註冊清單只切換為 `tier=live` 且有實機證據的項目；依切換手冊逐步驗證與回復。
- 上線前處理終點回報列出的必要提案，並逐一核准組織操作。

P8-PROP-008 僅記錄計畫文件文字一致性，已不再是奉獻標籤阻擋；正式組織仍須按上述條件各自完成轉換及回填。
