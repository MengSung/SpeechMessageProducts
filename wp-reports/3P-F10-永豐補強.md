# 3P-F10 永豐補強（沙箱）驗收報告

## 結論

程式與離線自動測試完成，程式提交為 `6dc26670`（`F10 fix: 保持 Gateway capability 契約相容`；前一個功能提交為 `1af591cf`）。本包狀態為「完成（自動測試通過）」；永豐沙箱五個情境尚未宣稱成功，原因是 P0-1 的沙箱交接秘密尚未具備，本包也未連線任何正式金流。

## 實作內容

- 新增 provider-neutral 綁卡、訂單維護與定期扣款 capability；Gateway 依伺服器端 profile 路由，沒有 capability 的 provider fail closed。
- 永豐實作 `CardBindCreate`、`OrderMaintain` 的 C／P／E 命令、`RegularQuery` 建立／查詢／停止，以及綁卡付款的 `BindNo`／`BindToken`。
- 綁卡查詢結果只交付 profile、商店與 BindNo 綁定的 AES-GCM 密文；明文 BindToken 只在單次 provider 操作中存在，完成後清空 DTO 欄位。
- RegularQuery 先驗證商店、主單及每筆穩定 `OrderNo`／期數，候選集合完整驗證前不發布；本地候選上限為 1,000 筆。
- HTTP 使用 `ResponseHeadersRead`，回應本文以 4 MiB 固定位元組上限逐步讀取，並以 linked cancellation token 將 `HttpClient.Timeout` 延伸至本文讀取；超限、取消、逾時與傳輸失敗均 fail closed，response／stream 確定釋放。

## 實機待補與邊界

- 實機待補：綁卡、取消授權、立即請款、延後請款到期查詢、定期定額建立與中止五個永豐沙箱情境；需在具備 P0-1 設定後以 `Live3P` 執行，必要時以瀏覽器輸入規格書測試卡。
- `MaximumResponseBodyBytes = 4 MiB` 與定期扣款 1,000 筆是本地資源上限，不是已確認的永豐銀行限制；若正式規格證據需要調整，必須保留有界讀取與對應測試。
- V2.6 外層簽章未涵蓋巢狀 `TSResultContent`；F10 以 HTTPS、商店／PayToken／BindNo 關聯及本機 AEAD 保護，不把巢狀 BindToken 宣稱為外層簽章涵蓋。
- BindToken 銀行效期尚未確認，產品持久層必須依正式規則清除密文；跨請求最終入帳冪等由後續持久化層以唯一鍵及原子 create-or-update 負責。
