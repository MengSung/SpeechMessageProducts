# 多小組顯示相同聯絡人問題修復報告

## ?? 問題描述

**症狀**: 裝備狀態頁面有兩個或以上小組時，點擊不同小組後卻都顯示相同的聯絡人名單

**預期行為**: 不同小組應該顯示各自的成員名單

**影響範圍**: 多小組裝備管理功能

---

## ?? 根本原因分析

### 問題代碼

```csharp
[HttpGet]
public object LoadEquipmentContact(string id, DataSourceLoadOptions loadOptions)
{
    try
    {
        // 確保資料已載入
        if (InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport == null || 
            !InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport.LoadFlag)
        {
            InMemoryContext.ListManager.SetupIntegrateData(id);
        }

        var members = InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport
            ?.m_SmallGroupDataList?.m_AllMemeberData?.Members 
            ?? new List<Member>();

        // ...
    }
}
```

### 問題關鍵

**條件判斷不完整**:
```csharp
if (InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport == null || 
    !InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport.LoadFlag)
```

這個條件只檢查：
1. ? 資料是否為 null
2. ? 資料是否已載入

但**沒有檢查**:
3. ? 已載入的資料是否為當前請求的小組

### 問題場景

```
情況 1: 用戶點擊小組 A
    ↓
LoadEquipmentContact(id = "小組A的ID")
    ↓
檢查: m_ListSmallGroupWeeklyReport == null? → 是
    ↓
執行: SetupIntegrateData("小組A的ID")
    ↓
載入小組 A 的成員 → 正確 ?

情況 2: 用戶點擊小組 B
    ↓
LoadEquipmentContact(id = "小組B的ID")
    ↓
檢查: m_ListSmallGroupWeeklyReport == null? → 否（已有小組 A 的資料）
檢查: LoadFlag? → 是（小組 A 的資料已載入）
    ↓
跳過 SetupIntegrateData，直接使用現有資料
    ↓
返回小組 A 的成員（錯誤！應該是小組 B） ?
```

## ?? 修復方案

### 修復後的代碼

```csharp
[HttpGet]
public object LoadEquipmentContact(string id, DataSourceLoadOptions loadOptions)
{
    try
    {
        System.Diagnostics.Debug.WriteLine($"[LoadEquipmentContact] 開始載入聯絡人，小組ID={id}");

        // 修正: 添加小組 ID 檢查
        if (InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport == null || 
            !InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport.LoadFlag ||
            InMemoryContext.ListManager.ActiveListId != id)  // ? 新增條件
        {
            System.Diagnostics.Debug.WriteLine($"[LoadEquipmentContact] 需要重新載入資料，目前ActiveListId={InMemoryContext.ListManager.ActiveListId}，請求ID={id}");
            InMemoryContext.ListManager.SetupIntegrateData(id);
        }

        var members = InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport
            ?.m_SmallGroupDataList?.m_AllMemeberData?.Members 
            ?? new List<Member>();

        System.Diagnostics.Debug.WriteLine($"[LoadEquipmentContact] 取得成員數量={members.Count}");

        // 轉換為 EquipmentContact 清單
        var equipmentList = members.Select(m => new EquipmentContact
        {
            ContactFullName = m.FullName,
            EquipmentStatus = m.EquipmentStatus,
            EquipmentContactId = m.PresentRecordId,
            SmallGroupName = InMemoryContext.ListManager.LoginFullName ?? "",
            SmallGroupListEntityId = id,
            StorLessonsList = new List<EquipmentStorLessons>()
        }).ToList();

        System.Diagnostics.Debug.WriteLine($"[LoadEquipmentContact] 返回聯絡人數量={equipmentList.Count}，小組名稱={InMemoryContext.ListManager.LoginFullName}");

        return DataSourceLoader.Load(equipmentList, loadOptions);
    }
    catch (Exception e)
    {
        System.Diagnostics.Debug.WriteLine($"[LoadEquipmentContact] 錯誤: {e.Message}");
        return HandleError(e, "LoadEquipmentContact");
    }
}
```

### 關鍵修改

#### 1. 新增條件檢查

```csharp
// 修改前
if (InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport == null || 
    !InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport.LoadFlag)

// 修改後
if (InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport == null || 
    !InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport.LoadFlag ||
    InMemoryContext.ListManager.ActiveListId != id)  // ← 新增
```

**作用**: 確保當前載入的資料確實屬於請求的小組

#### 2. 添加詳細日誌

```csharp
System.Diagnostics.Debug.WriteLine($"[LoadEquipmentContact] 開始載入聯絡人，小組ID={id}");
System.Diagnostics.Debug.WriteLine($"[LoadEquipmentContact] 需要重新載入資料，目前ActiveListId={InMemoryContext.ListManager.ActiveListId}，請求ID={id}");
System.Diagnostics.Debug.WriteLine($"[LoadEquipmentContact] 取得成員數量={members.Count}");
System.Diagnostics.Debug.WriteLine($"[LoadEquipmentContact] 返回聯絡人數量={equipmentList.Count}，小組名稱={InMemoryContext.ListManager.LoginFullName}");
```

**作用**: 便於診斷和追蹤不同小組的資料載入情況

### 測試場景 1: 兩個小組切換

**步驟**:
1. 訪問 `/Equipment/EquipmentView`
2. 展開小組 A
3. 記錄顯示的成員名單
4. 折疊小組 A
5. 展開小組 B
6. 記錄顯示的成員名單
7. 比較兩個名單

**預期結果**:
- 小組 A 顯示小組 A 的成員
- 小組 B 顯示小組 B 的成員
- 兩個名單不同

**驗證方法**:
```javascript
// 在瀏覽器 Console 中執行
// 展開小組 A 後
var groupAMembers = [...document.querySelectorAll('.dx-data-row')]
    .map(row => row.textContent.trim());
console.log("小組 A 成員:", groupAMembers);

// 展開小組 B 後
var groupBMembers = [...document.querySelectorAll('.dx-data-row')]
    .map(row => row.textContent.trim());
console.log("小組 B 成員:", groupBMembers);

// 比較
console.log("是否相同:", JSON.stringify(groupAMembers) === JSON.stringify(groupBMembers));
// 應該輸出: 是否相同: false
```

### 測試場景 2: 三個小組循環切換

**步驟**:
1. 展開小組 A → 記錄成員
2. 展開小組 B → 記錄成員
3. 展開小組 C → 記錄成員
4. 再次展開小組 A → 記錄成員
5. 比較步驟 1 和步驟 4 的成員名單

**預期結果**:
- 步驟 1 和步驟 4 的小組 A 成員名單相同
- 小組 B 和 C 的成員名單與 A 不同

### 測試場景 3: 快速切換

**步驟**:
1. 快速連續展開/折疊不同小組
2. 觀察是否有資料混亂或錯誤

**預期結果**:
- 每次展開都顯示正確的小組成員
- 無資料混亂
- 無 JavaScript 錯誤

### 2. 緩存優化

目前每次切換小組都需要重新載入資料，可考慮：

```csharp
// 緩存多個小組的資料
private Dictionary<string, ListSmallGroupWeeklyReport> _groupDataCache 
    = new Dictionary<string, ListSmallGroupWeeklyReport>();

public object LoadEquipmentContact(string id, DataSourceLoadOptions loadOptions)
{
    if (!_groupDataCache.ContainsKey(id))
    {
        // 載入並緩存
        InMemoryContext.ListManager.SetupIntegrateData(id);
        _groupDataCache[id] = InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport;
    }
    else
    {
        // 使用緩存
        InMemoryContext.ListManager.m_ListSmallGroupWeeklyReport = _groupDataCache[id];
    }
    
    // ...
}
```

**優點**: 減少 CRM 查詢次數，提高切換速度  
**缺點**: 增加記憶體使用，資料可能過時
