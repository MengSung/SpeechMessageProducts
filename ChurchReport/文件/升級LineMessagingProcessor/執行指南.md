# LineMessagingProcessor 升級至 .NET 10 - 執行指南

## 概述

本文檔說明如何將 `LineMessagingProcessor` 專案從 .NET Framework 4.6.2 升級至 .NET 10。

## 升級內容

### 1. 專案檔案變更
- **舊格式**: .NET Framework 4.6.2 (舊式 .csproj 格式)
- **新格式**: .NET 10 (SDK-style .csproj 格式)

### 2. NuGet 套件更新
| 套件名稱 | 舊版本 | 新版本 | 變更說明 |
|---------|--------|--------|----------|
| Newtonsoft.Json | 13.0.4 | 13.0.3 | 維持相容性 |
| RestSharp | 105.2.3 | 112.1.0 | 重大 API 變更 |

### 3. 程式碼變更

#### RestSharp API 更新
舊版 RestSharp (105.2.3) 使用的 API 已過時，新版 (112.x) 有以下主要變更:

**舊 API (v105.x)**:
```csharp
RestClient restClient = new RestClient(@"https://api.line.me/v2/bot/message/push");
RestRequest restRequest = new RestRequest(Method.POST);
restClient.PostAsync(restRequest, (response, handle) => { });
```

**新 API (v112.x)**:
```csharp
var options = new RestClientOptions("https://api.line.me/v2/bot");
var restClient = new RestClient(options);
var request = new RestRequest("message/push");
await restClient.PostAsync(request);
```

#### 主要變更清單

1. **RestClient 初始化**
   - 使用 `RestClientOptions` 配置基礎 URL
   - 移除 `Method` 枚舉，直接使用方法如 `PostAsync()`, `GetAsync()`

2. **非同步方法**
   - 所有 HTTP 方法現在都是完全非同步的
   - 移除回調模式，改用 `async/await`

3. **回應處理**
   - `GetAsync()` 和 `PostAsync()` 直接返回 `RestResponse`
   - 使用 `response.IsSuccessful` 檢查成功狀態
   - 使用 `response.Content` 獲取回應內容

4. **JSON 處理**
   - 繼續使用 Newtonsoft.Json 進行反序列化
   - 使用 `JsonConvert.DeserializeObject<T>()` 處理回應

5. **IDisposable 模式**
   - RestSharp v112.x 的 `RestClient` 不再實現 `IDisposable`
   - 移除 Dispose 呼叫，但保留類別的 Dispose 模式以符合設計原則

## 執行步驟

### 前提條件
1. 關閉 Visual Studio
2. 確保已安裝 .NET 10 SDK

### 升級步驟

#### 方法 1: 使用 PowerShell 腳本 (推薦)

1. **開啟 PowerShell** (以系統管理員身分執行)

2. **導航至專案根目錄**:
   ```powershell
   cd "D:\網頁APP雲端線上版本\DevExpressDevExtreme-21.2.7版本\音訊產品版本\ChurchReport"
   ```

3. **執行升級腳本**:
   ```powershell
   .\ChurchReport\文件\升級LineMessagingProcessor\升級腳本.ps1
   ```

4. **重新開啟 Visual Studio**

5. **還原 NuGet 套件**:
   - 在 Visual Studio 中，右鍵點擊方案
   - 選擇「還原 NuGet 套件」

6. **重新建置專案**:
   ```
   建置 > 重建方案
   ```

#### 方法 2: 手動升級

1. **關閉 Visual Studio**

2. **備份舊專案檔案**:
   ```powershell
   Copy-Item "LineMessagingProcessor\LineMessagingProcessor.csproj" "LineMessagingProcessor\LineMessagingProcessor.csproj.backup"
   ```

3. **替換專案檔案**:
   ```powershell
   Remove-Item "LineMessagingProcessor\LineMessagingProcessor.csproj"
   Copy-Item "LineMessagingProcessor\LineMessagingProcessor_Net10.csproj" "LineMessagingProcessor\LineMessagingProcessor.csproj"
   ```

4. **刪除不需要的檔案**:
   - `LineMessagingProcessor\packages.config` (已刪除)
   - `LineMessagingProcessor\Properties\AssemblyInfo.cs` (已刪除)

5. **重新開啟 Visual Studio 並還原套件**

- `LineMessagingProcessorClass` 應透過 Factory 或 DI 容器管理生命週期

### 2. Dispose 模式
- 正確實現 `IDisposable` 介面

## 已知問題與解決方案

### 問題 1: RestSharp API 不相容
**症狀**: `Method.Post` 或 `Method.Get` 找不到定義

**解決方案**: 已更新為新 API，直接使用 `PostAsync()` 和 `GetAsync()` 方法

### 問題 2: C# 語言版本
**症狀**: CS8370 錯誤 - 無法使用可為 Null 的參考型別

**解決方案**: 專案檔案已設定 `<LangVersion>latest</LangVersion>` 和 `<Nullable>enable</Nullable>`

### 問題 3: 編碼問題
**症狀**: 繁體中文顯示亂碼

**解決方案**: 
- 專案檔案使用 UTF-8 編碼
- 所有 .cs 檔案使用 UTF-8 with BOM
- HTTP 請求指定 `charset=UTF-8`
