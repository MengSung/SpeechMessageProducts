## ?? Phase 1: HttpClient 記憶體洩漏修復 (P0) ? 已完成

### 1.1 問題說明

每次 `new HttpClient()` 都會創建新的 TCP 連接，導致：
- Socket 耗盡 (port exhaustion)
- 連接未能重用
- 記憶體持續增長

### 1.2 ? 已修復項目

- ? `Dispose()` 方法僅在內部建立的 HttpClient 時才釋放
- ? `CreateAsync` 靜態方法新增接受 `HttpClient` 的多載

```csharp
// ? 建議用法 - 使用 DI 注入的 HttpClient

{
    _client = httpClient ?? throw new ArgumentNullException(nameof(httpClient));
```

## ?? Phase 2: 事件訂閱洩漏修復 (P1) ? 已完成審計

### 2.1 問題說明

事件訂閱 (`+=`) 如果沒有對應的取消訂閱 (`-=`)，會導致：
- 訂閱者物件無法被 GC 回收
- 發布者持有訂閱者的強參考
- 長時間運行後記憶體持續增長

### 2.2 ? 審計結果

經過完整掃描，本專案**沒有使用傳統的 C# 事件訂閱模式**（`event EventHandler`）。

專案使用的是：
- **依賴注入模式**：透過建構函式注入 `LineMessagingClient`
- **虛擬方法模式**（Template Method Pattern）：如 `WebhookApplication.cs`
- **非同步方法**：直接呼叫 async/await 方法

### 2.3 ? 已修復項目

#### 2.3.1 ChurchReport\Tools\LineUtilityClass.cs
- ? 修正 `Dispose()` 方法，確保 `LineMessagingClient` 被正確釋放

```csharp
protected virtual void Dispose(bool disposing)
{
    if (_disposed) return;

    if (disposing)
    {
        // ? 釋放 ToolUtilityClass
        m_ToolUtilityClass?.Dispose();
        
        // ? 釋放 LineMessagingClient
        m_LineMessagingClient?.Dispose();
        
        // ? 釋放 ReplyUtility
        (m_ReplyUtility as IDisposable)?.Dispose();
    }

    _disposed = true;
}
```

### 2.4 ? 已驗證的正確實現

| 類別 | 狀態 | 說明 |
|-----|------|------|
| `PushUtility` | ? 正確 | 接收注入的 LineMessagingClient，不負責釋放 |
| `ReplyUtility` | ? 正確 | 接收注入的 LineMessagingClient，不負責釋放 |
| `WebhookApplication` | ? 正確 | 使用虛擬方法模式，無事件訂閱 |
| `LineMessagingProcessorClass` | ? 正確 | 已實現 IDisposable |

### 2.5 審計結論

原始審計報告中提到的「434 處事件訂閱」實際上是 `+=` 數值累加運算（如 `count += 1`），而非事件訂閱。本專案**不存在傳統的事件訂閱洩漏問題**。

## ?? Phase 7: .Result 阻塞風險修復 (P2)

### 7.1 問題說明

使用 `.Result` 或 `.Wait()` 會導致：
- 執行緒阻塞
- 死鎖風險
- 執行緒池耗盡

### 7.2 搜尋指令

```powershell
Get-ChildItem -Path "." -Recurse -Include *.cs | Select-String "\.Result" | Select-Object Path, LineNumber
Get-ChildItem -Path "." -Recurse -Include *.cs | Select-String "\.Wait\(" | Select-Object Path, LineNumber
```

### 7.3 修復模板

**? 錯誤寫法:**
```csharp
public void SyncMethod()
{
    var result = AsyncMethod().Result; // ?? 可能死鎖
}
```

**? 正確寫法 (選項 1 - 全非同步):**
```csharp
public async Task AsyncMethodWrapper()
{
    var result = await AsyncMethod(); // ? 正確的 async/await
}
```

**? 正確寫法 (選項 2 - 必須同步時):**
```csharp
public void SyncMethod()
{
    var result = Task.Run(async () => await AsyncMethod()).GetAwaiter().GetResult();
}
```

```csharp
private static void StartGCMonitoring()

    Task.Run(async () =>

        {
            await Task.Delay(TimeSpan.FromMinutes(10));
            
            var gen0 = GC.CollectionCount(0);
            var gen1 = GC.CollectionCount(1);
            var gen2 = GC.CollectionCount(2);
```
