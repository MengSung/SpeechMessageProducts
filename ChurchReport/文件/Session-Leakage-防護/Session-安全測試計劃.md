# Session 安全性測試計劃

## ?? 測試目標

驗證 Session Leakage 防護措施是否有效防止以下問題：
1. A 登入 WiFi → B 登入 WiFi 看到 A 網頁
2. Session 被後登入的人繼承/共用
3. LINE ID 登入相關頁面的安全性

---

## ?? 測試環境準備

### 必要條件
- [ ] 至少 2 台測試設備（或 2 個瀏覽器/無痕模式）
- [ ] 連接至同一個 WiFi 網路
- [ ] 準備 2-3 個測試帳號
- [ ] 準備 2-3 個 LINE ID 測試帳號
- [ ] 啟用 DEBUG 模式以查看詳細日誌

### 測試帳號範例
```
帳號 A: user_a / password_a
帳號 B: user_b / password_b
帳號 C: user_c / password_c

LINE ID A: U7638e4ed509708a3573ba6d69970583d
LINE ID B: U1234567890abcdef1234567890abcdef
LINE ID C: Uabcdef1234567890abcdef1234567890
```

## ?? 測試案例

### 測試組 1：基本 Session 隔離測試

#### TC-001: 一般帳號登入隔離測試
**目的**：驗證不同用戶登入後互不干擾

**步驟**：
1. **設備 A**：使用帳號 A 登入
   - 記錄顯示的用戶名稱、資料
2. **設備 B**（同 WiFi）：使用帳號 B 登入
   - 記錄顯示的用戶名稱、資料
3. **設備 A**：重新整理頁面
   - 驗證是否仍顯示帳號 A 的資料
4. **設備 B**：重新整理頁面
   - 驗證是否仍顯示帳號 B 的資料

**預期結果**：
- ? 設備 A 始終顯示帳號 A 的資料
- ? 設備 B 始終顯示帳號 B 的資料
- ? 無任何資料混淆或洩漏

#### TC-008: Session Fixation 攻擊模擬
**目的**：驗證系統是否能防禦 Session Fixation 攻擊

**步驟**：
1. **攻擊者**：訪問登入頁面，取得未登入的 Session ID
   ```
   攻擊者 Session ID: _____________________

3. **受害者**：使用攻擊者提供的 Session Cookie 登入
4. **攻擊者**：嘗試使用原本的 Session ID 訪問受害者的資料

**預期結果**：
- ? 受害者登入後，Session ID 改變

### 測試組 4：Session Hijacking 防護測試

#### TC-009: User-Agent 變更檢測
**目的**：驗證 User-Agent 變更時 Session 是否被清除

**步驟**：
1. 使用瀏覽器 A（Chrome）登入
2. 複製 Session Cookie
3. 使用瀏覽器 B（Firefox，不同 User-Agent）貼上 Session Cookie
4. 嘗試訪問需要登入的頁面

**預期結果**：
- ? 瀏覽器 B 被重導向至登入頁面
- ? DEBUG 日誌顯示「User-Agent 不一致」警告
- ? Session 被清除

**實際結果**：
```
[ ] 通過
[ ] 失敗（說明：_________________）
```

---

#### TC-010: Cookie 竊取模擬
**目的**：驗證即使 Cookie 被竊取，User-Agent 檢查也能防護

**步驟**：
1. **受害者**：正常登入（使用 Chrome）
2. **攻擊者**：竊取受害者的 Session Cookie
3. **攻擊者**：在不同設備/瀏覽器（Firefox）使用竊取的 Cookie
4. **驗證**：攻擊者是否能訪問受害者資料

**預期結果**：
- ? 攻擊者無法訪問（被重導向登入）
- ? SessionValidationMiddleware 檢測到異常
