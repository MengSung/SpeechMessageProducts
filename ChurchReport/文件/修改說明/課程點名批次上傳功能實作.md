# 課程點名批次上傳功能實作說明

## ?? 需求摘要

將課程點名頁面 (`PresentView.cshtml`) 的資料修改流程改為「先暫存修改，再批次上傳」的模式，而非原本的「即時更新資料庫」。

## ?? 實作目標

1. **延遲資料庫更新**: `PopulateObjectAndUpdateEntity` 不再立即呼叫 `UpdateFeeDataList` 更新資料庫
2. **暫存修改歷程**: 所有修改先存放在類似 ViewModel 的修改歷程中
3. **批次上傳**: 透過 `save-button` 按鈕觸發批次上傳到資料庫

#### 變更點 2: 修改 `PopulateObjectAndUpdateEntity` 方法

**原本**: 立即呼叫 `m_FeeDownUpLoader.UpdateFeeDataList()` 更新資料庫

**修改後**: 
1. 更新記憶體中的 `Fee` 物件
2. 呼叫 `ChangeHistory.RecordChange()` 記錄修改
3. **不立即更新資料庫**

```csharp
public void PopulateObjectAndUpdateEntity(string Values, Fee aFee)
{
    // ... (更新記憶體物件的程式碼)

    // ? 記錄修改到 ChangeHistory，而不直接更新資料庫
    ChangeHistory.RecordChange(aFee.StorLessonsId, Key, Value);

    // 處理特殊欄位的聯動邏輯 (僅更新記憶體物件)
    if (Key == "Amount" && !string.IsNullOrEmpty(Value) && Value != "0")
    {
        // 同時記錄聯動修改
        ChangeHistory.RecordChange(aFee.StorLessonsId, "PayDate", DateTime.Now.ToUniversalTime().ToString("u"));
        ChangeHistory.RecordChange(aFee.StorLessonsId, "PayWay", "現金");
    }
}
```

#### 變更點 3: 新增 `CommitPendingChanges` 方法

負責批次提交所有待處理的修改到資料庫:

```csharp
/// <summary>
/// 批次提交所有待處理的修改到資料庫
/// 由 save-button 觸發
/// </summary>
public int CommitPendingChanges()
{
    int successCount = 0;
    
    foreach (var changeRecord in ChangeHistory.PendingChanges.Values)
    {
        try
        {
            // 對每個欄位執行資料庫更新
            foreach (var field in changeRecord.ModifiedFields)
            {
                bool createFlag = false;
                m_FeeDownUpLoader.UpdateFeeDataList(
                    field.Key,      // 欄位名稱
                    field.Value,    // 新值
                    changeRecord.StorLessonsId, 
                    ref createFlag);
            }
            successCount++;
        }
        catch (Exception ex)
        {
            // 記錄錯誤，繼續處理其他記錄
        }
    }
    
    // 清除所有待處理的修改
    ChangeHistory.ClearAll();
    
    return successCount;
}
```

#### 變更點 2: 修改 `SaveBatch` 方法

### 4. 修改 `PresentView.cshtml` (前端介面)

**檔案位置**: `ChurchReport\Views\Home\PresentView.cshtml`

#### 變更點 1: 更新「上傳」按鈕的 OnClick 事件

**原本**: 呼叫 `SaveFeeManager` API

**修改後**: 
1. 檢查是否有待上傳的修改
2. 呼叫 `SaveBatch` API
3. 顯示上傳結果（包含更新筆數）
4. 重新載入資料

```javascript
.OnClick(@<text>
    function(arg) {
        var dataGrid = $("#FeeGridContainer").dxDataGrid("instance");
        var ButtonContainer = $("#save-button").dxButton("instance");

        // 先儲存 DataGrid 的所有編輯變更到本地
        dataGrid.saveEditData();

        // 檢查是否有待處理的變更
        if (!dataGrid.hasEditData()) {
            DevExpress.ui.notify("目前沒有需要上傳的資料變更", "info", 2000);
            return;
        }

        // 顯示載入面板
        $("#loadPanel").dxLoadPanel("instance").show();
        ButtonContainer.option("disabled", true);

        // AJAX 批次上傳
        $.ajax({
            url: '@Url.Action("SaveBatch", "FeeManagement")',
            type: 'POST',
            success: function (response) {
                $("#loadPanel").dxLoadPanel("instance").hide();
                ButtonContainer.option("disabled", false);

                if (response.status === "success") {
                    var message = "上傳成功! 已更新 " + response.count + " 筆記錄";
                    DevExpress.ui.notify(message, "success", 3000);
                    
                    // 清除待上傳修改記錄
                    clearPendingChanges();
                    
                    // 重新載入資料
                    dataGrid.refresh();
                } else {
                    DevExpress.ui.notify("上傳失敗: " + response.message, "error", 5000);
                }
            },
            error: function (xhr, status, error) {
                $("#loadPanel").dxLoadPanel("instance").hide();
                ButtonContainer.option("disabled", false);
                DevExpress.ui.notify("上傳時發生錯誤", "error", 5000);
            }
        });
    }
</text>)
```

#### 變更點 3: 新增 JavaScript 追蹤修改數量

```javascript
// 追蹤待上傳的修改數量
var pendingChangesMap = {}; // Key: StorLessonsId, Value: 修改的欄位集合

// 更新待上傳修改數量的顯示
function updatePendingChangesIndicator() {
    var count = Object.keys(pendingChangesMap).length;
    $("#pendingChangesCount").text(count);
    
    if (count > 0) {
        $("#pendingChangesIndicator").show();
    } else {
        $("#pendingChangesIndicator").hide();
    }
}

// 記錄資料修改
function recordDataChange(storLessonsId, fieldName) {
    if (!pendingChangesMap[storLessonsId]) {
        pendingChangesMap[storLessonsId] = new Set();
    }
    pendingChangesMap[storLessonsId].add(fieldName);
    updatePendingChangesIndicator();
}

// 清除所有待處理的修改記錄
function clearPendingChanges() {
    pendingChangesMap = {};
    updatePendingChangesIndicator();
}
```

## ?? 資料流程圖

### 修改前 (即時更新模式)

```
使用者編輯 DataGrid 單元格
    ↓
DevExtreme 觸發 UpdateFeeData API
    ↓
PopulateObjectAndUpdateEntity()
    ↓
UpdateFeeDataList() ← 立即更新資料庫 ?
    ↓
資料庫已更新
```

### 修改後 (批次上傳模式)

```
使用者編輯 DataGrid 單元格
    ↓
DevExtreme 觸發 UpdateFeeData API
    ↓
PopulateObjectAndUpdateEntity()
    ↓
ChangeHistory.RecordChange() ← 只記錄修改 ?
    ↓
記憶體中的 Fee 物件已更新，但資料庫未變更
    ↓
(重複上述流程，累積多筆修改)
    ↓
使用者按下「上傳」按鈕
    ↓
SaveBatch API
    ↓
FeeList.CommitPendingChanges()
    ↓
批次呼叫 UpdateFeeDataList() ← 一次性更新所有修改 ?
    ↓
資料庫批次更新完成
    ↓
清除 ChangeHistory
    ↓
重新載入 DataGrid
```

## ?? 效能影響分析

### 優點 ?

1. **減少資料庫連線次數**: 從「每次編輯 1 次連線」改為「批次上傳 1 次連線」
2. **提升使用者體驗**: 使用者可以連續編輯多筆資料，最後一次上傳
3. **降低網路延遲影響**: 不會因為網路慢而影響編輯流暢度

### 缺點 ??

1. **資料同步延遲**: 修改不會立即反映到資料庫（可接受，因為是刻意設計）
2. **記憶體佔用**: 需要額外記憶體儲存 `ChangeHistory`（影響極小）

### 適用場景 ??

- ? 適合: 需要連續編輯多筆資料的場景（例如: 課程點名）
- ? 適合: 網路環境不穩定，希望減少連線次數
- ? 不適合: 需要即時同步到資料庫的場景（例如: 金融交易）
