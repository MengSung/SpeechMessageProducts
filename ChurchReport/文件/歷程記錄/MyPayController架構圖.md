## ?? 模組化設計說明

### 獨立模組（無外部服務依賴）
```
MyPayMessageBuilder
└─ 純函數式設計
   └─ 輸入參數 → 輸出訊息字串
   └─ 無狀態、無副作用
```

### 輔助模組（僅依賴 Logger）
```
MyPayStatusHelper
├─ 狀態判斷邏輯
├─ 訊息轉換邏輯
└─ 時間解析邏輯

MyPayFeeTypeHelper
├─ 類型判斷邏輯
└─ 名稱轉換邏輯

MyPayLogger
└─ 日誌記錄邏輯
```

### 整合模組（依賴多個服務）
```
MyPayCrmService
├─ 依賴：StatusHelper
└─ 整合：CRM 操作 + 狀態轉換

MyPayNotificationService
├─ 依賴：MessageBuilder, StatusHelper, FeeTypeHelper
└─ 整合：訊息建立 + 狀態判斷 + LINE 發送
```

### 協調層（依賴所有服務）
```
MyPayController
├─ 依賴：所有服務
└─ 職責：API 端點 + 流程協調
```

## ?? 效能考量

### 同步 vs 異步
```
目前實作：同步處理
┌────────────┐
│金流回傳通知 │
└──────┬─────┘
       │
       ▼ (等待)
┌────────────┐
│驗證 + 處理  │
└──────┬─────┘
       │
       ▼ (等待)
┌────────────┐
│CRM 更新     │
└──────┬─────┘
       │
       ▼ (等待)
┌────────────┐
│LINE 發送    │
└──────┬─────┘
       │
       ▼
  回傳 "8888"

未來優化：異步處理
┌────────────┐
│金流回傳通知 │
└──────┬─────┘
       │
       ▼ (快速回應)
  回傳 "8888"
       │
       ├─? 背景處理 ──┬─? CRM 更新
       │              └─? LINE 發送
       │
   (不阻塞)
```
