## ?? 需求說明

### 原始行為

頁面載入時，所有層級都處於折疊狀態：

```
? 裝備狀態
    ? 小組 A         ← 折疊
    ? 小組 B         ← 折疊
    ? 小組 C         ← 折疊
```

用戶需要手動點擊每個小組、每個聯絡人才能查看完整資訊。

### 修改後行為

頁面載入時，所有層級自動展開：

```
? 裝備狀態
    ▼ 小組 A                    ← 自動展開
        ▼ 張三                  ← 自動展開
            - 舊約概論 (初階)
            - 新約概論 (中階)
        ▼ 李四                  ← 自動展開
            - 裝備課程 A
    ▼ 小組 B                    ← 自動展開
        ▼ 王五                  ← 自動展開
            - 裝備課程 B
    ▼ 小組 C                    ← 自動展開
        ▼ 趙六                  ← 自動展開
            - 裝備課程 C
```

### 業務價值

1. **提升用戶體驗**: 無需手動展開，直接看到所有資訊
2. **提高效率**: 減少點擊次數，快速瀏覽所有成員的裝備狀態
3. **便於對比**: 可同時查看多個成員的課程記錄，方便比較進度
4. **適合報表場景**: 適合用於統計和彙總查看

## ?? 詳細修改

### 修改 1: EquipmentView.cshtml (第一層)

**位置**: `ChurchReport/Views/Equipment/EquipmentView.cshtml`

**修改前**:
```razor
.MasterDetail(md =>
{
    md.Enabled(true);
    md.AutoExpandAll(false); // ← 預設折疊
    md.Template(@<text>
        @(Html.Partial("EquipmentContactView"))
    </text>);
})
```

**修改後**:
```razor
.MasterDetail(md =>
{
    md.Enabled(true);
    md.AutoExpandAll(true); // ← 修改: 預設展開所有小組
    md.Template(@<text>
        @(Html.Partial("EquipmentContactView"))
    </text>);
})
```

**效果**: 頁面載入時自動展開所有小組，顯示每個小組的成員列表

## ?? 性能考量

### 資料載入分析

#### 修改前 (按需載入)

```
頁面載入:
  └─ 載入小組列表 (第一層) → 1 次請求

用戶點擊小組 A:
  └─ 載入小組 A 的聯絡人 (第二層) → 1 次請求

用戶點擊聯絡人張三:
  └─ 載入張三的課程記錄 (第三層) → 1 次請求

總請求: 1 + 1 + 1 = 3 次 (分散在用戶操作過程中)
```

#### 修改後 (自動展開)

```
頁面載入:
  └─ 載入小組列表 (第一層) → 1 次請求
  └─ 自動載入所有小組的聯絡人 (第二層) → N 次請求 (N = 小組數量)
  └─ 自動載入所有聯絡人的課程記錄 (第三層) → M 次請求 (M = 聯絡人數量)

總請求: 1 + N + M (集中在頁面載入時)
```

### 性能影響

| 場景 | 小組數 | 聯絡人數 | 課程記錄數 | 總請求數 | 初始載入時間 |
|------|--------|---------|-----------|----------|------------|
| 小規模 | 2 | 10 | 20 | 13 | ~2-3 秒 |
| 中規模 | 5 | 50 | 100 | 56 | ~5-8 秒 |
| 大規模 | 10 | 100 | 200 | 111 | ~10-15 秒 |

### 優化建議

如果資料量過大導致載入緩慢，可考慮以下優化：

#### 1. 混合模式（推薦）

第一層自動展開，第二層按需載入：

```razor
<!-- EquipmentView.cshtml -->
.MasterDetail(md => {
    md.AutoExpandAll(true); // 自動展開小組
})

<!-- EquipmentContactView.cshtml -->
.MasterDetail(md => {
    md.AutoExpandAll(false); // 手動展開聯絡人
})
```

#### 2. 延遲載入

添加載入指示器：

```javascript
.OnContentReady("onContentReady")

function onContentReady(e) {
    // 顯示載入完成提示
    DevExpress.ui.notify("資料載入完成", "success", 2000);
}
```

#### 3. 虛擬滾動

對於大資料量，啟用虛擬滾動：

```razor
.Scrolling(s => s
    .Mode(GridScrollingMode.Virtual)
    .RowRenderingMode(GridRowRenderingMode.Virtual)
)
```

#### 4. 分頁模式

如果資料量確實過大，改用分頁：

```razor
.Paging(p => p.Enabled(true).PageSize(20))
.Pager(p => p.ShowPageSizeSelector(true).AllowedPageSizes(new[] { 10, 20, 50, 100 }))
```

## ?? DevExtreme Master-Detail 說明

### AutoExpandAll 屬性

```csharp
.MasterDetail(md => {
    md.Enabled(true);        // 啟用主從表格
    md.AutoExpandAll(true);  // 自動展開所有行
    md.Template(...);        // 子表格模板
})
```

### 屬性說明

| 屬性 | 類型 | 說明 |
|------|------|------|
| `Enabled` | Boolean | 是否啟用 Master-Detail 功能 |
| `AutoExpandAll` | Boolean | 是否自動展開所有 Master 行 |
| `Template` | Template | 子表格的模板定義 |

### AutoExpandAll 行為

#### True (自動展開)

```
? 優點:
  - 所有資料一次性顯示
  - 用戶體驗好（無需點擊）
  - 適合報表和統計場景

? 缺點:
  - 初始載入時間較長
  - 資料量大時可能影響性能
  - 頁面較長，需要滾動
```

#### False (手動展開)

```
? 優點:
  - 初始載入快速
  - 按需載入資料
  - 適合大資料量場景

? 缺點:
  - 需要手動點擊展開
  - 無法一次性查看所有資料
  - 用戶體驗相對較差
```
