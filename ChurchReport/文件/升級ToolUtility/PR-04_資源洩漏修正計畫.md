# PR-04: 移除 ctor 開啟長期 FileStream 與 TraceListener，改為 ILogger 注入

## 執行摘要

根據 PR-02 高風險掃描報告，`ToolUtilityClass` 在建構式中開啟了長期的 `FileStream` / `StreamWriter` / `TraceListener`，且未在 `Dispose` 方法中正確關閉，這會導致：
- 記憶體洩漏
- 檔案鎖定（無法刪除或修改 trace 檔案）
- 資源耗盡（長期執行會累積未釋放的句柄）

此 PR 將進行以下改造：
1. 移除 ctor 中的 FileStream/StreamWriter/TraceListener
2. 注入 `ILogger<ToolUtilityClass>`
3. 同時注入 `ICrmClient`（可選，向後相容）
4. 修正 `Dispose` 方法

---

## 改造方案

### 方案 A: 激進式（推薦 - 完全移除）

完全移除 FileStream trace，改用 `ILogger<T>`：

#### 優點
- ? 完全解決資源洩漏
- ? 符合 .NET Core / .NET 10 最佳實務
- ? 可配置（appsettings.json）
- ? 支援多種 provider（Console / File / EventLog / Azure Application Insights）
- ? 結構化日誌（可查詢、可分析）

#### 缺點
- ?? 需要調整所有 `TraceByLevel` 呼叫（約 50+ 處）
- ?? 暫時失去 Big5 編碼支援（但 UTF-8 更通用）

#### 實作步驟
1. 加入 `Microsoft.Extensions.Logging` NuGet 套件
2. 新增 `ILogger<ToolUtilityClass>` 欄位與建構參數
3. 改寫 `TraceByLevel` 使用 `ILogger`
4. 移除所有 FileStream / TraceListener 相關程式碼
5. 修正 `Dispose` 方法

---

### 方案 B: 保守式（短期保留，逐步遷移）

保留舊的 trace 機制，但修正 Dispose：

#### 優點
- ? 不影響現有呼叫
- ? 小步驟改動

#### 缺點
- ? 仍有硬編碼路徑問題
- ? 仍有 Big5 編碼問題
- ? 未達到現代化目標

#### 實作步驟
1. 修正 `Dispose` 方法：關閉 FileStream / StreamWriter / TraceListener
2. 改為需要時才開啟（Lazy initialization）
3. 路徑改為可配置

## 採用方案 A（推薦）

### 新的建構式設計

```csharp
// 支援 DI 注入
public ToolUtilityClass(
    ILogger<ToolUtilityClass> logger = null,
    ICrmClient crmClient = null,
    IConfiguration configuration = null)
{
    _logger = logger ?? NullLogger<ToolUtilityClass>.Instance;
    _crmClient = crmClient;
    _configuration = configuration;

    // 向後相容：若未注入 CrmClient，使用舊方式（暫時）
    if (_crmClient == null)
    {
        // TODO: 從 configuration 讀取連線資訊（移除硬編碼）
        var connectionInfo = GetConnectionInfo();
        m_Crm2011OrganizationService = new OnPremiseClient(
            connectionInfo.Url,
            connectionInfo.Username,
            connectionInfo.Password
        );
    }
}

// 舊的無參數建構式（向後相容，標註為 Obsolete）
[Obsolete("Please use constructor with ILogger injection")]
public ToolUtilityClass() : this(null, null, null)
{
}
```

### 改寫 TraceByLevel

```csharp
public void TraceByLevel(int totalLevel, int qualifiedLevel, string message)
{
    if (totalLevel < qualifiedLevel) return;

    // 使用結構化日誌
    _logger?.LogDebug(
        "Level {QualifiedLevel}/{TotalLevel}: {Message}. StackTrace: {StackTrace}",
        qualifiedLevel,
        totalLevel,
        message,
        new StackTrace(new StackFrame(1, true)).ToString()
    );
}
```

### 修正 Dispose

```csharp
protected virtual void Dispose(bool disposing)
{
    if (_disposed) return;

    if (disposing)
    {
        // 釋放 managed 資源
        _crmClient?.Dispose();
        
        // 舊的 service（若有）
        if (m_OrganizationService is IDisposable disposableOrgService)
        {
            disposableOrgService.Dispose();
        }

        // ILogger 由 DI 容器管理，不需手動 dispose
    }

    _disposed = true;
}
```
