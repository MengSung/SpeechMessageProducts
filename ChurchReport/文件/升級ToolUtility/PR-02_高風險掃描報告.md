# PR-02: ToolUtility 高風險模式掃描報告

**掃描日期**: 2024-01-XX  
**目標專案**: ToolUtility (.NET Framework 4.6.2)  
**掃描範圍**: `ToolUtility\ToolUtilityClass.cs`

---

## 一、執行摘要

本報告針對 `ToolUtilityClass.cs` 進行靜態程式碼掃描，識別出 **8 大類高風險模式**，共計 **超過 50 處** 需要立即修正的問題。這些問題將嚴重影響升級到 .NET 10 的可行性、安全性與資源管理。

### 風險等級分類
- **?? Critical (嚴重)**: 必須立即處理，否則無法升級或造成嚴重資源洩漏
- **?? High (高)**: 升級後可能導致執行錯誤或性能問題
- **?? Medium (中)**: 需要改善以符合現代實務

---

## 二、高風險模式清單

### 1. ?? 資源洩漏 - FileStream / StreamWriter / TraceListener

**風險等級**: Critical  
**影響**: 記憶體洩漏、檔案鎖定、無法回收資源

#### 發現位置

| 行號 | 類型 | 問題描述 |
|------|------|----------|
| 114-118 | FileStream/StreamWriter | 在 ctor 中開啟但未正確 dispose |
| 127-132 | ctor | 建構式中建立長期 FileStream 並加入 Debug.Listeners |
| 207-218 | Dispose | Dispose 方法未關閉 FileStream/StreamWriter/TraceListener |

#### 程式碼片段
```csharp
// 行 114-118: 宣告但未釋放
private FileStream m_XmlFileStream;
private StreamWriter m_XmlFileStreamWriter;
private const String TRACE_DIRECTOR = @"D:\除錯追蹤\CHURCH_REPORT_TRACE.TXT";

// 行 127-132: 在 ctor 開啟
m_XmlFileStream = new FileStream(m_TraceLogFile, FileMode.Append, FileAccess.Write, FileShare.ReadWrite);
m_XmlFileStreamWriter = new StreamWriter(m_XmlFileStream, Encoding.GetEncoding("big5"));
m_Listener = new BugslayerTextWriterTraceListener(m_XmlFileStreamWriter);
Debug.AutoFlush = true;
Debug.Listeners.Add(m_Listener);

// 行 207-218: Dispose 未正確關閉
protected virtual void Dispose(bool disposing)
{
    if (_disposed) return;
    // Free any unmanaged objects here.
    //this.m_OrganizationService.Dispose(); // 註解掉
    _disposed = true;
}
```

#### 建議修正
1. **移除 ctor 中的 FileStream 建立**，改為需要時才開啟
2. **在 Dispose 中正確關閉**：
   ```csharp
   protected virtual void Dispose(bool disposing)
   {
       if (_disposed) return;
       if (disposing)
       {
           m_XmlFileStreamWriter?.Dispose();
           m_XmlFileStream?.Dispose();
           if (m_Listener != null)
           {
               Debug.Listeners.Remove(m_Listener);
               m_Listener.Dispose();
           }
       }
       _disposed = true;
   }
   ```
3. **改用 ILogger 注入**，完全移除自訂 FileStream trace

### 2. ?? 硬編碼憑證與敏感資訊

**風險等級**: Critical  
**影響**: 安全漏洞、憑證外洩

#### 發現位置

| 行號 | 類型 | 明碼內容 |
|------|------|----------|
| 52-54 | 常數 | `USERNAME = "Administrator@speechmessage.com.tw"` |
| 53 | 常數 | `PASSWORD = "hu9840"` |
| 54 | 常數 | `DOMAIN = "DYNAMICS-365"` |
| 141-143 | ctor | `var adUsername = @"SPEECHMESSAGE\Administrator";`<br/>`var adPassword = "hu9840";` |
| 178-180 | ctor | 重複硬編碼相同憑證 |

#### 程式碼片段
```csharp
// 行 52-54
private const String USERNAME = "Administrator@speechmessage.com.tw";
private const String PASSWORD = "hu9840";
private const String DOMAIN = "DYNAMICS-365";

// 行 141-143
var adUrl = "https://" + ORGANIZATION + ".speechmessage.com.tw/XRMServices/2011/Organization.svc";
var adUsername = @"SPEECHMESSAGE\Administrator";
var adPassword = "hu9840";
```

#### 建議修正
1. **立即移除所有硬編碼憑證**
2. **改用配置來源**：
   - appsettings.json
   - 環境變數
   - Azure Key Vault / User Secrets
3. **實作 `ICrmCredentialProvider` 介面**：
   ```csharp
   public interface ICrmCredentialProvider
   {
       string GetUsername();
       string GetPassword();
       string GetDomain();
   }
   ```

### 3. ?? OrganizationServiceProxy (WCF) - 不支援 .NET 10

**風險等級**: Critical  
**影響**: .NET 10 不支援 WCF，無法編譯

#### 發現位置

| 行號 | 類型 | 問題描述 |
|------|------|----------|
| 43 | 欄位 | `public OrganizationServiceProxy m_OrganizationService;` |
| 252-264 | 方法 | `GetOrganizationService()` 使用 OrganizationServiceProxy |
| 288-302 | 方法 | `SetOrganizationService()` |
| 各處 | 使用 | 超過 30 處使用 `m_OrganizationService` |

#### 程式碼片段
```csharp
// 行 43
public OrganizationServiceProxy m_OrganizationService;

// 行 288-302
using (loServiceProxy = new OrganizationServiceProxy(loOrgConfigInfo, loCreds))
{
    loServiceProxy.ServiceConfiguration.CurrentServiceEndpoint.Behaviors.Add(new ProxyTypesBehavior());
    m_Crm2011OrganizationService = (IOrganizationService)loServiceProxy;
}
```

#### 建議修正
1. **新增 `ICrmClient` 介面**：
   ```csharp
   public interface ICrmClient
   {
       Guid Create(Entity entity);
       void Update(Entity entity);
       void Delete(string entityName, Guid id);
       Entity Retrieve(string entityName, Guid id, ColumnSet columnSet);
       EntityCollection RetrieveMultiple(QueryBase query);
       OrganizationResponse Execute(OrganizationRequest request);
   }
   ```
2. **實作 `DataverseServiceClientAdapter`**（使用 `ServiceClient`）
3. **實作 `LegacyOrganizationAdapter`**（短期保留相容）
4. **在 `ToolUtilityClass` 注入 `ICrmClient`**

### 4. ?? 硬編碼檔案路徑 (D:\)

**風險等級**: High  
**影響**: 跨平台失敗、容器環境失敗

#### 發現位置

| 行號 | 類型 | 路徑 |
|------|------|------|
| 116 | 常數 | `@"D:\除錯追蹤\CHURCH_REPORT_TRACE.TXT"` |

#### 建議修正
1. 改為可配置路徑：
   ```csharp
   private string GetLogFilePath()
   {
       var baseDir = Configuration["LogDirectory"] ?? Path.Combine(AppContext.BaseDirectory, "Logs");
       Directory.CreateDirectory(baseDir);
       return Path.Combine(baseDir, "CHURCH_REPORT_TRACE.TXT");
   }
   ```
2. 使用相對路徑或 `ILogger` provider

### 5. ?? 硬編碼 Encoding.GetEncoding("big5")

**風險等級**: High  
**影響**: 跨平台編碼問題、可能拋出 NotSupportedException

#### 發現位置

| 行號 | 類型 | 問題描述 |
|------|------|----------|
| 128 | ctor | `Encoding.GetEncoding("big5")` |
| 154 | ctor | 註解中也有 big5 |

#### 程式碼片段
```csharp
// 行 128
m_XmlFileStreamWriter = new StreamWriter(m_XmlFileStream, Encoding.GetEncoding("big5"));
```

#### 建議修正
1. **改用 UTF-8**：
   ```csharp
   new StreamWriter(m_XmlFileStream, new UTF8Encoding(false)) // BOM-less UTF-8
   ```
2. 若必須 Big5，使用 `System.Text.Encoding.RegisterProvider(CodePagesEncodingProvider.Instance);` 並加入 NuGet 套件 `System.Text.Encoding.CodePages`

### 6. ?? 缺少 async 支援

**風險等級**: Medium  
**影響**: 可擴展性、效能

#### 發現位置

| 方法數量 | 類型 | 問題描述 |
|----------|------|----------|
| 150+ | 同步方法 | 所有 Retrieve/Update/Create/Delete 都是同步 |
| 1 | async | 僅 `CreateEntityAsync` / `UpdateEntityAsync` (但實作仍為同步) |

#### 程式碼片段
```csharp
// 行 3742-3753: 假 async
public async Task<Guid> CreateEntityAsync(IOrganizationService aOrganizationService, Entity aEntityTobeToCreate)
{
    try
    {
        if (EXCUTION_FLAG == true)
        {
            return aOrganizationService.Create(aEntityTobeToCreate); // 仍為同步！
        }
    }
    catch { ... }
}
```

#### 建議修正
1. 使用 `IOrganizationServiceAsync` (Dataverse SDK 支援)
2. 改寫為真正非同步：
   ```csharp
   public async Task<Guid> CreateEntityAsync(IOrganizationServiceAsync service, Entity entity, CancellationToken ct = default)
   {
       return await service.CreateAsync(entity, ct);
   }
   ```

### 7. ?? 大量註解與未使用程式碼

**風險等級**: Medium (技術債)  
**影響**: 可維護性

#### 發現位置
- 大量 `//lock (...)` 註解 (超過 100 處)
- 未使用的 overload 方法
- 重複的 Dynamics365/CRM2011 分支

#### 建議修正
1. 清理所有註解的 lock
2. 移除未使用的多載
3. 用策略模式取代 `if (CRM_TYPE == "DYNAMICS365")` 分支

---

### 8. ?? 缺少 Null 檢查與錯誤處理

**風險等級**: Medium  
**影響**: 潛在 NullReferenceException

#### 發現模式
- 多數方法未檢查參數 null
- Entity attribute 取值未先檢查 `Contains`
- 例外處理僅 throw，未記錄或回復

#### 建議修正
1. 啟用 Nullable Reference Types (C# 8+)
2. 加入參數驗證：
   ```csharp
   public Entity Retrieve(string entityName, Guid id)
   {
       if (string.IsNullOrWhiteSpace(entityName))
           throw new ArgumentException("Entity name cannot be null or empty", nameof(entityName));
       if (id == Guid.Empty)
           throw new ArgumentException("Entity ID cannot be empty", nameof(id));
       // ...
   }
   ```
3. 使用 Polly 加入 retry / circuit breaker
