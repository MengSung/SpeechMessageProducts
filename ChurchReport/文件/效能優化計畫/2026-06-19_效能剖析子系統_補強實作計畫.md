## Task 1 ⭐（最高優先）：修補 F-1 — FeeManagement 去重的登入綁定

> **風險背景**：`FeeList` 以 Session ID 為鍵存於 `IMemoryCache`（`Models/InMemoryDataContextSmallGroup.cs:978-982`）。登入流程用 `HttpContext.Session.Clear()`（`BaseChurchController.cs:940`）清的是 session **資料**、**不換 Session ID** → 同瀏覽器換帳號時，前一位使用者的 `FeeList`（含 `FeeDataList`、`LoadedPresentDiscipleLessonsId`）仍在快取中。現行 `IsPresentFeeListLoadedFor(discipleLessonsId)` 無登入綁定、`EnsureLessonListLoaded` 又自 `FeeList.m_Account` 取值自我比較 → 可能重用到別人的資料。

### Step 1: `FeeList` 新增 `EnsureLoginScope`（登入改變即清空，不打 CRM）

**File:** `Models/FeeList.cs`（在既有 `private void ClearUserScopedFeeData()`（約 :214）**之後**插入）

- [ ] 插入下列方法：

```csharp
        /// <summary>
        /// 以「當前 session 真實登入身分」校準本 FeeList 的資料範圍。
        /// 若登入身分與目前已載入資料的身分不同，立即清空所有使用者範圍資料（不觸發 CRM），
        /// 並把身分更新為當前登入者。用於防止「同一 Session ID 換帳號」時重用前一位使用者的資料。
        /// </summary>
        public void EnsureLoginScope(string account, string password)
        {
            if (!IsSameLogin(account ?? "", password ?? ""))
            {
                ClearUserScopedFeeData();
                m_Account = account ?? "";
                m_Password = password ?? "";
            }
        }
```

> `IsSameLogin`（`FeeList.cs:208`）為 private，但 `EnsureLoginScope` 同類別內可呼叫。`m_Account/m_Password` 為 public 欄位。`ClearUserScopedFeeData` 會清 `LessonList/FeeDataList/_lessonListLoaded/LoadedPresentDiscipleLessonsId/...`（`FeeList.cs:214-224`）。

### Step 2: 控制器改以 session 真實登入身分判斷重用

**File:** `Controllers/FeeManagementController.cs`（取代既有 `EnsureLessonListLoaded`（:410）與 `EnsurePresentFeeListLoaded`（:427）兩方法）

- [ ] 以下列**完整內容**取代這兩個方法（並在其上方新增 `CurrentLogin()` 私有輔助）：

```csharp
        /// <summary>
        /// 取得「當前 session 真實登入身分」。權威來源為登入時寫入的 session 鍵
        /// _LoginAccount / _LoginPassword（帳密登入＝帳號/密碼；LINE 登入＝ "LineIdLogin" / lineUserId）。
        /// 切勿改用 FeeList.m_Account 自身欄位（會造成自我比較、恆真，使換登入偵測失效）。
        /// </summary>
        private (string account, string password) CurrentLogin()
            => (HttpContext?.Session?.GetString("_LoginAccount") ?? "",
                HttpContext?.Session?.GetString("_LoginPassword") ?? "");

        private void EnsureLessonListLoaded(string phaseName)
        {
            var (account, password) = CurrentLogin();

            // 安全：換登入身分即清空前一位使用者的資料
            InMemoryContext.FeeList.EnsureLoginScope(account, password);

            if (InMemoryContext.FeeList.IsLessonListLoadedFor(account, password))
            {
                System.Diagnostics.Debug.WriteLine("[FeeManagement] Reuse LessonList for current login.");
                return;
            }

            using (PerfPhase.Measure(HttpContext, phaseName))
            {
                InMemoryContext.FeeList.SetupLessonList(account, password);
            }
        }

        private void EnsurePresentFeeListLoaded(string discipleLessonsId, string phaseName)
        {
            var (account, password) = CurrentLogin();

            // 安全：先以當前登入身分校準範圍。換登入時 EnsureLoginScope 會清掉 FeeDataList，
            // 使下面的 IsPresentFeeListLoadedFor 不可能命中前一位使用者的資料。
            InMemoryContext.FeeList.EnsureLoginScope(account, password);

            if (InMemoryContext.FeeList.IsPresentFeeListLoadedFor(discipleLessonsId))
            {
                System.Diagnostics.Debug.WriteLine($"[FeeManagement] Reuse PresentFeeList for discipleLessonsId={discipleLessonsId}");
                return;
            }

            using (PerfPhase.Measure(HttpContext, phaseName))
            {
                InMemoryContext.FeeList.SetupPresentFeeList(discipleLessonsId);
            }
        }
```

> **效果**：同一使用者重複載入 → `IsSameLogin` 為真、不清空、重用照舊（保留 P2 效能效益）。換帳號/換 LINE 使用者（即使 Session ID 不變）→ `EnsureLoginScope` 清空 → 重用判斷不命中 → 為新使用者重載。**跨使用者重用被關閉。**

## Task 2：修補 F-2 — 讓 `PerfPhase` 在 Release 真正零額外開銷

### Step 1: 以 `readonly struct` 重寫 `PerfPhase`，移除 `Func<T>` 重載

**File:** `Diagnostics/Profiling/PerfPhase.cs`（以下列**完整內容**取代整檔）

```csharp
using System;
using Microsoft.AspNetCore.Http;

namespace ChurchReport.Diagnostics.Profiling
{
    /// <summary>
    /// 控制器端 phase 計時的呼叫點包裝。
    /// Release：Measure 回傳 default(PerfScope)（readonly struct、Dispose 為空 → JIT 內聯消除），
    ///          且不提供 Func 重載 → 呼叫點不會配置 closure → 真正零額外開銷。
    /// Debug ：委派 RequestProfiler.MeasurePhase（仍受 ProfilingSwitch 控制）。
    /// 用法一律為 using 區塊：using (PerfPhase.Measure(HttpContext, "Name")) { ... }
    /// </summary>
    public static class PerfPhase
    {
        public static PerfScope Measure(HttpContext context, string name)
        {
#if DEBUG
            return new PerfScope(RequestProfiler.MeasurePhase(context, name));
#else
            return default;
#endif
        }
    }

    /// <summary>phase 計時範圍。Release 下為空殼 struct（零配置、Dispose 被 JIT 消除）。</summary>
    public readonly struct PerfScope : IDisposable
    {
#if DEBUG
        private readonly IDisposable _inner;
        internal PerfScope(IDisposable inner) { _inner = inner; }
        public void Dispose() => _inner?.Dispose();
#else
        public void Dispose() { }
#endif
    }
}
```

> `RequestProfiler.MeasurePhase` 已存在且為 `#if DEBUG`（`RequestProfiler.cs:39-50`），Release 不被參照。`using` 形式呼叫點（約 34 處）因回傳值型別由 `IDisposable` 改為 `PerfScope`（struct）→ Release 不裝箱、Dispose 為空 → 零配置。

### Step 2: 將所有 `Func<T>` 呼叫點改為 `using` 區塊形式

> **轉換規則（機械式）**：
> `var x = PerfPhase.Measure(ctx, "N", () => Expr);` → `T x; using (PerfPhase.Measure(ctx, "N")) { x = Expr; }`
> `return PerfPhase.Measure(ctx, "N", () => Expr);` → `using (PerfPhase.Measure(ctx, "N")) { return Expr; }`
> Expr 為多行時，把整段搬進 `using { }`，並把原 lambda 的 `return`/結果指派照搬。**phase 名稱字串保持不變。**

**範例 A（指派型）— `PersonalController.cs:485`**
```csharp
// before
                var contactCollection = PerfPhase.Measure(HttpContext, phaseName, () =>
                    ToolUtility.m_Crm2011OrganizationService.RetrieveMultiple(query));
// after
                Microsoft.Xrm.Sdk.EntityCollection contactCollection;
                using (PerfPhase.Measure(HttpContext, phaseName))
                {
                    contactCollection = ToolUtility.m_Crm2011OrganizationService.RetrieveMultiple(query);
                }
```

**範例 B（return 型、迴圈內）— `EquipmentController.cs:365`（`RetrieveDiscipleLesson`）**
```csharp
// before
                                var discipleLesson = PerfPhase.Measure(HttpContext, "Equipment.LoadEquipmentStorLessons.RetrieveDiscipleLesson", () =>
                                    ToolUtility.RetrieveEntity("new_disciple_lessons", discipleLessonId));
// after
                                Microsoft.Xrm.Sdk.Entity discipleLesson;
                                using (PerfPhase.Measure(HttpContext, "Equipment.LoadEquipmentStorLessons.RetrieveDiscipleLesson"))
                                {
                                    discipleLesson = ToolUtility.RetrieveEntity("new_disciple_lessons", discipleLessonId);
                                }
```

## Task 3：補蓋章 — Release 無痕（DLL `[Perf` 掃描）+ Trace.log 不變量

### Step 1: 新增驗證腳本

**File:** Create `Tools\verify-release-noperf.ps1`

```powershell
# 驗證 Release 組件「無痕」：不得含任何 [Perf 字串（剖析輸出全在 #if DEBUG）。
# 用法：powershell -File Tools\verify-release-noperf.ps1
$ErrorActionPreference = "Stop"
$proj = "ChurchReport\ChurchReport.csproj"

Write-Host "==> dotnet build -c Release" -ForegroundColor Cyan
dotnet build $proj -c Release --nologo -v minimal
if ($LASTEXITCODE -ne 0) { throw "Release build failed." }

$dll = Get-ChildItem -Path "ChurchReport\bin\Release" -Recurse -Filter "ChurchReport.dll" |
       Sort-Object LastWriteTime -Descending | Select-Object -First 1
if (-not $dll) { throw "ChurchReport.dll (Release) not found." }

$bytes = [IO.File]::ReadAllBytes($dll.FullName)
$u = [Text.Encoding]::Unicode.GetString($bytes)
$a = [Text.Encoding]::ASCII.GetString($bytes)
$hit = $u.Contains("[Perf") -or $a.Contains("[Perf")

Write-Host ("DLL: " + $dll.FullName)
if ($hit) {
    Write-Host "[FAIL] Release DLL contains '[Perf' — 剖析字串外洩到 Release！" -ForegroundColor Red
    exit 1
} else {
    Write-Host "[PASS] Release DLL 無 '[Perf' 字串（無痕通過）。" -ForegroundColor Green
}
```
