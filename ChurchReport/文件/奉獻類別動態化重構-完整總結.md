# 奉獻類別動態化重構 - 完整總結

## ?? 重構目標

將所有奉獻相關頁面中硬編碼的奉獻類別清單改為動態從 Dynamics 365 的 `new_fee.new_category` OptionSet 取得，實現真正的「不寫死程式碼」。

## ? 已完成的重構

### 1. **核心服務層** - `OptionSetMetadataService`

**檔案**: `ChurchReport/Services/OptionSetMetadataService.cs`

#### 主要功能
- 動態查詢 Dynamics 365 OptionSet Metadata API
- 支援快取機制（24 小時）
- 支援多語言（優先繁體中文）
- 允許 `logger` 和 `cache` 參數為 null（使用預設值）

#### 主要方法
```csharp
// 取得 OptionSet 對應表（顯示文字 → 值）
Dictionary<string, int> GetOptionSetMapping(string entityName, string attributeName)

// 根據顯示文字取得 OptionSet 值
int GetOptionSetValue(string entityName, string attributeName, string displayText, int? defaultValue = null)

// 根據 OptionSet 值取得顯示文字（反向查詢）
string GetOptionSetText(string entityName, string attributeName, int optionSetValue)

// 清除快取
void ClearCache(string entityName, string attributeName)
```

#### 修正的問題
? 解決了 `logger` 參數不能為 null 的問題
```csharp
// 修正前
_logger = logger ?? throw new ArgumentNullException(nameof(logger));

// 修正後
_logger = logger ?? Microsoft.Extensions.Logging.Abstractions.NullLogger<OptionSetMetadataService>.Instance;
_cache = cache ?? new MemoryCache(new MemoryCacheOptions());
```

### 3. **業務邏輯層** - `QpayManager` 與 `DedicationInfo`

#### 3.1 QpayManager
**檔案**: `ChurchReport/Models/QpayManager.cs`

在 `SetQpayModel(Entity aContact)` 方法中新增動態取得奉獻類別清單的邏輯：

```csharp
#region ? 動態取得奉獻類別清單
// 從 Dynamics 365 OptionSet 動態取得奉獻類別清單
try
{
    var optionSetService = new ChurchReport.Services.OptionSetMetadataService(
        this.m_ToolUtilityClass.m_Crm2011OrganizationService,
        null, // Logger (可選)
        new Microsoft.Extensions.Caching.Memory.MemoryCache(
            new Microsoft.Extensions.Caching.Memory.MemoryCacheOptions())
    );

    // 取得 new_fee 實體的 new_category OptionSet 對應表
    var categoryMapping = optionSetService.GetOptionSetMapping("new_fee", "new_category");
    
    // 將 Dictionary 的 Key (顯示文字) 轉換為 List<string>
    m_QpayModel.DedicationCategoryList = categoryMapping.Keys.ToList();

    System.Diagnostics.Debug.WriteLine($"[SetQpayModel] 成功取得 {m_QpayModel.DedicationCategoryList.Count} 個奉獻類別");
}
catch (Exception ex)
{
    // 如果動態取得失敗，使用備用的硬編碼清單
    System.Diagnostics.Debug.WriteLine($"[SetQpayModel] 動態取得奉獻類別失敗，使用備用清單: {ex.Message}");
    m_QpayModel.DedicationCategoryList = new List<String> {
        "主日奉獻", "十一奉獻", "感恩奉獻", "建堂奉獻",
        "宣教奉獻", "愛心奉獻", "特別奉獻"
    };
}
#endregion
```

### 奉獻類別動態化（8 個頁面）
- ? 所有奉獻相關頁面的類別選單改為從 `new_fee.new_category` OptionSet 動態取得
- ? 支援 `QpayModel`、`DedicationInfoModel`、`DedicationModel` 三種 Model
- ? 統一使用 `OptionSetMetadataService` 服務

### 會員身分動態化（4 個方法）
- ? `PersonalController.GetMembershipStatusText()` - 個人資訊管理 (數值 -> 文字)
- ? `ChurchListDataProcessor.ConvertIndexToIdentity()` - 教會名單處理 (數值 -> 文字)
- ? `RegisterConnector.ConvertIdentityToIndex()` - 註冊處理 (文字 -> 數值，**反向查詢**)
- ? 所有方法改為從 `contact.customertypecode` OptionSet 動態取得

### 信仰狀態動態化（1 個方法）
- ? `PersonalController.GetSpiritualIdentityText()` - 個人資訊管理
- ? 從 `contact.new_spiriitual_identity` OptionSet 動態取得

### 奉獻類別值轉換動態化（1 個方法）
- ? `QPayProcessor.GetCategoryValueByDisplayText()` - 奉獻處理 (文字 -> 數值，**反向查詢**)
- ? 從 `new_fee.new_category` OptionSet 動態取得

## ?? 特殊功能：反向查詢 (文字 -> 數值)

### 支援反向查詢的方法
1. **`RegisterConnector.ConvertIdentityToIndex()`** - 註冊時將使用者輸入的身分文字轉換為 Dynamics 365 數值
   - 自動移除前綴數字 (例如: "01. 牧師師母" -> "牧師師母")
   - 查詢 `contact.customertypecode` OptionSet

2. **`QPayProcessor.GetCategoryValueByDisplayText()`** - 奉獻時將類別文字轉換為 Dynamics 365 數值
   - 查詢 `new_fee.new_category` OptionSet

### 反向查詢的優勢
- ? 不需硬編碼數值對應表
- ? CRM 管理員可在 Dynamics 365 中自由新增/修改選項
- ? 自動處理文字格式變化 (移除前綴編號)
- ? 備用硬編碼機制確保穩定性
