## 實作與行為差異
- 私有 Configuration 只註冊 JPEG／PNG／GIF；保留既有副檔名、Content-Type 與 5 MiB 檢查。WebP、TIFF、BMP 等偽裝 JPG 現在預期被拒絕，不新增 WebP 支援。
- 四條上傳路徑共用三個上傳方法；加三個縮圖，共六個解碼位置。先 Identify，再檢查單邊 ≤8192、總像素 ≤40,000,000，才完整 Load；第一影格輸出維持單張 JPEG。
- 保留 JPEG90、EXIF 轉正、MemberInfo 補白正方形、三個縮圖 crop／fit、JPEG82／85 與原回退；黃金測試比較解碼後尺寸、像素及大小範圍，不比較編碼 bytes。
- 上傳拒絕不再儲存原始檔。新人已建立後的附圖失敗保留建立成功狀態，只追加照片提示，避免重送造成重複新人；此處也不更改原有宣告不符、無檔等前置處理。
- 預期拒絕只回固定文字、不通知。真正故障傳原始 Exception 給既有共用入口，輸出不帶原始訊息；明確 caller 取消重新拋出。移除修改區域原本記錄姓名、ID、底層訊息的 debug 日誌。
- 輸入及輸出 stream、Image 由每次呼叫 using 擁有。非 seekable 輸入最多緩衝 5 MiB＋1 byte；失敗也 Dispose，借用來源不由 validator 處置。解碼器不跨請求保留像素池、不保存影像或使用者狀態；12 個混合併發及 175 次真實路徑操作後串流歸零、未釋放 ImageSharp 配置無增加。
- 新增顯示文字置 ImageInputText.resx，由 I18nCheck 產生不可變資料；本機 facade 只複製繁中固定欄位，不建立使用者快取。CJK 曾抓到 3691>3685，已修為 3682；未提高基準、未忽略或放寬守門。
