# P7.2 Slice C seed bootstrap 需求

## 問題與目標

Slice C 的 cleanup 正確刪除每輪 fresh fixture 的 source/list descriptor，卻使下一輪
`FreshPreflightProbe` 缺少輸入。此需求以持久、目前 Windows 使用者綁定的 seed descriptor
取代對上一輪 fresh descriptor 的依賴，解除控制面循環；不改變 Dynamics 週報、使用者或既有
非 task-owned 資料。

## 必要行為

1. seed 只保存已證明的五個 task-owned 靜態清單、baseline leader、UTC Sunday 與去識別化
   deployment metadata；不保存帳密、token、cookie、端點、原始 CRM 回應、例外、fresh entity ID
   或任何 Owner authority。
2. 既有 `.bak` 僅可作一次性唯讀候選。它必須通過 current-user、UTF-8 無 BOM、CRLF、大小、
   固定 legacy schema、GUID shape 與去識別化 metadata 檢查，並且忽略 `targetOwnerId`。
3. bootstrap 僅在 WhoAmI、精確 Retrieve 與有界 RetrieveMultiple 全部證明五個清單、task-marked
   leader、active non-Data8 owner、週報分支後，才可原子發佈 seed。任何失敗都是零 CE mutation。
4. Fresh preflight 只讀 seed；它不得建立 ledger、fresh descriptor、nonce、temporary mutation
   state 或執行 cleanup。
5. fresh provision 只在 preflight `go` 後開始；使用新 nonce 與 ledger，成功且完整 graph
   read-back 後才發佈 disposable active descriptor pair。
6. cleanup 只可刪除本輪 active pair、ledger 與 ledger 精確記錄的 fresh CRM entities；不得
   刪除或改寫 seed。
7. `zero-active` 仍是 go 且週報 lookup 缺席；`exactly-one-active` 必須精確關聯並 read-back；
   `duplicate-active` 或 `unavailable` 必須在 mutation 前 no-go。不得建立或修改週報。

## 驗收條件

- cleanup 後可在沒有 active descriptor pair 的情況下，以保留的 seed 啟動全新的 preflight。
- bootstrap、preflight、provision、publication、cleanup 的每個 no-go、timeout、ambiguous、
  read-back mismatch 或 cleanup uncertainty 都 fail closed 且不重試。
- 不掃描或挑選 CRM systemuser；不接受呼叫端 Owner；不觸及 CE 8.2、Official Worker、
  ChurchReport 流量或 feature flag。
- 完成 focused C# / PowerShell contract tests、Release build、serial tests、encoding、
  `git diff --check`、scope check 與相稱 isolation/lifecycle 驗證後，才能執行一次受控 CE cycle。
