# P7.1 Data8 唯讀真機 Evidence Handoff

## 目的與固定邊界

這個 handoff 只驗證 ChurchReport 目前選用的 `sunnyvalechback` CE 9.1
`Embedded + Data8` 路徑。它執行六個既有 Package01 read capability，不執行
write、action、function，不啟用 `Package01FeeReadsEnabled`，不啟動 Dedicated
Gateway、Official Worker 或 P6.2。

`DedicatedGateway + Data8` 與 Embedded 共用同一個 ProductClient／operation
contract；Dedicated Gateway listener 與 browser/live cutover 屬 P7.4 的 gate，
不在本 handoff 偷換成另一個 transport。

## 操作者前置條件

1. Lenovo Legion 使用者帳號的 Windows Credential Manager 已有固定的 **Windows 認證**：
   Generic Credential target `speechmessage.crm91.p62`。handoff 在確認 repository 與
   fixture 輸入後才讀取它，且只把密碼暫時交給 child test process；不要把密碼貼到 Chat、
   檔案或 command line。
2. 你已在隔離的 `sunnyvalechback` 開發 Organization 中確認三個 test-owned GUID：
   contact、dedication booking、disciple lesson。這次只讀取，不會建立或修改 CRM 資料。
3. 日期區間與 paid period 只針對測試資料，日期必須是 ISO 8601 UTC 形式。

缺少任何 fixture 時，不要猜 GUID，也不要重試 Credential Manager／P6 profile；只把該
gate 留在 `evidence-pending`。

## Lenovo PowerShell 5.1 指令

在 worktree 根目錄執行，將四個 `<...>` placeholder 換成你已核准的 test-owned 值：

### 找到 P7.1 測試資料的方法

請使用 `sunnyvalechback`，不要使用正式 Organization。這個步驟只是在找既有的
測試資料，不會新增、修改或刪除資料：

1. 開啟一位明確屬於測試用途的會員，從瀏覽器網址中的 `id=` 取得 **Contact GUID**。
2. 開啟屬於同一測試情境的奉獻預約資料，從網址中的 `id=` 取得
   **Dedication Booking GUID**，並記下其 `Paid Period` 欄位值。
3. 開啟同一測試會員可安全讀取的門徒課程資料，從網址中的 `id=` 取得
   **Disciple Lesson GUID**。

網址裡的 GUID 有 `{}`、`%7B` 或 `%7D` 時可以直接複製；PowerShell 會交給
handoff 的 strict GUID validation。日期範圍必須涵蓋奉獻資料，例如 Paid Period 是
`202601` 時可使用 `2026-01-01T00:00:00Z` 到 `2026-01-31T23:59:59Z`。

若找不到三筆彼此相關的測試資料，請停止在此；不要猜 GUID，也不要拿正式會員資料代替。

```powershell
$root = 'D:\音訊科技產品\系統平台\SpeechMessageProducts\.worktrees\1.0.0.3.Gateway&Embedded.Worktree'

powershell.exe -NoProfile -ExecutionPolicy Bypass -File `
  "$root\docs\scripts\Invoke-Package01Data8ReadEvidence.ps1" `
  -RepositoryPath $root `
  -ContactId '<TEST_CONTACT_GUID>' `
  -DedicationBookingId '<TEST_DEDICATION_BOOKING_GUID>' `
  -DiscipleLessonId '<TEST_DISCIPLE_LESSON_GUID>' `
  -StartDate '2026-01-01T00:00:00Z' `
  -EndDate '2026-01-31T23:59:59Z' `
  -PaidPeriod '202601' `
  -Json
```

script 會在結束時還原它自己建立的 `CRM_PASSWORD` 與 `P7_1_*` process environment
variables，並清除測試輸出的暫存檔。請只貼回最後一行 `schemaVersion=1` 的 JSON；不要貼 dotnet
完整 log、TRX、例外、帳號、密碼或 CRM 回應。

## 輸出判讀

- `outcome=go` 且六個 operation 都是 `status=succeeded`：可把 P7.1 CE 9.1
  Data8 read evidence 更新為 `go`。
- `outcome=no-go`：保留固定 `reason` 與各 operation 狀態；不得把它解讀成
  Official Worker 問題，也不得回頭重做 P6。
- `outcome=error` 或缺少 JSON：代表 handoff／本機輸入問題，不代表 CE operation
  成功；保留 P7.1 為 `evidence-pending`，等待唯一需要的修正資料。

此檔案與 script 都不改產品設定；`Package01FeeReadsEnabled` 在 base／Development
仍為 `false`。任何後續 consumer 開關、Dedicated Gateway listener preflight、
shadow comparison 與 rollback drill 必須留到 P7.4。
