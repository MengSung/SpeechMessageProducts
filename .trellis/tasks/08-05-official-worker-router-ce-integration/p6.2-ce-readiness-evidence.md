# P6.2 CE 唯讀驗證：本機就緒證據

日期：2026-08-05

## 結論

**No-Go（尚未執行 CE 呼叫）**。

P6.1 的離線 Router／Pool／Lease 生命週期驗證維持有效，但目前工作區沒有足以安全啟動 P6.2 受控真機唯讀驗證的部署材料。因此未啟動 Gateway、未啟動 Official Worker、未建立 generation，亦未對 CE 8.2 或 CE 9.1 發送任何請求。

## 已完成的安全就緒檢查

- Gateway 的 Official Worker 部署程式碼要求相鄰的 deployment-owned overlay 以提供受限欄位；其驗證會拒絕相對 executable path、全零或無效 SHA-256，以及 placeholder Organization ID，並 fail closed。
- 工作區遞迴搜尋結果：`dynamics-official-workers.gateway.json` 為 **0** 份。
- 已找到 CE 8.2 與 CE 9.1 Worker executable 的建置輸出，但 `worker-profile.xml` 為 **0** 份；因此沒有可確認、由服務身分存取的 worker-local credential reference／profile source。
- 已透過 repository 既有的 publish script 重新產出兩個固定版本 Worker 與 manifest；manifest 有效、兩個 executable 雜湊有效，且明確標記 feature gate 必須維持 disabled。產物仍不含 `worker-profile.xml` 或 Gateway overlay，未視為可部署完成。
- 本機目前使用者的 Credential Manager 項目未命中已知部署 reference；即使存在其他標記為 Dynamics／CRM 的項目，也不能證明目標 Gateway／Worker 服務身分可以存取它們。
- 已新增 `Test-DynamicsOfficialWorkerDeploymentReadiness.ps1`。此 probe 只檢查 manifest、profile-input、執行身分與 Credential Manager target presence，僅輸出去識別化 Go／No-Go evidence；不會讀取 credential blob、建立 overlay、啟動 Worker／Gateway 或連線 CE。
- 檢查當時沒有 `SpeechMessage.Dynamics.Gateway`、`SpeechMessage.Dynamics.Crm82Worker` 或 `SpeechMessage.Dynamics.Crm91Worker` 行程。
- 設定檢查只保留 presence／validity 類型的結果；沒有把 endpoint、connection string、credential、token、cookie、pipe name 或原始設定／回應寫入本文件或主控台證據。

## 為何不得繼續執行

P6.2 的前置條件是 CE 8.2、CE 9.1 各有一個啟用的 deployment-owned Official Worker profile，且 Worker 可由 host-side worker-local profile 取得其 credential reference。缺少 overlay 與 `worker-profile.xml` 時，嘗試啟動只會落入預期的 fail-closed 路徑；自行補值、略過 executable hash 或建立秘密設定均超出本 task 與本次授權。

因此下列 P6.2 operation 均**沒有執行**：

- Data8 CE 9.1 control：`runtime.health.whoami`
- Official Worker CE 8.2／9.1：`runtime.health.whoami`
- Official Worker CE 8.2／9.1：`runtime.pool.validate.connection`

沒有啟動 generation，所以不需要 drain；也沒有任何需保留的 CE 或 IPC 失敗證據。

## 重新取得 Go 的必要條件

由部署 owner 在目標驗證主機完成下列事項後，才能重新請求 P6.2：

1. 在 Gateway executable 同目錄提供符合 allowlist 的 `dynamics-official-workers.gateway.json`，其中每個目標 profile 都具有有效、非 placeholder 的 worker kind、絕對 executable path、SHA-256、package lock、base URI 與 expected Organization ID。
2. 安裝與各 profile 相符的固定版本 Worker executable，並讓其檔案雜湊與 overlay 相符。
3. 在每個 Worker executable 同目錄提供有效的 `worker-profile.xml`；其 credential reference 必須由目標服務身分存取。不得把 credential 本身交給本 task 或寫入 repository／artifact。
4. 確認 CE 8.2 與 CE 9.1 profile 都獲准啟用，且 CE 9.1 Data8 control profile 的 secret provider 可用。
5. 取得一次新的明確授權後，僅執行上述 allowlisted read-only matrix、輸出去識別化結果，並在結束時驗證 Worker drain／process cleanup。
