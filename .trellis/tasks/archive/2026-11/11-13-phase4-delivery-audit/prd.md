# 階段 4 完整交付自我稽核

## Goal

依目前工作樹的權威文件與可追溯證據，深入核對階段 4（P4-00、P4-01～P4-06、階段審查）是否依核定範圍完成，並向使用者交付明確列出未完成事項、證據缺口及後續阻擋條件的一頁稽核報告。

## Requirements

- 稽核目前分支、HEAD、工作樹狀態及遠端 SHA；不修改既有提交或執行推送。
- 依優先順序核對 `AGENTS.md`、`04A_階段4_執行細則.md`、`00_總覽與執行規則.md`、階段 4 計畫、各包 Trellis 任務、回報、驗收文件及進度頁 DATA。
- 對 P4-00、P4-01～P4-06 與階段審查逐項核對完成條件、同名測試、提交、守門、推送核對、產物、證據及例外核定。
- 將每一項判定為「已驗證完成」、「核定條件式完成」、「未完成」或「證據不足」；不得把離線或合成測試寫成供應商實機通過。
- 特別核對 P4-06 沙箱 Order HTTP 400、合成回寫與冪等實機結果、殘留清理、P4-PROP-008 及使用者待辦。
- 本任務只讀；不得修改產品程式、User Secrets、D365、進度頁、已封存 P4 回報或遠端狀態，不重跑 `PaymentsLive`。
- 只可為本稽核建立任務文件及最終稽核報告；若發現既有紀錄與證據不一致，先如實列為稽核發現，不自行修訂原階段紀錄。

## Acceptance Criteria

- [ ] 清單覆蓋 P4-00、P4-01～P4-06、階段審查及全階段收尾。
- [ ] 每項狀態均有可定位的主要證據，並明示證據不足或來源衝突。
- [ ] 對 P4-06 明確說明「已驗收（沙箱連線未驗證）」是條件式結案，不代表永豐撥款查詢通過。
- [ ] 列出尚待使用者或永豐處理的事項，包含 P4-PROP-008 對階段 7 首次正式組織切換的阻擋關係。
- [ ] 結論可由 repo 文件、Git 提交／遠端、現存測試結果及本機 evidence 重現；不以先前助理的敘述代替證據。
- [ ] 最終提供繁體中文稽核報告，按重大性排列未完成、條件式項目及證據缺口。
