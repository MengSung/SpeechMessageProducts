# 審查設計

## 範圍與信任邊界

本任務是唯讀交付審查，不是階段 4 的續作。證據來源分為：計畫與正式驗收契約、Git 提交及工作樹、產品程式與測試、原始測試／guard 證據、工作包及總回報、進度頁資料，以及指定 Codex 對話。對話中的摘要和推理是待驗證主張，不視為測試證據；未保存或無法重現的 TRX 不以回報文字代替。

任何只存在於 User Secrets、環境變數、正式原始碼舊常數或工具輸出的秘密都不得複製到審查任務或報告。僅檢視既存紀錄；不接觸正式組織／商店／Channel，不付款、不呼叫 Sandbox，不改 repository 原始階段資料。

## 核對方法

1. 以 AGENTS.md、3.5 的 00 與 04A 的優先序確認範圍、工作包順序、驗收條件和禁止事項。
2. 讀取指定對話，按時間線標記授權、失敗、修正、重試、結案與推送等轉折。
3. 由 Git 確認起點、提交內容、最終 HEAD、遠端 SHA 和乾淨狀態；以提交差異鎖定實際產品修改，不以任務摘要猜測。
4. 對照程式契約與測試，將測試涵蓋、真實環境行為及資料清理分別判定。
5. 逐項查回報所引用的 TRX、log、雜湊及審查輸出是否存在、內容是否吻合、能否重算；有證據保存缺口即明示其限制。
6. 對照進度 DATA、工作包回報及階段總結的狀態與時間；追查已變更狀態是否有後續授權和新證據。
7. 以風險排序形成 findings，將 Critical／High／Medium／Low 或資訊分級連結到具體檔案、提交、測試或原始證據。

## 判定語意

- **已驗證**：可由本機保存且內容吻合的原始證據或可重現測試支持。
- **僅有回報**：只有報告／對話摘要，沒有可查的底層證據。
- **未驗證**：必要測試未執行、失敗、未保留結果或真實外部情境未覆蓋。
- **不一致**：計畫、程式、工作包、進度或最終回報互相矛盾。
- **不適用**：契約明確不要求，並說明理由。

不得把條件式驗收等同完全通過，不得用較晚成功覆寫早期失敗證據，也不得用自審替代規定的外部審查。
