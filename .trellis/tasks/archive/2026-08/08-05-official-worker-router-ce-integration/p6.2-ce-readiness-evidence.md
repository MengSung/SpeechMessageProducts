## 結論

**Official Worker live compatibility：No-Go（離線部署材料已就緒，但 Worker 尚未通過 runtime READY gate）**。

G0 與 P6.2 的本機 profile／artifact／identity chain 已通過；兩個版本的離線
`runtime.health.whoami` 與 `runtime.pool.validate.connection` harness 也已通過
`ValidateOnly`。嘗試啟動 published Gateway／Official Worker composition 時，Worker
在建立 client 後未發布 nonce-bound READY frame，Gateway 因 fail-closed startup gate
結束；因此尚未執行任何 CE operation。

## 已通過的安全與離線證據

- Windows identity 與兩個 Credential Manager target 的 readiness probe 回報
  `go`：`crm82`／`OfficialCrm82Worker` 與 `crm91`／`OfficialCrm91Worker` 均為
  `credentialTargetState: present`。
- `New-DynamicsOfficialWorkerDeployment.ps1` 回報 `outcome: provisioned`，overlay
  與兩份 `worker-profile.xml` 均由部署工具產生，且 `featureGateMustRemainDisabled` 為
  `true`。
- 兩個 alias 的離線 identity chain 均回報 `outcome: validated`、
  `operationId: runtime.health.whoami` 及 `requestExecuted: false`。
- 兩個 alias 的離線 connection-evidence chain 均回報 `outcome: validated`、
  `operationId: runtime.pool.validate.connection` 及 `requestExecuted: false`。
- deployment/readiness、compatibility 與 P6 evidence PowerShell tests、P6 focused／
  full Dynamics tests、ChurchReport MemberInfo tests，以及 Release solution build 均通過。

## 受控啟動嘗試

- 只使用 published Gateway、兩個已核准 profile、目前 Windows identity 與兩個
  allowlisted read-only operation；ChurchReport feature flag 與流量未變更。
- 已在寫入兩個核准 canonical HTTPS root URI 後重跑 startup bridge；結果仍為
  `outcome: no-go`、`reason: gateway-startup-failed-before-ready`、
  `listenerObserved: false`、`ceContacted: false`、`operationExecuted: false`，且 bridge
  已確認 `listenerReleased: true`。因此 canonical URI 已不再是目前阻塞項。
- 隔離的 named-pipe READY handshake 顯示兩個 Worker 都能連上 pipe，但都在 READY 前以
  `workerExitCode: 10` 結束；此 exit code 對應 `ClientNotReady`。這證實 Gateway 已可
  啟動 Worker process，阻塞點位於 Worker client 的外部登入／驗證就緒，而不是 manifest、
  pipe 或本機 listener 建立。
- Gateway 在本機啟動期等待 Worker READY frame；實際結果是
  `worker-ready-frame-missing`（Worker 在 READY 前結束）。Gateway 沒有建立有效
  listener，啟動程序已結束，未留下 Gateway／Official Worker process 或 listener。
- `ceContacted: false`、`requestExecuted: false`；本次沒有 WhoAmI、connection
  validation、fee read、write、Action、Function 或任意 CRM request。

## 判定與邊界

這不是 canonical URI、manifest hash、profile input shape、named-pipe 連線或本機 listener
的 No-Go；目前尚不能由這個 sanitized 結果區分「Credential Manager blob／帳密不可用」、
「帳號未獲 CE Organization 授權」、「IFD home realm／Organization mapping 不正確」、
「CE/ADFS network authentication 失敗」或 Worker client startup 的其他 runtime failure。
不得猜測或把任一候選原因寫入設定，也不得把 `readiness: go` 當成真機相容性證據。

在 2026-08-06 checkpoint 當下，P6 維持 `in_progress`，P7.0、P7.1～P7.5 與 P8 均未啟動，
且沒有 ChurchReport cutover。此歷史狀態已由 2026-08-07 範圍重校取代；P7 仍須等待 P6 正式
archive，但不再等待本文件的 Official Worker READY。
