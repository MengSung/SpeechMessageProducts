# P7.2 Slice C seed bootstrap 實作計畫

1. 先以 PowerShell contract tests 建立 RED：沒有 active pair 但存在有效 seed 時，fresh
   preflight 可進入唯讀 child；seed 缺失/非法/跨使用者、legacy owner 欄位、partial publish
   與 cleanup fault 必須 fail closed 且 seed byte-identical。
2. 新增嚴格 seed schema/path/atomic-publication helpers，並將 fresh lanes 的靜態輸入改為 seed。
   保留 active pair 的 strict schema 作 execute/reconcile/repair 與 cleanup graph proof。
3. 以 C# focused tests 驗證 seed-derived request shape 保留 exact lists、baseline leader、
   weekly-report zero/one/duplicate semantics、Data8 WhoAmI owner separation、零 mutation probe
   與 deterministic service disposal。
4. 實作 one-time read-only bootstrap，並使 provision 成功後才由 ledger 發佈 active pair；
   cleanup 永遠保留 seed。
5. 執行 focused tests、PowerShell suites、P7.2 validator、Release build、serial solution tests、
   encoding/line ending、diff/scope/isolation/lifecycle checks 與受限雙模型 review。
6. 僅在本機 gates 全數通過後，依序一次 bootstrap、preflight、provision、Slice C、read-back、
   cleanup。任何 no-go 立即停止該寫入家族；Slice D-H 只在 Slice C 證據完整後開始。
