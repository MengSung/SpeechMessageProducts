# P7.2 Slice C seed bootstrap 設計

## 控制面邊界

```text
legacy .bak（唯讀候選）
  -> bootstrap read-only proof
  -> permanent current-user seed
  -> fresh preflight（唯讀）
  -> fresh provision（nonce + ledger）
  -> disposable active descriptor pair
  -> Slice C / read-back
  -> cleanup（刪 active pair、ledger、fresh entities；保留 seed）
```

seed 是靜態前置條件的 authority；active pair 僅是已發佈 fresh graph 的可清理輸出。兩者
不可共用檔名、schema 或刪除函式。PowerShell parent 依 current Windows identity 與固定
local-app-data root 驗證 path，child 永遠不接收 seed 檔案路徑、legacy `targetOwnerId` 或
呼叫端 owner。

## Seed schema 與 migration

seed 使用嚴格、版本化、固定屬性名稱的 JSON schema。只接受 current Windows identity、
`crm91`、Data8、CE 9.1、五個 distinct GUID list IDs、non-empty baseline leader GUID 與
canonical UTC Sunday。`targetOwnerId` 是 legacy candidate 中明確拒絕/忽略的欄位，絕不寫入
seed 或 child environment。

bootstrap 先在 local boundary 驗證 candidate；接著建立短生命週期、read-only child，使用
固定 Data8 identity 做 WhoAmI、精確 list/leader/owner Retrieve 及 TopCount=2 的週報查詢。
只有完整 `go` 的去識別化 evidence 才以 temporary-file + atomic replace 發佈 seed；任何
publication 失敗會刪除 temporary file 並保留原 seed，不會回復 `.bak`。

## Lane 規則

- 普通 execute/reconcile/repair：仍要求 disposable active pair。
- fresh preflight/provision：要求 seed；preflight 不讀 ledger 或 active pair，provision 先
  檢查沒有 pending ledger，才建立 nonce。
- cleanup：要求 seed、active pair 與 strict ledger；只把 ledger exact IDs 傳入 cleanup child。
  即使 seed 不存在也不允許以 cleanup 為名刪除其他資料。

所有 environment variable 都由 parent 以 allowlist 設定並在 `finally` 還原；Credential
Manager、child process、temporary directory、streams 與 Data8 lease 都具有單一 owner、
有界生命週期與 deterministic cleanup。證據只輸出固定去識別化分類。
