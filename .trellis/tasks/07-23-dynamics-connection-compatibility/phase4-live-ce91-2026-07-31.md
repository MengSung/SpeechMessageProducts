# CE 9.1 live smoke evidence — 2026-07-31

## 結論

CE 9.1 的真機驗證尚未通過，但阻塞已從模糊的「缺少可用 Kerberos/WinRM
工作階段」縮小為 D365APP01 CRM Web 應用程式內部的 URI 處理例外。此文件
只記錄不含密碼、權杖、Cookie、完整 HTTP header 或 ticket 的診斷事實。

這不是 Gateway connector 已失敗的證據，也不是可以透過放寬驗證、改 DNS、
修改 hosts、使用 Basic/明文 WinRM 或建立密碼型登入來繞過的 gate。

## 對 Gateway 的影響

1. 真機 CE 9.1 的 `WhoAmI`、metadata、operation、paging 證據仍為 **blocked**。
2. 這個 500 必須由 CRM 管理端依完整 ASP.NET 事件 stack trace 及受支援的
   Dynamics Deployment Manager／Claims-IFD 設定流程處理；不要猜測或直接修改
   DC、DNS、ADFS、IIS 或 CRM 資料庫。
3. Gateway 的本機安全與契約工作可繼續，不可因這個外部 gate 空轉。
4. CRM 修正後，必須以明確目標重新執行 connector-owned smoke；不要把匿名
   `HEAD` 或瀏覽器既有 Cookie 視為 Gateway 的驗證證據。

## 本次 repository 修正

`docs/scripts/Invoke-DynamicsLiveSmoke.ps1` 不再內建 `jesus` 或任何 CRM host。
啟用 `-EnableLive` 必須明確提供 `-WebApiRoot`，缺少時會在任何外部請求前
fail-closed。工具亦移除了與 connector 驗證語意不同的獨立 HTTPS `HEAD`；
真正的 `WhoAmI` 是唯一的 connector-authentication 判斷來源。

## CRM 修正後的最小重測

在核准的 D365APP01 網域工作階段、且 CRM 管理端已確認上述 500 修正後：

```powershell
.\docs\scripts\Invoke-DynamicsLiveSmoke.ps1 `
  -EnableLive `
  -WebApiRoot 'https://sunnyvalechback.speechmessage.com.tw/api/data/v9.1/' `
  -CeVersion '9.1' `
  -CredentialSource HostIdentity `
  -NoRestore
```

只有這個指令回傳 `WhoAmI` 成功，才可把 CE 9.1 HostIdentity transport 標記為
已驗證。若 CRM 之後轉為 ADFS/IFD redirect，則 HostIdentity 不適用；需另行依
既有規格評估核准的非密碼 service-workload 流程，不能退回 ROPC 或明文密碼。
