# P8-01a 技術設計

## 邊界

本單元分為結構定義、Deployment 轉換工具、GoodShepherd.Core 領域型別與離線測試四個邊界。Deployment 擁有組織中繼資料解讀、計畫完整性、命令路由、寫入批次及操作紀錄；Core 只提供純值類別、清單發布驗證、讀取委派與文字回退，不引用 Deployment，也不持有跨命令狀態。

## 資料流程

Plan 由單次命令取得的唯讀中繼資料與完整、有界的分頁資料投影形成候選結果：兩來源 choice 先各自驗證，再按選項數值做聯集；同一數值若兩欄的 1028 標籤不同即 fail closed，不允許任一來源覆寫。不同數值即使名稱相同仍是不同身份。每間教會依聯集中的選項值產生 `legacy-<value>` 類別；教會已使用選項與現有畫面選項的聯集均保留，依選項值識別，不因名稱相同而合併。畫面文字必須以中繼資料標籤精確對應；沒有唯一對應的文字列為未對應，不得任選選項值。計畫包含 `SchemaMetadata.Read` 核對後的 server organization ID／uniqueName、類別候選、每個教會及選項值的穩定來源筆數與摘要、目前可回填筆數、無法判定教會計數、未對應標籤，以及兩個來源欄位分開保存的 RequiredLevel 已知值或明確未知狀態。

來源摘要以伺服器主鍵、選項值與解析教會 ID 的穩定排序序列計算；不輸出主鍵清單，不把可變查閱欄納入摘要，因此本次已回填資料仍屬相同來源快照。頁面必須完整讀完，重複 ID、錯誤／重複 paging cookie、空續頁、超出明確上限或取消均使整份 plan 失敗，不發布部分計畫。plan 的 aggregate source counts 在 apply 期間保持不變；「目前可回填筆數」只用來顯示進度，不作來源漂移基準。

Apply 先取得既有組織寫鎖與唯一 lease，再於鎖內重讀 server identity、中繼資料及來源摘要，驗證完整 plan 檔 SHA-256 後才允許第一筆寫入。任何身份或來源漂移均拒絕；相同命令在本機並行時由鎖序列化，鎖內重驗。先以教會＋固定代碼完整替代索引鍵 Upsert 類別，再對收費單與預約逐批最多 100 筆執行 `ExecuteMultiple`。以每筆 response 核對成功／失敗數，回應筆數不符或任一 fault 即停止後續批次；不盲目重送不確定的寫入批次。下一次重試重新讀取，已填 lookup 跳過，其餘記錄依同一穩定來源摘要續跑。無法判定教會者不回填並計數。每批紀錄只存批次序號、實體、請求／成功／失敗筆數與安全錯誤碼，不含教會名稱、付款人或記錄 ID、例外本文或秘密；每批後 flush，紀錄寫入失敗即停止，不宣稱已完整套用。

教會解析由 plan/apply/verify 共用：實體中繼資料若提供正式教會 lookup，只有該欄是 account lookup 且有值時採用該 account ID；沒有該 lookup 欄時才使用付款人 lookup，並要求其 `parentcustomerid` 的實體種類為 account。缺付款人、找不到付款人或多型 lookup 指向非 account 均計為無法判定，不回填。若同時存在直接教會 lookup 與付款人，直接欄為 D8-8 所列較高優先來源；此決定不代表兩者一致性已在實機查證。

Verify 重新唯讀投影並按教會回報有舊選項但缺新查閱值的數量、無法判定教會的數量及查閱指向其他教會類別的數量；對可判定教會的未回填或跨教會指向不宣稱通過。

## 生命週期與隔離

命令沿 Deployment 現有 connector 取得一個命令專屬 lease；資料候選、雜湊與批次記錄不得跨命令保留。唯一寫入命令持有既有組織寫鎖，先排空同步 SDK 呼叫，再 Dispose lease 並釋放鎖。取消及 SDK 失敗時停止新批次，保留已 flush 的批次摘要；不自動 retry SDK 寫入。重試依唯一替代索引鍵與「已填即跳過」續跑，不以記憶體鎖取代 Dataverse 唯一性。本實作及測試不連任何組織，實機中繼資料與資料筆數缺口另列上線前查證事項。

Core 的讀取器採同步、借用 SDK 服務、不 Dispose、不快取；讀取限制單教會且最多 200 筆。候選清單完全建立並驗證後才交付唯讀快照；重複／空 ID 或超量拒絕整個集合。同名不同 ID 均保留。SDK adapter 的合成測試另注入兩選項集合不相同，以及共享值標籤衝突，分別驗證可合併與必須拒絕的分支。

## 失敗處理與相容性

未知中繼資料、錯誤型別／組織、plan 雜湊不符、來源漂移、重複主鍵、分頁不完整、批次失敗或跨教會 lookup 均不得靜默略過或發布部分結果。中斷後僅依已完成批次紀錄與冪等替代索引鍵續跑。命令參數只增加固定白名單語法，不改既有命令的解析、連線或退出碼契約。所有實機動作皆不在本單元執行。

## 驗證

Deployment 使用指定的 12 個測試，以合成 Metadata／OrganizationService 注入標籤衝突、名稱相似、無教會記錄、雜湊與組織漂移、每 100 筆批次、中斷與錯誤 lookup。Core 使用指定的 4 個測試及兩個目標建置，驗證同名保留、重複 ID fail closed、穩定排序及 200 筆硬上限。最後執行兩個 Release 測試目標、文件及位元組檢查，再按 08A 守門程序執行完整驗收。
