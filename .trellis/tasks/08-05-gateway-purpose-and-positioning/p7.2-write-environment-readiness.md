# P7.2 寫入環境級可行性與 capability fixture 交接

> 狀態：P7 Parent planning artifact。本文不啟動 P7.2、不建立 D365 資料、不執行 write／Action／Function，也不取代 P7.0 的 support matrix。

## 目的

保存 P7.2 之後可以重複使用的環境事實，避免把 P6 的 connector/lifecycle gate 與 ChurchReport 的業務寫入 gate 混為一談。這份文件只證明「有一個隔離的 CE 9.1 開發環境可作為候選 test-owned fixture host」；每個 operation family 仍須在 P7.0 matrix 完成後另行核准。

## 已核准的環境級事實

- `sunnyvalechback` 是 CE 9.1 IFD 公司研發 Organization，與正式系統分離。
- 使用者於 2026-08-08 明確確認 `sunnyvalechback`（CE 9.1）與 `jesus`（CE 8.2）的所有會員、收費、課程、出席及其他資料均為虛構研發資料，授權 P7 在 coverage matrix 與各切片 cleanup／reconciliation 邊界內任意新增、修改或刪除；此授權不適用於正式環境、P8 或 Central Gateway。CE 8.2 operation 仍只有在 matrix 明確標為 `required` 時才可執行。
- 這項明確授權解除兩個研發 Organization 的資料歸屬疑義，但不取代各 operation family 的 bounded contract、matrix activation、cleanup、reconciliation 與 evidence gate。
- P6 只使用此環境取得 allowlisted read-only identity／connection evidence；業務寫入保留給 P7.2。

## P7.2 每個 operation family 的必要欄位

在啟動任何 live write／Action／Function slice 前，P7.0 matrix 必須產生下列欄位；缺一項即該 slice `no-go`：

| 欄位 | 要求 |
|---|---|
| `operationId` | 已註冊、強型別、非 generic CRUD／任意 FetchXML 的 capability ID |
| `ceVersion`／`profileAlias` | 由 deployment-owned profile 決定，不由 request 選擇 |
| `fixtureOwner` | 唯一負責建立、驗證、清理與 reconciliation 的 owner |
| `allowedMutations` | 明確列出可建立／更新／關聯／執行的最小動作；禁止未列出的副作用 |
| `precondition` | 可重複驗證且不含秘密或完整個資的測試前置 |
| `idempotency` | duplicate delivery 與 retry 行為；寫入結果不明時不得盲目重試 |
| `cleanup` | bounded、可重複、按 operation 定義的刪除／還原步驟 |
| `reconciliation` | timeout-after-commit 或部分完成時，如何查證實際狀態並決定後續動作 |
| `evidence` | 去識別化結果、時間窗、correlation category、資源基線與清理結果 |

## CE version 判定

- CE 9.1 的 `sunnyvalechback` 與 CE 8.2 的 `jesus` 都可作為對應版本的 authorized synthetic fixture host，但每個 family 仍要有自己的 fixture contract。
- CE 8.2 write／Action／Function 只有在 P7.0 support matrix 標為 `required` 時才需要安全 fixture；若標為 `unsupported`，必須在 dispatch 前 fail closed 並保留理由。
- 不得以 CE 9.1 的 test member 證據外推 CE 8.2，也不得以 mock、unit test 或 registry declaration 冒充 live evidence。

## Activation gate

P7.2 child 只有在下列條件全部成立時才可 `task.py start` 或發出第一個 live write：

1. P6 已封存，P7.0 matrix／validator 已封存並列出該 operation family。
2. `operationId`、profile、CE support 狀態與 ProductClient／executor owner 一致。
3. `fixtureOwner`、allowed mutations、cleanup、reconciliation 與 ambiguous-timeout policy 已被寫入 child task。
4. operator 已在目標 Windows identity 下提供必要的 sanitized preflight；credential value、token、cookie、connection string 與完整個資不得貼回。
5. 第一次 live operation 的結果、清理與資源 baseline 可被獨立驗證；失敗時只停用該 slice，不切換 connector/profile/CE version。

若缺少任一項，代理必須在本 child task 寫入 `operator-handoff-*.md`，產生 bounded PowerShell，並保留 checkpoint；沒有明確資料庫授權時不得猜測 fixture，已有授權時也不得把它當成跳過 operation-specific gate 的無條件 Go。

## 禁止事項

- 不在 P6 執行業務 write／Action／Function。
- `sunnyvalechback` 的全資料庫授權只解除人工 fixture ownership 阻塞；每個 operation family 仍必須定義自己的 fixture graph、允許 mutation、cleanup、reconciliation 與去識別化 evidence，不得建立跨 family 的萬用產品 API。
- 不執行 generic entity／QueryBase／任意 FetchXML／caller-selected organization。
- 不對有歧義的 timeout 直接重送寫入；先走 reconciliation。
- 不把原始 Entity、OrganizationRequest、endpoint、OrganizationId、credential、token、cookie 或完整 payload 寫入 evidence。
