# 方案整合與國際化 P2 全部必要驗收

## Goal

依實作計畫 3.3 的「03_階段2-4_共用送訊_Webhook_金流.md」，完成階段 2
共用送訊與對外待辦的全部必要工作包、離線驗證、必要的使用者／D365
驗收步驟與交付紀錄；若外部環境或秘密尚未具備，必須完成所有不依賴項目並
明確記錄受阻，不得用 mock 或文件代替實機結果。

## Requirements

- 完成並逐包追蹤 `P2-01`～`P2-12`；每個工作包均須有實作位置、測試／驗收方式、實際結果與證據位置。
- 遵守 `AGENTS.md`、實作計畫 3.3、`.trellis/spec/backend` 與 `.trellis/spec/guides`：
  跨使用者／教會／租戶隔離、穩定資料身分、不重複發布、資源確定性清理、例外通知保密及繁中檔案說明均為 release blocker。
- P2-04 推播實作前，先完成「P2-04 前置驗收」的測試 Channel／本人測試帳號與
  `TestChannelToken`／`TestLineUserId` 條件；不得用正式 Channel、離線 mock 或 P0 trace 結果冒充沙箱實收。
- 所有 D365 寫入、LINE 實際推播及需要外部帳密的操作，只能在安全條件與使用者已授權的測試組織範圍內執行；秘密不得寫入 repo、命令列、進度頁或報告。
- 以單一主會話 inline 模式實作與檢查；本輪依使用者目標文件取消外部 Gemini／Claude 流程，但不降低本機測試、隔離、生命週期與實機驗收門檻。
- 每個獨立完成的工作包更新 `文件/規劃設計書/實作計畫-3.3/實作進度.html`，使用 Asia/Taipei 時間並保留歷史證據。

## Acceptance Criteria

- [ ] P2-01～P2-12 均已完成或以明確「受阻」狀態記錄；未完成項目不得標示已驗收。
- [ ] `SpeechMessage.Hosting`、`GoodShepherd.Core`、雙目標送訊核心、Token 加密、待辦 worker、Webhook 主機與金流整合均符合既定相依方向。
- [ ] 新增／修改的產品程式與測試具有完整繁中檔案說明及 XML／Razor 註解，UTF-8 無 BOM、CRLF、檔尾 CRLF。
- [ ] 方案建置、相關測試、檔案說明檢查、編碼檢查、重複程式掃描、I18nCheck、架構與生命週期測試均有實際結果。
- [ ] A／B 教會或租戶並行測試不串資料，快取／佇列／背景工作／連線／串流／取消註冊在停止後回到基線。
- [ ] P2-04 與 P2-12 的必要實機條件若未具備，進度頁、回報與最終交付均清楚列出阻塞、已嘗試方法與續作條件。
- [ ] 變更只包含本 P2 範圍及必要的任務／進度／規範紀錄；不推送、不合併遠端、不進正式環境。
