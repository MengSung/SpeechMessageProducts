# Sol 6.2 推理強度與圖片能力排查

## 目標
解釋為何在此電腦選 6.2 Sol 會顯示「中」並隱藏整個推理強度控制項，而 6.1 Sol 仍有滑桿；釐清不能附圖的能力宣告，提出最小、可回復的修正方案。

## 已確認事實
- 使用者同意建立排查任務；尚未核准修改設定、修補第三方安裝包或重啟應用程式。
- 使用者截圖顯示 6.1 Sol 有推理滑桿；使用者描述 6.2 Sol 選取後控制項消失、標籤顯示「中」。截圖不代表已確認實際 API reasoning effort。
- 本機 Codex 設定指定 CodexManager 產生的 gateway-models.json；6.2 Sol / Astra 宣告 input_modalities=[text]，6.1 Sol 宣告 [text,image]。
- 該目錄的 6.2 Sol 已列 low/medium/high/xhigh/max/ultra，但與 6.1 相比缺少 supports_reasoning_summaries，且 supports_reasoning_summary_parameter=false；這些差異尚不能直接認定為滑桿消失的根因。
- 不把本機模型別名或可選清單視為上游實際支援能力，先前無官方證據的斷言不採用。

## 需求
- 唯讀追蹤模型來源、能力轉換、介面顯示條件與本機快取，分開處理圖片與推理問題。
- 對照 6.1 / 6.2，保留去識別化、無機密的證據；不得收集金鑰、Cookie、對話、私有請求內容。
- 提案必須區分已證實原因與尚未驗證假設，不僅修改畫面標籤或強行宣告上游支援。
- 若需改第三方設定或安裝包，先說明擁有者、影響範圍、備份／回復與驗證，再由使用者確認。
