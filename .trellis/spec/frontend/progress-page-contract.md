# 實作進度頁狀態契約

`文件/規劃設計書/實作計畫-3.3/實作進度.html` 是靜態驗收快照，不自動取得背景進度。
更新時須保留一般資訊歷史，只能以實際驗證證據推進工作包。

- 工作包 `status` 只可為 `done`、`active`、`todo`、`you`。`review` 僅屬審查里程碑，不列入包數。
- 進行中使用 `active`，不可用 `doing`；LABEL/ICON 與摘要依同一狀態辨識。
- 修改狀態後，同步階段 `done/active`、階段卡片及全計畫 meter；不能只改單列或百分比。
- 完成數由驗收決定；顯示修好不代表後端或實機驗收完成。
- 同一階段的一般資訊集中在一張預設收合的摘要，後續原地更新日期、修改理由、實測結果、證據路徑、審查與提交狀態；不可每次工作另增卡片。當前阻擋在 notices，解決後保留歷史並移除當前告警。
- 所有文字經 esc；歷史可以說明 undefined 根因，但圖示及狀態標籤不可含缺值。
- 每次更新跑 `node tools/RepoQuality/Tests/Test-ProgressPage.cjs`：83包合法狀態、實際渲染、摘要計數、同名不合併、HTML跳脫與實機授權邊界均須通過。
- UTF-8 無 BOM、CRLF 與末尾 CRLF 必須按位元組檢查；原始驗證輸出不覆寫。

## 同階段資訊摘要（2026-11-07 使用者核定）

- `DATA.notices` 的階段摘要使用穩定 `id: "phase-N-summary"`、`phaseId: "階段 N"`、
  `level: "info"`；例如 P2 的標題為「P2 進度摘要」，不可按 P2-01、依賴盤點或每次提交另增一般資訊卡。
- `body` 是精簡現況；細節與歷史證據放入同卡 `steps`，以「歷史紀錄」區分過時測試數。
  `lastUpdated` 使用 Asia/Taipei 的 ISO 8601 `+08:00`，本文日期標明時區。
- 合併時保留原證據、授權界線、其他階段歷史及工作包；不以顯示整理改動驗收狀態。
  `warn`／`error` 維持獨立可見的問題摘要，不可吞入中性收合卡。
- 正確：更新既有 `phase-2-summary` 的現況與驗證證據。錯誤：每完成一個 P2 子項目，
  再新增另一張 P2 info，或為縮短頁面刪除舊驗收證據。
- `Test-ProgressPage.cjs` 保護單階段單卡、收合與證據保留；以合成分支、目前階段切換與
  `done/active/todo/you` 混合狀態驗證 renderer。真實進度計數必須一致，但不可把 P1
  分支、P1 為目前階段或未來階段永久全 todo 當成固定測試預期。

## 一般資訊逐筆日期時間（2026-11-07 使用者永久要求）

- 適用 P2 既有資訊與往後各階段新增／更新的一般資訊。`body` 與 `steps` 的每筆字串
  都以 `YYYY-MM-DD HH:mm Asia/Taipei (UTC+08:00)` 開頭，讓使用者展開後能逐筆辨認時間。
  `lastUpdated` 為同時區 ISO 8601 `+08:00`；隱藏欄位不能代替可見日期時間。
- 原有確切事件時間保留；原時間未記錄或不能確認時，使用
  `補記 YYYY-MM-DD HH:mm Asia/Taipei (UTC+08:00)（原事件時間未記錄）｜原文`。
  此為補記時間，不能稱為事件時間，不猜測或回填虛構時間。
- 同階段單卡、預設收合、舊證據、其他階段紀錄及狀態維持原有契約。
  正確：每筆顯示時間且保留原驗收證據。錯誤：只替 body 或 lastUpdated 加時間，
  詳細清單仍沒有時間，或把所有歷史事件改成今天發生。
- `Test-ProgressPage.cjs` 直接檢查真實 P2 body、每筆 steps、ISO 時區與實際 renderer
  輸出；缺日期、缺分鐘、缺時區或有日期卻沒有實際顯示，均必須失敗。
